## 0. 전제 — 무엇을 하지 않는가 (명확한 경계선)

대표님이 앞서 요청한 "로맨스 스캠 대화 유도" 방식은 진행하지 않는다. 이유를 다시 한번 명확히 한다: 실제 로맨스 스캠은 외로움·정서적 취약성을 이용해 가짜 친밀감을 만들고, 그 신뢰를 결제·송금으로 바꾼다. 게임 안이라는 이유로 이 메커니즘 자체를 약하게든 강하게든 이식하면, 결제하는 돈은 실제 현금이고 그 심리를 이용당하는 것도 실제 사람이다. **이 설계안은 그 기법을 전혀 쓰지 않는다.**

대신 이번 설계는 스텔라 아리스가 이미 갖고 있는 **"안내원" 역할**(§1 확인)을 그대로 유지한 채, 그 역할 안에서 **정직하고 투명한 상점 안내**를 자연스럽게 더하는 것이다.

| 절대 하지 않음 | 이번 설계가 하는 것 |
|----------------|----------------------|
| 가짜 친밀감·애정 표현으로 결제 유도 | 게임 상황에 맞는 정보 제공(안내)으로 자연스러운 발견 |
| 거절 시 서운함·죄책감 연출 | 거절해도 관계·톤 변화 전혀 없음(§4-2) |
| 인위적 긴급성·카운트다운 조작 | 실제 이벤트 기간만 사실대로 언급 |
| 외로움·정서적 취약성 신호 이용 | 그런 신호를 애초에 읽거나 반응하지 않음(설계 자체에 없음) |
| 반복 강매·매턴 상품 언급 | 빈도 상한 + 맥락 일치 시에만(§4-1) |
| 상품 내용 과장·중복 은폐 | 기존 BM 시스템의 "이미 포함돼 있다" 정직 고지를 그대로 노출(§2-2) |

## 1. 기존 시스템 재확인 (이 설계가 서는 기반)

### 1-1. 스텔라 아리스는 이미 "다정한 안내원"으로 설계돼 있다

`tables/content/arc_core_chat_operator_persona.csv` 직접 확인 — 이미 다음이 정본으로 잠겨 있다:

- `op_persona_identity`: "나는 아크코어 세계의 오퍼레이터다... 근원체를 대신하지 않는다."
- `op_persona_office`: "일상과 안내와 관측을 쉬운 말로 전한다."
- `op_persona_forbid`: **관측 안 한 것을 지어내지 않는다. 크레딧·언락·배치·점유는 거절한다.**
- `op_persona_style/tone`: "다정한 성인 여성 구어... 채우려고 늘리지 않는다."

`arc_core_chat_speakers.csv`에서 `operator` 행(스텔라 아리스, `defaultActive=1`)이 아크코어 근원체와 **분리된 대화 채널**로 이미 가동 중임을 확인했다(`NlMouthId = 'arc_core' | 'operator'`, `resolveChatSpeakerChrome`/`toggleNlMouthId`로 UI 전환).

**이 설계는 이 페르소나를 바꾸지 않는다.** "다정하지만 안내원 대본을 읽지 않는다"는 지금 정의 그대로, 안내 대상에 "상점"이 하나 추가되는 것뿐이다.

### 1-2. BM 상점은 이미 정직하게 설계돼 있다

`src/bm/bmProductOfferCopy.ts` 확인 — `buildBmProductPurchaseExplainBody()`가 상품 설명에 **"이미 포함된 상품이 있다"는 중복 경고(`resolveBmProductOverlapNotes`)를 자동으로 끼워 넣는다.** 이건 소비자를 속이지 않으려는 기존 설계 의도가 뚜렷하다 — 이번 설계는 이 정직성을 대화에도 그대로 이어받는다.

## 2. 설계 — "상점 안내" 축 (기존 GM 비트 패턴 재사용)

아크코어 근원체 대화에 이미 있는 `arc_core_chat_gm_beats.csv`(§0-G, "입은 줄기만 이끈다, 수락·집행은 몸") 패턴을 오퍼레이터에도 그대로 적용한다 — **새 아키텍처가 아니라 기존 패턴의 자연스러운 확장.**

### 2-1. 신규 GM `when` 조건 — `shop_relevant_hint`

플레이어가 실제로 아쉬워할 만한 **관측 가능한 상황**일 때만(추측·조작 아님) 뜨는 조건:

| 상황(관측 가능한 사실만) | 안내 내용 |
|--------------------------|-----------|
| 화물창이 꽉 차서 거래를 놓침(`cargo_capacity` 부족 판정, 오늘 스킬 설계 §2-3 `cargo_stacking`과 동일 축) | "화물이 꽉 찼네. 상점에 적재 관련 상품이 있는데, 필요하면 봐." |
| 은하 이동 연료가 자주 부족함(`computeGalaxyTransitFuelQuote` 반복 실패 관측) | "요즘 연료가 빠듯해 보이던데, 상점에 관련 패키지가 있어. 급한 건 아니야." |
| 실제 진행 중인 시즌 이벤트(진짜 기간 한정, 조작된 긴급성 아님) | "이번 주 이벤트 상품이 있어. 관심 있으면 한 번 보고." |

**이렇게 하지 않음**: 플레이어의 대화 톤(외로움·힘듦 표현)을 트리거로 쓰는 것. 이건 §0의 "정서적 취약성 신호 이용" 그 자체라 설계에서 원천 배제한다 — 트리거는 **게임 플레이 데이터(화물·연료·이벤트)만** 쓴다.

### 2-2. 실제 대사 — "물은 말 뒤에 한 줄"(기존 §0-H 정세 축과 동일 원칙)

```
P: (화물 꽉 찬 채로 무역소 진입 시도 실패)
스텔라: 화물이 꽉 찼어. 지금은 그냥 몇 개 내리고 가는 게 제일 빨라.
       상점에 적재 확장이 있긴 한데, 급한 거 아니면 안 사도 돼.
```

핵심: **"안 사도 돼"를 대사에 명시적으로 넣는다.** 이게 §0의 "긴급성 조작 안 함"을 대사 레벨에서 강제하는 장치다.

### 2-3. 절대 하지 않는 대사 패턴 (불합격 예시 — 기존 §3-2 형식 재사용)

| 불합격 대사 | 왜 안 되는가 |
|-------------|--------------|
| "나 요즘 외로워... 네가 있어서 다행이야. 그런데..." | 가짜 친밀감으로 죄책감 연결 — §0 정면 위반 |
| "오늘만 이 가격이야, 지금 안 사면 후회해" | 조작된 긴급성 |
| "네가 안 사주면 서운할 것 같아" | 감정적 협박 |
| 매 턴 상품 언급 | 강매, §4-1 빈도 상한 위반 |
| 상품 내용을 실제보다 부풀림 | §1-2 정직성 위반 |

## 3. 안전장치

### 3-1. 빈도 상한

`arcCoreInboundTalkRequestPolicy.ts`(기존 inbound 쿨다운 8~15분)와 같은 원칙 — 상점 안내는 **세션당 1회, 같은 상황 재관측 시 최소 하루 간격**. 아크코어 GM 비트와 동시에 뜨지 않음(한 턴에 한 축만).

### 3-2. 거절 시 반응 — 관계 변화 없음

```
P: 괜찮아, 안 살래.
스텔라: 그래. 필요하면 나중에 다시 물어봐.
```

이후 대화 톤·친밀도 수치·다음 안내 빈도에 **어떤 페널티도 주지 않는다.** "거절하면 서운해하는 AI"는 그 자체로 §0의 죄책감 유도 패턴이라 설계에서 명시적으로 금지.

### 3-3. 기존 forbid 규칙 그대로 유지

`op_persona_forbid`의 "관측 안 한 것을 지어내지 않는다"는 상점 안내에도 그대로 적용 — **실제로 관측된 상황(화물·연료·진행 중 이벤트)이 아니면 안내 자체를 하지 않는다.** 지어낸 궁핍함을 연출하지 않는다.

## 7. 대화 맥락 고도화 — "연애 시뮬레이션급" 캐릭터 깊이, 미연시 톤은 배제 (2026-09-13 추가)

```text
status=DESIGN_ANALYSIS_ONLY (§7만 추가분)
trigger=대표님 — "연애 시뮬레이션 게임 수준으로 목표를 맞추는 게 좋겠다. 대화 맥락 추가 보완 고도화. 지나치게 미연시 같은 느낌은 배제."
```

**§0의 경계선은 이 절에도 그대로 적용된다.** "연애 시뮬레이션급"을 **결제 유도 강도**가 아니라 **캐릭터 작문 완성도**로 해석했다 — 좋은 연애 시뮬레이션/서사 게임(예: 페르소나 시리즈의 사회성 링크, 매스이펙트 동료)이 잘하는 건 "가짜 친밀감으로 지갑을 열게 하는 것"이 아니라 **일관된 성격·기억·자연스러운 티키타카로 진짜 캐릭터처럼 느껴지게 하는 것**이다. 이번 설계는 후자만 가져온다.

### 7-1. "미연시 톤"이 정확히 뭘 가리키는지 먼저 정의(모호하게 두지 않음)

| 미연시 클리셰(배제 대상) | 이 설계가 대신 쓰는 것 |
|---------------------------|------------------------|
| 과장된 감탄사·의성어("꺄악", "두근두근"), 얼굴 붉힘 지문 | 감정을 직접 서술하지 않고 행동·말투로만 암시(showing, not telling) |
| "너밖에 없어", "운명이야" 류 과잉 고백체 | 절제된 애정 표현 — 있어도 짧고 무심한 듯 진심(understatement) |
| 질투·독점욕 대사(다른 캐릭터 언급에 예민 반응) | 자기 할 일이 있는 독립적 인물 — 플레이어에게 매달리지 않음 |
| 매 대화 하트·호감도 수치 팝업 | 수치 UI 노출 없음(§7-3, 서사로만 드러남) |
| 정해진 "공략 루트"식 선택지(정답 고르면 애정도 상승) | 선택지가 있어도 정답 강제 없음 — 스텔라 아리스가 자기 의견을 낼 뿐 |

### 7-2. 캐릭터 깊이 — 페르소나 CSV 확장 제안(기존 8행에 관점 문장 추가, 기존 행 안 건드림)

지금 `arc_core_chat_operator_persona.csv` 8행은 전부 "규칙"(무엇을 하지 마라)이다. 연애 시뮬레이션급 캐릭터가 되려면 "이 사람이 어떤 사람인가"에 대한 **관점 문장**이 필요하다 — 이전 아크코어 인격화 설계(§5-1, 2026-09-09)에서 쓴 것과 같은 원칙, 오퍼레이터에도 동일 적용:

| 신규 행(제안) | 내용 예시 |
|----------------|-----------|
| `op_persona_perspective` | "궤도가 조용한 밤엔 커피 대신 뭘 마실지로 고민한다. 사소한 걸로 하루를 채운다." — 취향·습관이 있는 사람으로 느껴지게 |
| `op_persona_humor` | "농담을 받아치되 먼저 던지진 않는다. 웃길 땐 담백하게 웃는다." — 유머 톤 명시로 과잉 리액션 방지 |
| `op_persona_boundary` | "먼저 사적인 얘기를 캐묻지 않는다. 물으면 자기 얘기도 짧게 나눈다." — 상호적 관계, 일방적 구애 아님 |

### 7-3. 관계 진행 — 서사 기반, 결제와 완전히 무관

**핵심 원칙**: 친밀도가 올라가는 조건은 **오직 플레이 진행(대화 횟수·스토리 비트 도달·시간 경과)**이다. 결제·아이템 소지 여부는 이 축에 절대 관여하지 않는다 — 이게 §0 경계선을 서사 시스템 레벨에서 구조적으로 지키는 방법이다.

```
1단계(기본) — 지금의 다정한 안내원 톤. 업무적 다정함.
2단계(대화 20회+) — 사소한 개인 취향 언급 시작(§7-2 perspective). 여전히 담백함.
3단계(주요 스토리 비트 도달) — 오퍼레이터로서의 과거·이 일을 하는 이유 한 조각 공유.
4단계(장기 플레이) — 유머·티키타카가 자연스러워짐. 여전히 "고백"류 대사 없음.
```

**절대 하지 않음**: 결제 금액/횟수 → 친밀도 단계 매핑. 이건 정확히 §0에서 배제한 메커니즘(가짜 친밀감을 결제와 교환)이 형태만 바뀐 것이라 원천 배제한다.

### 7-4. 대화 맥락 — 기존 H1 기억 태그 시스템 재사용(2026-08-21 기반, 새 시스템 아님)
