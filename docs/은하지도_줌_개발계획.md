## 0. 잠금 (대표님 정본)

```text
(최대축소) 100%  <>  50%  <>  0%  <>  50%  <>  100% (최대확대)
단 인덱스:   0         1        2        3         4
```

| 항목 | 잠금 |
|------|------|
| 조작 | 핀치 없음. **[−] / [+]** 만. 클릭 1회 = **사다리 한 칸** |
| 위치 | 정보창(하단 패널) **바로 위** · 맵 안. 왼쪽 `[−]` · 오른쪽 `[+]` |
| `0%` | 지금 은하 지도 = 배율 `1` (기본 진입) |
| `50%` | 그 방향 끝단까지 **같은 비율의 절반** (기하 중간) |
| `100%` 축소 | 은하 전체가 한 화면 · **스크롤 없음** |
| `100%` 확대 | 축소비의 **역수** (동일 비율 반대) |
| 어디 있든 | **최대확대 → 최대축소 = `[−]` 4회**. 반대는 `[+]` 4회 |
| `0%`에서 | `[−]` 2회 = 최대축소 · `[+]` 2회 = 최대확대 |

끝단에서 같은 방향은 노옵. hop을 현재 위치에서 다시 나누지 않는다.

**확대(0%보다 오른쪽, 단 3·4)에서도 탭·이동은 지금과 같다.** 성계 클릭, 정보창, 항로 이동. 배율만 커지고 조작 체계는 그대로다.

## 0-A. 버튼 vs 구글맵 핀치 — 왜 버튼인가

| | 5단 `[−]`/`[+]` | 두 손가락 모으기/벌리기 |
|--|------------------|-------------------------|
| 탭·이동 | 한 손가락만. 지금 Tap/Pan과 **안 싸운다** | 핀치·팬·탭이 같은 제스처 장. 확대 중 오탭·이동 실패가 남 |
| 최대축소 | 단 0에 **정확히** 도착. 스크롤 0 | 연속값. 끝단을 지나치거나 살짝 못 맞춤 |
| 50% 칸 | 잠근 사다리 그대로 | 없거나 스냅을 또 넣어야 함 |
| 이 맵 크래시 이력 | 버튼은 JS 탭 1회 | 월드맵 Pan/Tap worklet `executeSync` SIGSEGV가 있었음. 핀치는 같은 축에 제스처를 더 얹음 |
| 익숙함 | 전략맵·끝단 맞춤 | 구글맵·거리 보기 |

이 화면의 일은 길을 보는 것이 아니라 **별을 찍고 이동하는 것**이다.  
**1안 = 버튼 5단.** 핀치는 넣지 않는다. 나중에 같은 `S_min`~`S_max`로 핀치를 얹는 것은 별도 승인.

## 2. 배율 사다리 (기하 · 동일 비율)

원점 `S0 = 1` = 지금 지도.

`S_min` = 가시 은하 bbox가 맵 뷰포트에 **스크롤 없이** 들어가는 배율 (`content ≤ viewport`).  
`S_max = 1 / S_min`  (기준 1에서 축소비의 역 = 확대비)

한 번의 클릭은 **기하 중간**(절반 비율). 산술 평균(0.7 같은 가감)이 아니다.

```text
% :     100%축소    50%축소     0%      50%확대    100%확대
단:     0           1           2       3          4
값:     S_min       √S_min      1       √S_max     1/S_min
```

`[−]` → 단 −1 · `[+]` → 단 +1. 클램프 0..4.

| 출발 | `[−]` 횟수 | 도착 |
|------|------------|------|
| 4 최대확대 | 4 | 0 최대축소 |
| 2 `0%` | 2 | 0 최대축소 |
| 3 `50%`확대 | 1 | 2 `0%` |
| 0 최대축소 | 1+ | 그대로 |

예: 전체를 넣으려면 0.49배면 — 0.49 · 0.70 · **1** · 1.43 · 2.04

`S_min`은 뷰포트·bbox로 계산. 상수 금지.  
`mapContentSize`의 `span` 하한 0.001 · `clampDim` 1..8192를 **재사용**한다 (김클로드 검수 · 김팀장 채택).

## 4. 카메라 · 확대 후에도 지금 조작

| 이벤트 | 앵커 |
|--------|------|
| [−]/[+] 1단 | 화면 중심(또는 현재 성계가 보이면 그 점) 유지 |
| 최대축소 | bbox 전체가 들어가게 맞춤 · `scroll = 0` · maxScroll = 0 |
| 최대확대 | 같은 앵커로 확대 · 스크롤 클램프만 재계산 |

`toScreen` · 탭 히트 · 항로 · 보로노이는 **같은 배율**을 쓴다.  
스크롤 SharedValue는 **버튼 탭 후에만** 기존 `runOnUI` 클램프로 갱신. JS에서 `.value` 읽기 금지.

### 4-A. `mapLayout` — 뷰포트 ≠ 콘텐츠 (김클로드 지적 · 김팀장 정정)

`mapLayout.w/h`를 **전부 ×scale 하면 안 된다.** 창 크기와 은하 좌표를 가른다.

| 쓰는 곳 | 역할 | 배율 |
|---------|------|------|
| `toScreen` | 콘텐츠 좌표 | × scale |
| `mapContentSize` cw/ch | 콘텐츠 크기 | × scale + 기존 8192 clamp |
| `computeScrollTargetForSystem`의 pos | **toScreen과 식이 중복** | toScreen을 호출하거나 같은 scale. 뷰포트 `vx/vy`는 그대로 |
| `maxScroll = content - mapLayout` | 창 | 뷰포트 **불변** · content만 커짐 |
| 뷰포트 View `width/height: mapLayout` | 창 | **불변** |
| `mapMetricsReady` | 창 준비 | 불변 |

Z4 게이트: 위 표로 `worldmap.tsx`의 `mapLayout.w/h` 참조를 전수하고, 콘텐츠만 scale인지 확인.

### 4-B. `NODE_HIT_R` (28) 스케일

히트는 콘텐츠 좌표(`viewport + scroll`). 지금 28은 고정. 확대하면 노드 원은 커지고 히트만 28이면 원 가장자리가 안 찍힌다. 축소하면 28이 이웃과 겹친다.

1안: `hitR = clamp(NODE_HIT_R * scale, 20, NODE_HIT_R * S_max)` · 최근접 1개(현행 `bestDist`) 유지.

단 2·3·4(기준·확대)에서 **필수**:

| 지금 | 확대 후에도 |
|------|-------------|
| 한 손가락 탭 → 성계 선택·정보창 | 동일. 히트 박스는 스케일된 좌표 |
| 한 손가락 드래그 → 팬 | 동일 (최대축소만 스크롤 0) |
| 선택 후 이동 | 동일 경로·연료·메뉴 |

축소 단(0·1)도 보이는 프론티어/차트 성계는 탭·이동이 된다. 차폐는 포그 계약대로 히트 없음.
