# 플레이봇 3단 개선 프로세스 (주관 김플레이 · 2026-10-06 대표님 지시)

> 「1) 플레이봇의 성능개선 (김플레이) 2) 플레이봇이 자체적으로 성능개선 및 학습 (플레이봇) 3) 분석과 학습에 따른 필수 게임기능·밸런스·성능 개선 (대표님·김팀장). 실시간 혹은 반복 수행. 주체는 김플레이. 정체(홀딩·대기) 지점을 지속 보고. 김팀장 역할도 주시.」

## 1. 역할

| 단 | 담당 | 하는 일 | 산출 |
|---|---|---|---|
| 1단 | 김플레이 | 봇 행동·트윈 정합 개선, 일 1회 벤치로 후퇴 감시 | `tools/play-bot-console/**` 변경 · `bench-history.ndjson` |
| 2단 | 플레이봇 | 실기 로그 → human-delta → 정책 적응, FQA 30분 자체 검토, 정체 시 재시작·벽 기록 | `logs/learned/*` |
| 3단 | 대표님·김팀장 | 봇이 찾은 게임 문제(경제·밸런스·성능) 판단과 수정 | handoff B-항목 응답 · 게임 코드/CSV 변경 |

김플레이는 3단 코드를 고치지 않는다. 3단의 진행 여부를 **관찰**하고, 3단이 게임을 바꾸면 그 변화를 트윈에 반영(1단으로 되돌림)한다.

## 2. 주기

| 무엇 | 주기 | 어디서 |
|---|---|---|
| 감시판 갱신 | 30분 | FQA 루프(`review-fqa-cycle.ts --loop`) 안에서 `runProcessBoard` |
| 봇 벤치 (1,200일 × 4시드, 정체 횟수 포함) | 24시간 1회 | 같은 루프, 별도 프로세스로 실행 |
| 채팅 알림 | 상태가 나빠지거나 풀릴 때. STOP·RISK 즉시, 나머지 2시간에 1회 | `PLAYBOT_CHAT_REPORT_PENDING.md` → 다음 프롬프트에 자동 주입(열린 모든 창, 김팀장 창 포함) |
| 18:00 데일리 | 1일 | 기존 `playbot:report-daily-18` |

## 3. 상태 정의

| 상태 | 뜻 | 누가 움직여야 하나 |
|---|---|---|
| OK | 정상 | — |
| RUN | 진행 중 (김플레이 처리 대기열 포함) | 담당 |
| WAIT | 다른 담당 응답 대기 | 표시된 담당 |
| HOLD | 장기 대기(3단 48시간·1단 72시간 초과) 또는 의도적 보류 | 표시된 담당 · 김플레이가 재보고 |
| RISK | 이상 징후 (벤치 후퇴, 재기동 후 6시간 내 성장 정지 3회, 수집기 끊김) | 김플레이 우선 |
| STOP | 프로세스 종료 | 김플레이 (`npm run playbot:restart`) |

## 4. 감시 항목

- **1단**: 벤치 직전 대비 후퇴(레벨·본편·퀘스트) · 벤치 중 성장 정체 · 김플레이 처리 항목 나이.
- **2단**: 하네스·FQA 루프·실기 수집기·콘솔 생존 · 실기 입력 마지막 반영(24시간 넘으면 대표님 플레이 대기) · 정책 적응 · FQA CLI 응답 · 카드 동결 · 정체 재시작과 벽.
- **3단**: 김팀장 검수 상태(handoff status) · B-항목별 완료 신호(커밋·CSV 변경·npm 스크립트) · 봇이 흉내 내는 게임 파일 변경(트윈 정합 필요).

항목 등록부: `tools/play-bot-console/process-items.json` (B-항목 추가·완료 신호·감시 파일).

## 4-B. 3단 게임 개선 항목 올리는 법 (대표님 2026-10-06)

- 플레이봇·트윈·감시 프로세스 문제가 아님을 **게임 코드·CSV로 확정한 것만** 올린다. 트윈 근사에 기대는 판정은 1단 검증 항목으로 둔다.
- 정본은 `docs/ops/차기_업무_목록.md` §10 `PB-G`. 김플레이 이름으로 적는다.
- **차수제**: 김팀장에게 넘긴 차수는 닫는다. 새 항목은 닫힌 차수에 섞지 않고 다음 차수 절(10-2 …)에 PB-G4부터 이어 매긴다.
- 1차 = PB-G1~G3 (2026-10-06 15:02 김팀장 검토·개발 지시). 2차는 열려 있고 비어 있다.
- `process-items.json`의 3단 항목도 같은 ID·차수를 쓴다.

## 5. 명령

```bash
npx tsx tools/play-bot-console/process-board.ts               # 감시판 갱신
npx tsx tools/play-bot-console/process-board.ts --bench       # 벤치 강제
npx tsx tools/play-bot-console/process-board.ts --ack-mirror  # 게임 변경 트윈 반영 확인
npx tsx tools/play-bot-console/process-board.ts --done A-7a   # 수동 항목 완료
```

감시판: `tools/play-bot-console/logs/PLAYBOT_PROCESS_BOARD.md` · 변화 기록: `logs/learned/process-board-ledger.ndjson`

## 5-B. 스텔라 칸 — 1단 결과가 스텔라로 이어지는 길 (2026-10-06)

봇이 나아지면 스텔라 아리스도 같이 나아지도록, 1단 벤치 뒤에 스텔라 검증을 붙인다. 정본: `docs/playbot/STELLA_KNOWN_COLLEAGUE_DESIGN_v1.md` Part D.

| 순서 | 무엇 | 조건 |
|---|---|---|
| 1 | 일 1회 봇 벤치 (기존) | 후퇴 있으면 여기서 멈춤 |
| 2 | `botVersion` 확정 (정책 해시 · 미러 확인 시각 · 게임 CSV 해시) | 미러 WAIT 면 멈춤 |
| 3 | 스텔라 검증 — 조언 3자 A/B · 능동 빈도 재생 (사람다운 세션만) | `botVersion` 이 지난 검증 뒤 바뀐 날만 |
| 4 | `stella-bench-history.ndjson` 1줄 · 리포트 | 항상 |
| 5 | 지금 표와 다른 통과 후보 → `PB-S` 항목 (lane 3 · Fable / 기존값은 대표님) | verdict=PASS 일 때만 |

- 봇은 `tables/`·스텔라 앱 코드를 고치지 않는다. 후보와 근거만 낸다.
- 감시판에 「마지막 스텔라 검증 시각 · verdict」 칸을 둔다 (D5). 72시간 넘게 봇은 바뀌었는데 검증이 없으면 HOLD.
- 대표님 개발 빌드 플레이의 `[PLAY_VERB]` 가 human-seed 로 들어와 2단 적응을 거치면, 사람다운 세션이 대표님에게 가까워지고 스텔라 빈도·임계값도 따라 맞춰진다.

## 6. 한계

- 감시판은 FQA 루프에 붙어 있다. FQA 루프가 죽으면 갱신도 멈춘다(콘솔 재기동이 루프를 같이 살린다). 감시판 시각이 1시간 넘게 오래되면 루프 정지로 본다.
- 알림은 다음 프롬프트 때 주입된다. 대표님이 아무 창에도 입력하지 않으면 화면에 뜨지 않는다.
- 3단 판정은 파일 신호(커밋·변경 시각)로만 한다. 김팀장이 말로만 답한 경우는 김플레이가 `--done` 으로 닫는다.
