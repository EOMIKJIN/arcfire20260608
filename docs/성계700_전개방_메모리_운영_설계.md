### 0-A. 설계 목적 — 「기능 동일 작동」계약

본 문서의 1차 목적은 *코드에 이미 붙였는지*가 아니라:

1. **현재 구축된 게임 기능**(이동·허브·무역·전투·일일배치·확장·맵·부트)을 전제로 한 스케일 설계인가  
2. **~700 코어개방**이 되어도 그 기능들이 **플레이 체감상 동일하게** 돌아가게 만드는 운영 구조인가  

| 판정 | 내용 |
|------|------|
| 현재 시스템 반영 | **PASS** — §2 스냅샷이 코드와 정합 |
| 700시 기능 연속성 | **조건부 PASS** — §4 Sector Band Ops · Hot/Cold · 맵 LOD · 증분 economy가 **구현 전제** |
| 현행 코드만으로 700 | **FAIL 예상** — R1·R2·R3 (배치 O(N)·persist·맵 노드) |

## 1. 문제 정의

### 1-1. 목표 시나리오

아크코어 확장으로 **미발견 → 미개척(지도 표시만) → 코어 편입(B→A)** 이 진행되어, 장기적으로 **코어 관리 성계·행성이 ~700** 에 근접할 수 있다.  
**해금(일일 개방) ≠ 미개척 표시.** 일일 개방은 이미 보이는 미개척을 코어로 편입한다. 미발견을 보이게 하는 축은 별도(§15).

### 1-2. 실패 모드 (과거 회귀와 동일 계열)

| 모드 | 증상 |
|------|------|
| 일일 배치 O(N) 전량 동기 | 정오/부트 JS 스레드 장악 · 타이틀/입력 멈춤 |
| `planetCoreRuntime` unbounded | PSS floor 상승 · AsyncStorage JSON 비대화 |
| 맵 풀 노드 | Views/SVG/Voronoi 비용 · 프레임 드랍 |
| 개방 직후 경제 전량 integrate | 카탈로그·convoy 등록 폭주 (기존 O(n) 회귀 이력) |

### 1-3. 성공 기준 (운영)

| 지표 | 목표 (설계 초안) |
|------|------------------|
| 활성 허브 | 항상 **1** STAGE 세션 |
| 맵 인터랙티브 노드 | 뷰포트·밴드 기준 **≤ ~120** soft · **≤ ~200** hard |
| 핫 코어 런타임 행성 | **≤ ~80~120** (방문·점유·무역활성·근접) |
| 일일 배치 1틱 점유 | 청크+yield · 타이틀 버튼 게이트와 **분리** (현행 계약 유지) |
| 전량 해금 후에도 | idle PSS floor 계단식 붕괴 없음 · `audit:memory` 계열 유지 |

## 2. 현재 아키텍처 스냅샷 (코드 근거 · 변경 없음)

### 2-1. 계층

```text
[그래프] GALAXY_SYSTEMS ~757 — 번들/월드스토어 상주 (가벼움)
    │
    ├─ [맵 가시] visibleSystemsList
    │     · 21 코어 + 레거시 미개척(~79) + 확장 게이트웨이 + 해금 synth
    │     · 잠긴 미발견 → GalaxyMapUndiscoveredStarlightSvg (별빛)
    │
    ├─ [코어 개방 풀] listCoreOpenGameplayPlanetIds
    │     · A: 21 CSV 항상
    │     · B: unlocked synth + phase≥1
    │
    └─ [허브 STAGE] planet.tsx 세션 1 — dispose on replace
```

정본 주석: `src/world/coreOpenGameplayPlanets.ts` (A/B/C 티어).

### 2-2. 확장·개척

| 경제·코어 연동 | `integrateUnlockedSynthFrontierStatEconomy` | 개방분 ensure |

### 2-5. 이미 있는 선례 (재사용 · 신규 발명 금지 우선)

| 선례 | 경로 | 설계 활용 |
|------|------|-----------|
| 클라우드 백업 Hot/Cold 필터 | `slimGameSaveSnapshotForUpload.ts` (`retainPlanetIds` / `hasPlanetCoreBackupValue`) | §4-1·§4-5 로컬 persist 희소화의 **출발점** |
| warm 카탈로그 Set | `residentSetRegistry.ts` (`warmedPlanetCatalogIds`) | Hot 승격 추적 패턴 |
| 미발견 별빛 O(1) | `GalaxyMapUndiscoveredStarlightSvg` (배치 Path ≤15) | 잠금 성계는 **이미** 노드 비폭발 — LOD는 **해금 가시 노드**에 집중 |

### 2-6. 현재 규모 사실 (재검수 §14 흡수)

| 사실 | 의미 |
|------|------|
| `byPlanetId` 엔트리는 hydrate 시 **이미 ~760** | 그래프 전 행성 baseline stub. R2는 「미래에 700개」가 아니라 **오늘도 개수는 풀 · detail/바이트가 차면 위험** |
| DailyOps는 O(N) 선형(알고리즘 버그 수정 후에도) | 개방 풀·패스 대상이 커지면 **배치 시간 선형 증가** (실측 근거 §14-3) |
| colonization phase+1은 systems 맵 전량 얕은 복제 | 비용 ≈ O(해금_synth × \|systems\|) — 쿼터/섹터 재설계 **우선순위↑** |

## 3. 용량 모델 (설계)

### 3-1. 네 축으로 “700”을 분리한다

| ID | 의미 | 목표 |
|----|------|------|
| **G-700** | 그래프에 존재하는 성계 | 현행 유지 가능 |
| **V-*** | 맵에 **인터랙티브**로 그리는 성계 | LOD로 상한 |
| **H-*** | 핫 시뮬레이션·(로컬) persist 상세 대상 행성 | 희소 상한 |
| **Hub-1** | 활성 행성 허브 | 항상 1 |

**금지 사고**: “700 개방 = 700 허브 = 700배 메모리” — 허브는 Hub-1.  
**주의**: G와 `byPlanetId` 키 개수는 이미 ~760에 가깝다. H는 **상세 시뮬·두꺼운 persist** 상한이다.

### 3-2. 예산 초안 (한 주간 다듬기)

| 풀 | Soft | Hard | 비고 |
|----|------|------|------|
| V (맵 노드) | 120 | 200 | 초과분은 클러스터/별빛 |
| H (핫 런타임) | 80 | 120 | 콜드는 스텁·온디맨드 hydrate |
| 일일 배치/청크 | 20~40 행성/슬라이스 | — | yield 필수 |
| AsyncStorage core blob | 모니터링 | 실패 시 샤딩 | §6 |

수치는 **설계 앵커 JSON**과 동기화한다. 확정 전 soft.

## 4. 목표 운영 아키텍처 (제안 정본)

### 4-1. 티어

```text
Tier G — Graph (전량 상주, 읽기 위주)
Tier C — Cold open (해금됐으나 비활성: 최소 메타만)
Tier H — Hot (방문/점유/무역/근접/최근 전투)
Tier S — Session hub (현재 행성 STAGE만 Skia·WO·트래픽)
```

승격 트리거 후보: 착륙 · 점유 변경 · 무역소 활성 · 플레이어 N홉 이내 · 아크코어 캠페인 타깃.

강등: 장기 미방문 · 비점유 · 거리 밖 — **콜드 메타만 유지**, 상세 런타임 GC/스냅샷.

**재사용 계약 (김클로드 §14-6 · D3)**: Hot 집합 추적은 신규 invent 금지.  
정본 후보 = `src/arcCore/memory/residentSetRegistry.ts` 의 `warmedPlanetCatalogIds`(이미 동작 중인 Set 기반 warm 캐시)를 **Hot 승격/강등 레지스트리로 확장·연동**.  
백업 필터(`slimGameSaveSnapshotForUpload.retainPlanetIds`)와 **동일 planetId 집합 의미**를 맞출 것.

### 4-2. 은하 지도

| 거리/상태 | 표현 |
|-----------|------|
| 잠금 미발견 | 현행 별빛 (유지) |
| 원거리 해금 | 클러스터 도트 / LOD0 |
| 중거리 | 소형 노드 · 라벨 생략 |
| 근거리·선택·항로 | 풀 노드 · 연결선 · 점유 색 |

Voronoi: **전 700 사이트 매 프레임 금지**.  
핫/가시 사이트만 또는 섹터 캐시 + dirty 시에만 rebuild.

### 4-3. 일일 배치 · ArcCore

| 규칙 | 내용 |
|------|------|
| 부트 동기 전량 금지 | 현행 헌법 유지 · 타이틀 게이트와 **분리** |
| 전량 forEach → 로테이션 | `dayKey + sector` 로 일부만 deep pass |
| light pass | 플래그·카운터만 (콜드) |
| deep pass | 핫 행성 + 당일 섹터 샘플 |
| yield | 슬라이스 사이 `yieldJsThread` 유지·강화 |
| 체감 연속성 | 플레이어가 보는 코어 게이지·경제는 **방문/무역 활성(H)** 에서 현행과 동일 갱신 |

`runSynthColonizationAdvancePass` / `applySynthColonizationPhase` — **P0 · 구현 우선순위 상향** (김클로드 §14-6 · 별도 승인 후 I-wave):

| 항목 | 내용 |
|------|------|
| 근거 | `worldStore.applySynthColonizationPhase`가 시스템 **1개** phase+1마다 `{...state.systems}`로 **전체 systems(~760) 얕은 복제** → 비용 ≈ O(해금_synth × \|systems\|) |
| 기능 유지 | 개척 phase 일일 진행(플레이 체감)은 **동일** |
| 비용 목표 | **밴드/쿼터** + **in-place / 부분 패치**(전량 맵 복제 금지) |
| 비고 | “장기 후보”가 아니라 **I1~I2급 선착수 후보** (개방 풀이 커지기 전에도 이득) |

### 4-4. 경제 · ownership

| 축 | 설계 |
|----|------|
| item_defs ownership | Table-First 행은 유지 가능 · **런타임 카탈로그는 핫/무역 활성만** |
| convoy/trade enroll | 개방 즉시 전량 등록 지양 → 무역소 설치·첫 방문 시 (`ensureUnlockedSynthFrontierEconomyEnrollment` 갭) |
| integrate* | 배치·해금 시 **증분 only** · 전량 rebuild 금지 |
| 플레이 체감 | 무역소·ownership UI는 **해당 행성 진입/활성 시** 현행과 동일 |

### 4-5. Persist (김클로드 §14-6 최상 · 즉시 절감 여지)

> **전제 정정**: 「개방 풀이 커지면 콜드 omit」이 아니라 —  
> **첫 hydrate부터 `byPlanetId`에 이미 ~760 baseline stub이 존재**한다.  
> 따라서 로컬 persist 희소화는 **오늘 규모에서도 착수 가능한 절감**이다 (미래 전용 작업 아님).

| 데이터 | 전략 |
|--------|------|
| unlockedSystemIds | 유지 (ID 목록 · 작음) |
| synthColonizationPhase | 유지 또는 압축 맵 |
| planetCoreRuntime (메모리) | 키 ~760 stub **허용**(그래프 정합). **두꺼운 detail만 Hot** · Cold는 baseline/omit·온디맨드 hydrate |
| planetCoreRuntime (**로컬 persist**) | **`slimGameSaveSnapshotForUpload.ts`의 `retainPlanetIds` / `hasPlanetCoreBackupValue`를 로컬 경로에 재사용** — 새 필터 invent 금지. Cold stub을 디스크에서 빼도 기능 동일(재시드 가능) |
| 클라우드 백업 | 현행 slim 유지 · 로컬과 **동일 retain 의미** 정렬 |
| R2 완화 초점 | 「키 개수 억제」❌ · **바이트/엔트리·detail fill rate·persist 대상 축소** ✅ |

### 4-6. 정상 연동 체크리스트 (전개방 시에도 깨지면 안 되는 것)

기능 **동일 작동** = 아래가 700개방 후에도 통과해야 함 (§0-A).

- [ ] 21코어 이동·허브·무역·전투
- [ ] STAGE replace · dispose · Skia 계약
- [ ] 해금 성계 착륙 → 허브 1세션
- [ ] 일일 배치가 타이틀 버튼을 막지 않음
- [ ] 전역 확장 스케줄(결정적)과 클라이언트 일치
- [ ] purge / 계정 초기화와 월드 축 분리 규칙 유지
- [ ] 방문 행성 코어 게이지·무역·궤도 트래픽 체감이 현행과 동등 (콜드 희소화는 백그라운드만)

### 14-1. §13이 놓쳤거나 더 정확히 서술해야 할 것 (신규 발견)

|---|------|----------|-------------|------|

## 15. 3단계 확장 × 700 종단 재검수 (2026-08-21)

대표님 정본:

| 단계 | 의미 | 용량 축 |
|------|------|---------|
| **미발견** | 안 보임. 별빛만 | G만. V/H 증가 없음 |
| **미개척** | 지도에 보임. 코어 아님. 가명 `미개척-N` | **V만** 증가 |
| **코어성계** | 일일 편입. 실명·점유·개발 | **H + 배치 O(코어)** 증가 |

| 파이프 | 주기 | 하는 일 | 금지 |
|--------|------|---------|------|
| **일일 개방** | 1일 1개 | 미개척 → 코어 | 산식·API·epoch **변경 금지** |
| **표시 승격** (신규) | 3일 1개 · 오늘부터 | 미발견 → 미개척 가시 | `unlockSystem` 금지 |
| **첨가** | — | 보이게 된 id ⊂ 일일 편입 후보 | 숨은 미발견 직행 코어 금지 |

### 15-1. 지금 규모 (대략)

| 축 | 추정 | 예산 |
|----|------|------|
| G 그래프 | ~760 이미 상주 | 유지 가능 |
| **V 맵 노드** | 21 + 레거시 미개척 ~79 + 게이트 ~16 ≈ **116** | soft 120 / hard 200 |
| **H 코어 런타임** | 21 + 편입 synth ~57 ≈ **78** (현행은 개방=등록) | soft 80 / hard 120 |

V는 **이미 soft 직전**. H도 soft 근처. 700 설계의 「현행 코드만 FAIL」은 **오늘도 유효**.

### 15-2. 종단까지 가면

표시 3일 1개 · 코어 1일 1개 · 남은 미발견 ~660.

| 시점 | V (표시 누적, LOD 없을 때) | H (현행 개방=등록) | 판정 |
|------|---------------------------|-------------------|------|
| +12일 | ~120 (soft) | ~90 | V soft 도달. 표시는 계속돼도 **풀노드면 초과** |
| +~6주 | ~130 | **~120 (hard)** | H가 먼저 hard. I1·I3 없으면 배치·persist 위험 |
| +~8개월 | **~200 (hard)** | ~300 | V hard. 풀노드 700 불가 |
| 미발견 전량 표시 (~5.4년) | **~760** | 코어는 그사이 전량 근처 | V 폭주 = **R3·R9** |
| 전량 코어 (~2년, 1일 1개) | 표시가 앞서면 V≈코어 | **~760** | R1 배치 선형 · R2 persist · R5 enroll |

**결론**: 그래프 700은 이미 있다. 위험한 것은 「전부 풀노드 + 전부 핫 시뮬」이다.  
표시 병행은 **H를 안 키운다**(올바름). 대신 **V를 코어보다 빨리 채운다.**

### 15-3. 설계 제약 (표시 구현 시 필수)

1. **일일 편입 불변** — 후보 집합에 표시분을 **첨가**만.
2. **표시 ≠ 코어** — 경제 enroll · `ensureUnlockedWorldPlanetsInCoreRuntime` · phase 1 · CSV 실명 금지.
3. **표시 ≠ 전원 인터랙티브 노드** — 「보인다」= 차트됨. 원거리 미개척은 클러스터/소형 마크. 풀노드는 근거리·항로·선택·프론티어. V soft120 / hard200 **유지** (I5와 동일 계약).
4. **종단 전 I1~I5** — 표시만 먼저 켜도, 코어 1일 1개는 H를 수 주 내 hard에 밀어 넣는다. persist slim(I1)·phase 전복제 제거(I2)·Hot 캡(I3)은 표시와 **병행 전제**. 맵 LOD(I5)는 표시 V 누적의 **가드**.
5. **회귀 금지** — 표시 목록·코어 unlocked 축소 없음.

### 15-4. 700 READY와의 관계

| Wave | 표시 3일 1개 | 일일 코어 1개 |
|------|-------------|---------------|
| I1 persist slim | 무관(표시는 persist 얇음) | **필요** (H 바이트) |
| I2 colonization in-place | 무관 | **필요** (코어 수×760 복제) |
| I3 Hot/Cold | 표시는 H 넣지 말 것 | **필요** (개방≠핫) |
| I4 DailyOps 섹터 | 표시 패스는 O(1) | **필요** (코어 풀 선형) |
| I5 맵 LOD | **표시의 V 가드** | 원거리 코어도 동일 |

표시 기능만 넣고 I5 없이 전 미개척을 `<Path>` 노드로 그리면, 수개월 내 700 설계 hard를 깨뜨린다.

## 16. 개발 우선 · 안정성 게이트 (2026-08-21 전수)

대표님 지시: 맵·월드 **분할/존로딩을 먼저**. 게임성·현행 동작 불변. **그다음** 미발견→미개척 표시 + 일일 후보 첨가.

### 16-1. 지금 당장 개방순차가 1순위인가?

**아니오.** 표시를 먼저 켜면 V가 늘고, 존 없이 노드가 쌓인다. 일일 편입은 이미 동작 중이며 손대면 안 된다.

| 지금 1순위가 아닌 것 | 이유 |
|----------------------|------|
| 미발견→미개척 표시 | V 증가. 존 가드 선행 필요 |
| 일일 편입 주기/픽 개조 | 게임성·월드 진행 변경. **금지** |
| 외곽 4칸 **강제 언로드**(지금 보이는 미개척 숨김) | 지금 지도에서 동서남북 미개척이 **한눈에 보임**. 숨기면 체감 변경 |
| I3 콜드 경제 스킵 · I4 배치 섹터로 게이지 희소 | 방문 안 한 행성 수치가 달라질 수 있음 |

### 16-2. 현행 코드 — 문제 없음 (고칠 버그 아님)

| 항목 | 상태 |
|------|------|
| 일일 미개척→코어 | 정상. 레거시 우선 |
| 맵 가시 ≈ 21+76+관문16(+해금) | 의도된 현재 모습. **존5(97)만이 아님** |
| 미발견 별빛 | O(1) 배칭 + 로드 존/화면 안 필터 |
| 존 로드 세션 | **반영됨.** 존5 상시 · 관문 트리거 · 반대 히스테리시스 |
| `GalaxyMapSystemsSvg` | `visibleSystemsList` **전량** Circle+라벨 |
| Voronoi | 가시 전량 사이트. 지금 규모 OK |
| 그래프 ~760 상주 | 설계상 유지. 존으로 지우면 안 됨 |

존로딩은 **신규 인프라**이지, 크래시 패치가 아니다. 반쪽 우회로 일일 편입을 건드리지 않는다.

### 16-3. 「게임성 불변」존로딩 정의

플레이어가 **오늘 보는 것·갈 수 있는 것·이름이 붙는 시점**이 같아야 한다.

| 허용 (체감 동일) | 금지 (체감 변경) |
|------------------|------------------|
| **뷰포트 컬링** — 화면 밖(+마진) 노드 미마운트. 스크롤하면 동일 | 지금 보이는 레거시 미개척을 방향 이유로 숨김 |
| 존 레지스트리(N/E/S/W+코어) **데이터만** | `unlockSystem` / epoch / systemsPerDay |
| 미발견 별빛 유지 | 줌 아웃 전은하에서 3칸을 빈 칸으로 |
| I2 phase **in-place** (진행 결과 동일) | I3/I4로 콜드 행성 경제·게이지 생략 |
| I1 persist slim (재시드 후 수치 동일) | 타이틀에 존 prewarm |

줌 아웃으로 지금 가시분이 한 화면에 들어오면 **지금과 같이 전부 그림**. 이득은 줌인·향후 노드 증가 때다.

### 16-4. 개발 순서 (잠금)

## 17. 존 기하 — 9칸 번호 · 실분포는 십자 5존 (실측 2026-08-21)

전 그래프 757. 좌표 bbox ≈ x[-1.90, 3.18] × y[-1.86, 2.78].  
확장 생성은 **동서남북 4 타원 클러스터**라 사각형이 아니라 **십자(+)** 이다.

### 17-1. 번호 (대표님 9분할)

```text
상  1   2   3     ← 2 = 북
중  4   5   6     ← 4 서 · 5 중앙(현재 지도) · 6 동
하  7   8   9     ← 8 = 남
```

전 bbox를 3×3 등분한 **실측 성계 수**:

| 존 | 전부 | 지금 가시 | 내역 |
|----|------|-----------|------|
| **5** | **97** | 97 | 코어 21 + 레거시 미개척 76. 미발견 0 |
| **2** 북 | 165 | 4 | 관문 4 + 미발견 161 |
| **4** 서 | 165 | 4 | 관문 4 + 미발견 161 |
| **6** 동 | 165 | 4 | 관문 4 + 미발견 161 |
| **8** 남 | 165 | 4 | 관문 4 + 미발견 161 |
| 1·3·7·9 | **0** | 0 | 성계 없음. 예약만 |

4분할(현재 중심에서 대각 절단)은 **존 5를 네 조각**으로 가른다(가시 30/24/25/34). 중앙 지도 개념과 맞지 않음.

**1안**: 번호는 9칸을 쓰고, **로딩 단위는 5·2·4·6·8**. 코너 1/3/7/9는 비어 있으므로 로드하지 않음.

지금 가시 bbox를 존 5로 키우면 관문·미발견 409가 5에 빨려 들어가 **522**가 된다. 쓰면 안 된다. 존 5 = **코어+레거시만**.

### 17-2. 관문 = 존 로딩 트리거

이미 `isExpansionGatewayOrdinal` 관문 **16** (방향당 4). 등분 9칸에서 각각 존 2/4/6/8에 4개.
