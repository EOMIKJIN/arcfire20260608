## 0. 한 줄 요약

배달 퀘스트는 **행성 허브에 착륙했을 때만** 완료되고, **도착 시 실제 화물이 있어야** 한다. HUD가 그 숨은 조건을 숨기던 문제는 1단계로 고쳤다. **식량팩 10개 구매 후 인벤 0·미완료(§3-C)** 와 배달 루프의 **오래된 player 스냅샷**은 아직 미착수 — 초기화 후 재현으로 원인을 확정한다.

## 2. 현재까지 적용된 수정

실기 재현 전에 이미 들어간 코드. Metro **`r` 리로드**면 충분 (네이티브 재빌드 불필요).

### 2-1. QuestHUD

- 활성 미션 스크롤 리스트. 헤더 1개 + 행 1개 높이 고정 (`QUEST_HUD_ROW_*` · 레이아웃 상수 변경 없음).
- 진행 중 + 목표 1개 이상 완료 → 작은 `Updated` 배지 (배경 무채색, 글자 시안).
- **§3-B 1단계**: 이동 목표가 남았는데 배달 화물이 모자라면, 구매 목표를 다시 보여 `· 부족`을 붙인다.  
  - 파일: `src/missions/resolveHudCurrentObjective.ts` · `src/components/QuestHUD.tsx`  
  - persist 플래그는 그대로 (배달 직후 클리어 대기 중 구매 목표가 되살아나지 않음).  
  - i18n: `mission.hud.cargoShort` = `부족` / `short`.

### 2-2. 진행·완료 파이프라인

| 항목 | 내용 |

| 빈 목표 미션 | 수락 `no_objectives`. 바 목록에서 숨김 |

### 2-3. 동시 완료 덮어쓰기 (§2 · 조치 완료)

김클로드 확정: 한 이벤트에서 활성 미션 2건이 마지막 목표를 동시에 채우면, 단일 `pendingMissionClearDialog` 슬롯이 앞 건을 덮어씀. HUD에는 「다 깼는데 안 사라짐」. 재부팅 hydrate 는 예전엔 1건만 복구.

- 테스트: `pendingMissionClearQueue.test.ts`.

  `src/arcCore/economy/tradeRouteSectorCategories.ts`.

### 2-7. 완료 담당자 — 오퍼레이터 기본 / 컨택 퀘스트만 NPC (2026-08-24)

김클로드 초안은 도착 행성만 있으면 바 주인을 전원 배정했다. **기각.**

| 구분 | 완료 대화 | 허브 [대화] |
|---|---|---|
| 일반(전투·탐험·단순 이동·구매만) | 오퍼레이터 | 기존 궤도/총사령관. 목적지 담당 활성화 없음 |
| 배달 `type=delivery` 또는 구매/화물+도착 | 목적지 바 주인(수락 스냅샷). 맞춤 씬 있으면 그 씬 | 목적지 행성에서만 그 담당자 활성화 |
| 접선 `requiresClearContact=1` (`mission_001`, `tq_oth_05`) | 위와 동일 | 위와 동일 |
| 명시 `clearNpcCaptainId` | 그 NPC | 목적지에서 그 NPC |
| 담당 해석 실패 | 오퍼레이터 | 활성화 없음 |

인스턴스(`tq_del_*` 등)는 생성 시 미션 설명에 `발송지 담당`/`목적지 담당`을 찍는다. 기존 CSV 제목·설명은 유지.

`__neighbor_system__`(광물 샘플 운송 등): 특정 성계가 아니라 **출발 성계가 아닌 아무 성계** 허브 착륙이면 배달 완료. 목적 담당이 모호하므로 **도착 행성 바 주인**이 완료 대화를 연다. 이미 목표가 다 채워졌으면 바 [대화]로 클리어 대사를 다시 띄운다.

## 3. 실사용에서 나온 문제 (재현 대상)

### 3-B. 외곽 항로 점검 — 도착해도 완료 안 됨 · **원인 확정**

- 미션: `sandbox_002` 「외곽 항로 점검」.
- 목표: `obj_s002_a` `buy_goods` food×3 · `obj_s002_b` `reach_system` `vega_outpost`.
- 관찰: 구매는 체크, **인벤 식량 팩 0**. 베가 착륙해도 배달 안 됨.
- 원인: 배달은 persist 체크를 안 믿고 **실화물**을 다시 본다. HUD는 예전엔 체크된 구매를 숨기고 「베가로 이동」만 보여 「이미 다 했다」로 오해.
- **이미 한 일**: HUD `· 부족` (2-1). 실패 팝업은 넣지 않음.
- **재현 시 볼 것**: 식량 팩을 산 뒤 팔거나 소모 → HUD가 `식량 팩 3개 구매 · 부족` 인지. 다시 3개 이상 보유한 채 베가 **허브 착륙** → 3개 차감 · 클리어 대사.

### 3-C. 베가에서 식량 팩 10개 구매 → 인벤 0 · 미완료 · **원인 미확정**

김클로드 관찰(코드 미수정): 베가 도착 상태에서 10개 구매 후 **인벤 0**, 퀘스트도 미완료.

코드대로면: +10 → 착륙 reconcile → 3개 소모 → **7개 남고 완료**여야 함. 0·미완료는 §3-B 만으로 설명이 안 됨.

**재현 후 확인할 후보 (아직 손대지 않음)**

| # | 후보 | 왜 의심인가 |
|---|---|---|
| 1 | `food` 가 슬롯에 안 들어감 | `addToInventorySlotsMax` 실패면 무역소가 `invShort` 를 띄워야 함. 알림 유무를 기록 |
| 2 | 산 아이템이 `food` 가 아님 | 카탈로그에 tg_* 식량 카테고리(합성 단백질 등)와 `식량 팩(food)` 이 같이 있음. 퀘스트는 **`goodId=food` 만** 센다 |
| 3 | 인벤 UI 가 `food` 를 안 보여 줌 | 슬롯에는 있는데 표시만 0 |
| 4 | 배달 루프가 전량 소모 | 아래 3-D 스냅샷 + 활성 미션 여러 건 |
| 5 | **베가에 무역소가 없음** | `planets.csv` `vega_base` **`hasTradePort=false`**. 어디서 샀는지(개발 무역소·다른 행성·조선소) 경로를 먼저 적는다 |

코드 예상과 어긋난 관찰이므로, **추측 패치 금지**. 재현 때 무역소 영수증(goodId·수량)·인벤 슬롯·활성 미션 목록을 남긴다.

### 3-D. 배달 루프 stale player 스냅샷 · **코드로 보임, 실기 미확정**

`applyReachSystemMissionObjectives` 가 루프 밖에서 받은 `player` 를 재사용하고, 화물 차감 후 `setPlayer({ ...player, inventorySlots })` 한다. 활성 배달이 2건이면 **두 번째가 첫 차감 전 인벤으로 덮어쓸** 수 있다.

- 다음 패치 후보: 루프마다 `usePlayerStore.getState().player` 를 다시 읽기.
- §3-C(10개→0)와 겹칠 수 있어, 재현 때 활성 미션이 `sandbox_002` 만인지 `mission_003`(food×10) 등도 켜져 있는지 본다.

### 3-E. 기타 알려진 잔여 (급하지 않음)

| 항목 | 메모 |
|---|---|
| `system_arrival` 전용 목표 | 캐퍼빌리티 공백. 콘텐츠 요청 전까지 분기 추가 금지 |
| `completeObjective` 「클리어씬 없으면 즉시 완료」 | `mission_clear_default` 가 있어 **죽은 코드**. 정리만 여유 시 |
| `__neighbor_system__` 폴백 | 이웃 해석 실패 시 출발 성계가 되면, 수락 행성에서 즉시 배달될 수 있음 |
| `buy_goods` 잔여 인벤 | 예전에 산 `food` 가 있으면 구매 목표가 바로 체크됨. 테스터가 헷갈리기 쉬움 |
| `deliver_cargo` 타입 | CSV 0건. 미구현과 일치. 결함 아님 |
| 튜토리얼 `mission_003` | 솔라(`solar_station`)에서 food×10 → `minerva` 배달. 식량 팩은 early 존 **아이템** 탭 |

## 4. 수정 예정안 (단계별 · 한 번에 하나)

대표님 재현·지시 후에만 착수. 순서를 건너뛰지 않는다.

### 1단계 — HUD 화물 부족 · **적용됨**

§3-B (a). 배달 재검증 유지. HUD만 부족을 드러냄. 본 문서 §2-1.

### 2단계 — §3-C 경로 확정 (다음 · 코드는 원인 확정 후)

1. 재현 체크리스트(§6)로 goodId·수량·행성·무역소 유무를 남긴다.
2. 원인 1개가 정해지면 **그 축만** 패치한다. 예:
   - 카탈로그/표시: `food` 와 tg_* 혼동 → 퀘스트 SKU 강조 또는 구매 탭 기본값.
   - 슬롯 미적재: `addToInventorySlotsMax` / 아이템 정의.
   - 베가 무무역소: 시설 게이트와 「어디서 샀는가」 불일치 해소. **기존 `hasTradePort=false` 는 확정값 — 바꾸려면 대표님 재확인**.
3. 추측으로 배달 소모량을 바꾸지 않는다.

### 3단계 — stale player 스냅샷

`applyReachSystemMissionObjectives` 루프에서 최신 `player` 를 읽고, 차감 결과를 다음 미션에 넘긴다. 단위 테스트: 동일 착륙에서 food 배달 2건.

### 4단계 — 고도화 (버그 재현이 안정된 뒤)

| 우선 | 안 | 메모 |
|---|---|---|
| A | 화물 부족 시 `buy_goods` persist 를 다시 false | HUD보다 강한 신호. 배달 직후 클리어 대기와 충돌하지 않게 게이트 필요 |
| B | 성계 도착 전용 목표 플래그 | 대표님이 지도-only 퀘스트를 **명시**할 때만 |
| C | `__neighbor_system__` 폴백을 출발 성계로 두지 않기 | 잘못된 즉시 배달 방지 |
| D | 죽은 코드 제거 | 클리어씬 없는 즉시 완료 분기 |
| E | 퀘스트 구매 탭 | 활성 `buy_goods` SKU 가 있으면 아이템 탭으로 안내 |
| F | HANDOFF P2 | `talk_npc` DSL, 궤도 `defeat_enemy` quantity, E2E 목록 — 기존 `MISSION_SYSTEM_HANDOFF.md` |
