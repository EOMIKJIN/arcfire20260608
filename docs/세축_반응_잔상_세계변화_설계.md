## 0. 한 줄

멀티플레이 체감의 정본은 장치 목록이 아니다.  
**같은 상대가 나를 알고(반응), 다시 만났을 때 그 함선이 그때의 함선이며(잔상), 떠나 있는 동안 세계가 1~2개 달라져 있다(세계 변화).**  
이 세 문장이 플레이어에게 성립하면 궤도·대화·배치가 이미 있는 자리에서 충분하다. 광장·100인 바·전 함장 HAL·실시간 제국 흥망은 넣지 않는다.

## 1. 왜 세 축인가

일반 SLG에서 사람이 빠지면 남는 빈자리는 「정보 NPC」가 아니라 **내가 한 일이 세계에 남았다는 감각**이다.  
8종 장치는 그 감각의 *출구 후보*일 뿐이고, 출구를 늘리면 기억·인과·변화는 오히려 희석된다.

| 축 | 플레이어가 입으로 말할 문장 | 실패 문장 (지금 구멍) |
|----|------------------------------|------------------------|
| **반응** | 「이 함장이 내가 한 일을 안다」 | 통신요청마다 첫 인사만 반복 (`skipSeenCheck: true` + `triggerRepeat=repeat`) |
| **잔상** | 「저 함이 그때 그 함이다」 | 슬롯·해시로만 보이면 다른 배처럼 느껴짐. 행성  Hop 후 동일 `captainId`를 말로 확인하지 않음 |
| **세계 변화** | 「내가 없을 때도 세계가 움직였다」 | 배치·점유·공지는 이미 돌아가지만, **내가 떠난 뒤의 1~2개 차이**로 모아 주지 않음 |

세 축은 서로 다른 시스템이 아니다. **한 함장 id가 시간과 장소를 가로질러 같은 레코드를 가리키는 일**이다.

```text
통신요청(반응 기록)
    │
    ├─ 같은 행성 재통신 → 반응 (다른 대사·토큰)
    ├─ 다른 행성에서 재조우 → 잔상 (지난 행성 이름)
    └─ 착륙 시 이전 방문 스냅과 비교 → 세계 변화 (점유·명단·공지 중 1~2)
```

NL 입(아크코어·오퍼레이터)은 이미 `rollingSummary`·팩트로 **반응**을 일부 갖고 있다.  
본 문서의 1순위 구멍은 **CSV NPC 궤도 통신**이다. 입은 4단계에서 그 스칼라를 한 줄만 인용한다.

## 4. 축 정의 — 합격 / 불합격

### 4-A. 반응

**입력**: 동일 `captainId`에 대한 두 번째 이후 `requestNearbyOrbitComm` 수락.  
**출력**: 첫 통신과 **다른 대사 또는 다른 토큰**(지난 행성·횟수).  
**불합격**: 같은 씬 같은 문장. LLM으로 NPC 대사를 생성. 메신저 오픈.

거부(적대·미식별·대화 비활성)는 **범용 팝업 유지**. 거부도 이력에는 남긴다(다음 수락 때 「그때는 거절했다」를 쓸 수 있게). 거부 팝업 문구 자체는 기존 키를 유지한다.

### 4-B. 잔상

**입력**: 함장 A를 행성 P1에서 통신(또는 궤도에 봄)한 뒤, 배정 epoch가 바뀌어 행성 P2 INFO에 A가 있음.  
**출력**: 통신 연결 문장 또는 1차 대사 토큰에 P1이 보임. 정체 키는 `captainId` (없으면 `linkedCapitalShipId`).  
**불합격**: `slotIndex`를 persist. 닉네임 재롤. 클랜 접두 복구. 허브 가시 마크.

### 4-C. 세계 변화

**입력**: 행성 P를 떠났다가(다른 행성 착륙 또는 벽시계 배치 완료 후) P에 재착륙.  
**출력**: 점유 시그 · 궤도 명단 · 보드 head 중 **달라진 것 최대 2개**가 이미 있는 면(보드 / inbound 이유 / 보유 플레이트) 중 **하나**에 나타남.  
**불합격**: 착륙마다 새 모달. 전 은하 뉴스 덤프. 배치 패스 신설. 틱에서 점유 재계산.

## 5. 데이터 계약 (코드에 그대로 옮김)

플레이어 인터랙티브 진행이다. **`player.flags`에 넣지 않는다.**  
신규 스토어 + `purgeLocalAccountData` 연동. ArcCore 월드 축이 아님(계정 초기화 시 리셋).

### 5-1. 스토어

| 항목 | 값 |
|------|-----|
| 모듈 | `src/store/orbitPresenceMemoryStore.ts` |
| 순수 헬퍼 | `src/game/planetHub/orbitPresenceMemory.ts` (RN/스토어 import 최소화, 테스트 용이) |
| AsyncStorage | `arcfire_orbit_presence_memory_v1` |
| persist | **1.5s 코얼레스** (`createFactionVaultStore` 패턴). 통신 직후 메모리는 즉시 정확 |
| hydrate | 허브 안착·통신 직전 lazy 1회. 타이틀 게이트 금지 |
| purge | `src/account/localAccountReset.ts` — `resetOrbitPresenceMemory()` |
| 생성 | 빈 상태로 자연 시드. `bootstrapAccountData` 특수 시드 없음 |

### 5-2. 스키마 (상한 고정)

```ts
export type OrbitCommOutcome =
  | 'accept'
  | 'refuse_hostile'
  | 'refuse_unidentified'
  | 'refuse_talk_disabled';

export type OrbitCommEvent = {
  atMs: number;
  planetId: string;
  outcome: OrbitCommOutcome;
  sceneId: string;
};

export type CaptainPresenceMemory = {
  captainId: string;
  lastPlanetId: string;
  lastSeenAtMs: number;
  lastOutcome: OrbitCommOutcome | 'seen_orbit';
  commCount: number; // accept 횟수만
  refuseCount: number;
  events: OrbitCommEvent[]; // 최신 앞, 최대 4
};

export type PlanetVisitSnapshot = {
  planetId: string;
  visitedAtMs: number;
  holdSig: string; // `${occupierClanId}|${deedOwnerClanId??''}|${kind}|${neutralizedAt??0}`
  captainIds: string[]; // 표시 예산 적용 후, 정렬, 최대 8
  boardHeadId: string; // notices[0]?.id ?? ''
};

export type OrbitPresenceMemoryPayload = {
  schemaVersion: 1;
  updatedAtMs: number;
  captains: CaptainPresenceMemory[]; // 최대 64, lastSeenAtMs LRU
  visits: PlanetVisitSnapshot[];     // 행성 키 유일, 최대 24, 오래된 visitedAtMs 축출
};
```

캡 상수는 스키마 필드가 아니다. `schemaVersion` 1 페이로드에 항목이 24 미만이어도 유효하다.

| 캡 | 이유 |
|----|------|
| 함장 64 | 코어 대화 가능 함장 ≪ 전체 CSV. 무한 `acknowledgedHubDialogKeys` 패턴 금지 |
| 이벤트 4 | 대사 분기는 first / revisit / refused-then-accept 정도면 충분 |
| 방문 24 | v1.0의 16은 실측이 아니라 PSS 보수값. 코어 루프 21 + synth 여유 3. **전수 보관·소유 핀은 하지 않음** (§5-5) |
| 명단 8 | 렌더 캡과 동일. 논리 전수 저장 금지 |

직렬화는 payload 전체 1회. 이벤트마다 배열 rebuild 금지 — **해당 captain 슬롯 in-place**.

### 5-3. 쓰기 시점 (이 네 곳만)

| # | 시점 | 함수 | 빈도 |
|---|------|------|------|
| W1 | 통신 판정 직후 | `recordOrbitComm(captainId, planetId, outcome, sceneId)` | 플레이어 탭 1 |
| W2 | 수락 대화 종료(선택) | completion `record_orbit_comm` — W1과 중복이면 no-op | 대화 1 |
| W3 | 행성 착륙 1회 | `recordPlanetVisitSnapshot(planetId)` — digest 계산 **후** 스냅 갱신 | `lastPlanetLandedId`와 동일 가드 |
| W4 | INFO에 함장이 보임 (선택, Phase 3) | `touchCaptainSeen(captainId, planetId)` — `seen_orbit`, commCount 불변 | 착륙 시 명단 루프 1회, 행당 할당 없이 기존 배열 |

**금지**: `onWallTick` · 스캔 틱 · 궤도 rAF · 거리 정렬 5s · 통신 버튼 hover.

W1을 정본으로 한다. W2는 대화 중 이탈(스테이지 leave) 시 수락 미완료를 걸러야 할 때만 쓴다.  
현행 `requestNearbyOrbitComm`은 수락 팝업 확인 전에 대화를 열지 않으므로, **팝업 확인 시 W1 accept** / **거부 판정 즉시 W1 refuse**.

### 5-4. 읽기 (O(1))

```ts
getCaptainPresenceMemory(captainId): CaptainPresenceMemory | undefined
resolveOrbitCommSceneVariant(baseSceneId, memory): { sceneId: string; visitCount: number }
computeWorldChangeDigest(prev: PlanetVisitSnapshot | undefined, next: Omit<PlanetVisitSnapshot,'visitedAtMs'>): WorldChangeItem[]
```

맵은 hydrate 시 1회 구축, persist 직전 배열만 저장.

### 5-5. 방문 캡 24 — 김팀장 잠금 (v1.1)

김클로드 질문: 16이면 넓게 도는 플레이어의 세계 변화가 조용히 꺼진다.

**판정**: 16은 평균 재방문 실측이 아니라 보수 상한이었다. 캡을 **24**로 올린다.

| 잠금 | 내용 |
|------|------|
| 숫자 | `VISITS_MAX = 24` — 코어 21 + 최근 synth 3 |
| 축출 | `visitedAtMs` 가장 오래된 행성 1곳. 소유·거점 **핀 금지**(synth 보유가 늘면 캡이 사실상 무한) |
| 축출 후 재착륙 | `prev` 없음 = 첫 방문. digest 없음. **허용된 트레이드오프** |
| 체감 범위 | 세계 변화는 「지금 맴도는 행성」용이다. 전 은하 백과가 아니다 |
| 올리지 않는 이유 | 32·전 코어 고정 슬롯·deed 핀은 Phase 1~4 밖. 상수만 바꾸면 되므로 실기 후 대표님 지시로만 |

스냅 24 × (id+시그+함장 8)는 persist 한 덩어리로도 수 KB. 틱 할당 없음.

### 5-6. `complete_talk_npc`와 분리

`{ type: 'complete_talk_npc'; captainId; planetId }`는 `applyTalkNpcMissionObjectives`만 호출한다.  
세축 기억에 쓰지 않는다. **합치거나 재사용하지 말 것.**

## 6. 축 A — 반응 (구현 설계)

### 6-1. 씬 변이

기존 `resolveAcceptSceneId` 결과는 **베이스 씬**으로 남긴다.

```text
base = mainStageTalkSceneId || npc_dialog_{id without npc_cpt_} || npc_dialog_arc_transport_temp
revisitId = `${base}__revisit`

if memory.commCount >= 1 && getIngameDialogSceneById(revisitId)
  → sceneId = revisitId
else
  → sceneId = base
```

- `__revisit`이 없으면 **베이스 씬 + 컨텍스트 토큰만**. 기존 대사는 토큰이 없으면 그대로(하위 호환).
- **기존 `npc_dialog_*` 행의 문구를 수정하지 않는다.** 재방문 대사는 **행 추가**만 (Fable, 대표님 승인 후).
- `triggerRepeat`는 재방문 씬도 `repeat`. `seenStorySceneIds`에 의존하지 않음.
- 궤도 통신은 계속 `skipSeenCheck: true` (once 메인스토리 씬을 통신이 삼키지 않게).

### 6-2. 컨텍스트 토큰 (기존 씬이 무시해도 됨)

`IngameDialogTextContext`에 **선택 필드만 추가**:

| 필드 | 출처 | 기존 씬 |
|------|------|---------|
| `npcCaptainId` / `npcName` / `npcNameEn` | 이미 있음 | 유지 |
| `orbitCommVisitCount` | `commCount` (이번 수락 전) | 미사용이면 무시 |
| `orbitCommLastPlanetName` | `lastPlanetId` → 행성 표시명 | 미사용이면 무시 |
| `orbitCommLastPlanetNameEn` | 동 | 동 |
| `orbitCommHadRefuse` | `refuseCount > 0 && commCount === 0` | 첫 수락·이전 거부 |

토큰 문법은 기존 인게임 다이얼로그 치환과 동일하게 맞춘다(구현 시 `ingameDialog` 치환기 1곳만 확장).  
CSV 본문에 `{orbitCommLastPlanetName}`을 넣은 **신규 행**만 효과를 본다.

### 6-3. 완료 액션

```ts
| { type: 'record_orbit_comm'; captainId: string; planetId: string; outcome: OrbitCommOutcome; sceneId: string }
```

`ingameDialogCompletion.ts`에서 스토어 호출.  
`requestNearbyOrbitComm`의 거부/수락 팝업 경로가 W1을 이미 호출하면 액션은 idempotent.

### 6-4. 분기 표 (대사 의도 — 카피 잠금은 Fable/대표님)

| 조건 | 씬 | 의도 (구현 힌트, 문구 미확정) |
|------|-----|-------------------------------|
| commCount=0, refuseCount=0 | base | 현행 첫 통신 |
| commCount=0, refuseCount≥1 | base 또는 토큰 | 거절 이력이 있는 첫 수락 |
| commCount≥1, lastPlanetId===now | `__revisit` | 같은 궤도에서 다시 |
| commCount≥1, lastPlanetId≠now | **같은** `__revisit` + `{orbitCommLastPlanetName}` | 잔상 문장은 팝업이 담당 (§7-2). 대사는 한 골격 |
| 수송 fill | `npc_dialog_arc_transport_temp` + 동일 규칙 | 수송 전용 `__revisit` 1행이면 충분 |

### 6-4-A. 재방문 씬 1안 잠금 (v1.1 · 김클로드 3-1)

김클로드 질문: 팝업은 키 2개(`connectedRevisit` / `connectedRevisitFrom`)인데 대사는 `__revisit` 하나 + 토큰 — 의도인가.

**판정: 의도적 비대칭. Phase 2 기본은 씬 1개다.**

| 면 | 분기 | 이유 |
|----|------|------|
| 연결 팝업 | 키 2개 | 잔상은 **한 줄**로 「여기 다시」/「그때 그 행성」을 보여 주면 끝 |
| 1차 대사 | `__revisit` 1행 + 토큰 | 반응은 「이전에 말했다」. 장소 차이는 토큰이 있으면 말하고, 없으면 같은 재회 문장 |

`__revisit_from` 같은 **두 번째 씬 id는 Phase 2 할당량에 넣지 않는다.**  
Fable 카피가 토큰만으로 부자연하면 Phase 2 검수에서 **추가 행만** 검토한다. 그때도 기존 `__revisit` 문구는 덮어쓰지 않는다.

리졸버(구현 힌트, Phase 2):

```text
if commCount>=1 && lastPlanetId≠now && exists(`${base}__revisit_from`)
  → 그 씬   // 후속 여지. 기본 CSV에는 없음
else if commCount>=1 && exists(`${base}__revisit`)
  → __revisit
else
  → base
```

**Phase 1 코드만으로도** `__revisit` 없이 토큰을 넘기면 합격의 절반(시스템이 기억함)은 된다.  
체감 합격(다른 문장)은 Phase 2 CSV 추가.

### 6-5. 하지 않는 반응

- NPC → `presentArcCoreBackchannel`
- 함장별 `rollingSummary`
- 관계 점수·호감도 게이지
- 대화로 퀘스트 생성(입 write 금지와 동일)
- `mainStageTalkEnabled` 런타임 토글 (CSV 정본 유지)

## 8. 축 C — 세계 변화 (구현 설계)

### 8-1. digest 후보 (이미 있는 값만)

`WorldChangeItem` 최대 2. 우선순위 고정:

| 순위 | kind | 비교 | 플레이어 면 |
|------|------|------|-------------|
| 1 | `hold` | `holdSig` 변경 (점유·**증서**·kind·중립화) | 허브 점유 플레이트 + (선택) inbound |
| 2 | `roster` | `captainIds` 대칭차 중, **기억에 있는** id가 들어오거나 빠짐 | 통신 잔상과 연결 — 「그때 그 함」이 없/있음 |
| 3 | `board` | `boardHeadId` 변경이고 새 head tag ∈ `ops` \| `diplomacy` \| `arccore` | 바 보드 기존 행 — **추가 푸시 없음** |

경제 일괄(`economyBulk`)·성운(`nebulaShift`)은 보드에 이미 있다. digest 1·2를 채운 뒤에만 3순위로 본다.  
전 행성 코어 5지표 덤프 금지.

### 8-2. 착륙 순서 (1회)

```text
허브 세션 진입 1회 (STAGE 1 마운트 / replace 착륙)
  → prev = visits[planetId]
  → next = snapshot(now)   // holdSig(점유+증서) + budgeted captainIds + board head
  → items = computeWorldChangeDigest(prev, next).slice(0, 2)
  → 면 1개에만 반영 (§8-3)
  → recordPlanetVisitSnapshot(next)   // 이번 방문이 다음의 prev
```

첫 방문(`prev` 없음)은 digest 없음. 스냅만 저장. 캡 축출 후 재착륙도 동일(§5-5).

**W3 가드 (v1.1)**: `ingameDialogStore.lastPlanetLandedId`를 **그대로 공유하지 않는다.**  
그 플래그는 착륙 대사 1회용이고, 허브 이탈 시 `resetIngameDialogPlanetLandedDedupe`(`planet.tsx`)로 비운다.  
세축 스냅은 **허브 세션 진입 1회**(STAGE 1 마운트 / `replace` 착륙)에서만 찍는다. 같은 허브 체류 중 리렌더는 금지.  
A → 은하지도 → A 는 세션이 갈리므로 새 방문이다(대사 가드도 리셋됨). 같은 행성 재진입이어도 `holdSig` 등이 같으면 digest는 빈 배열.

`boardHeadId`만 비교한다. 보드 중간 행 변경은 보지 않는다(착륙 시 공지 전량 스캔 금지). 헤드가 아닌 변화는 바 보드 자체가 보여 준다.

### 8-3. 노출 면 — 하나만

착륙마다 새 Alert/모달 **금지**.

```text
if inbound 가 이번 허브 체류에 이미 예약됨
  → why id `world` 후보. spy/combat/story보다 낮고 observe/idle보다 높음
  → 텍스트는 items[0] 한 줄 (템플릿, LLM 아님)
else if items에 hold|board
  → 추가 UI 없음 (플레이트·보드가 이미 보임)
else if items에 roster only
  → inbound가 없으면 침묵. INFO 통신 연결 문장이 잔상 축에서 처리
```

`world` why 템플릿 (신규, 기존 why 문구 변경 금지):

| id | ko 골격 |
|----|---------|
| `world` | `{fact}` — 관측만. 질문 1개까지 |

`{fact}` 예 (i18n 파라미터, 구현 시 키 추가):

- hold: `{planet} 점유가 {prev}에서 {next}로 바뀌었다.`
- roster_gone: `{name} 함선이 이 궤도에 없다.`
- roster_back: `{name} 함선이 이 궤도에 다시 있다.`

입은 **관측 스칼라만**. 점유를 바꾸거나 함장을 호출하지 않음 (입≠몸).

### 8-4. 배치와의 계약

세계 변화의 **생산자**는 기존 배치·영토·반란 패스다.  
본 문서는 **소비자**만 추가한다.

- `runArcCoreDailyOpsBatch`에 패스 추가 금지
- `ArcNewsBoardSubCore.onBoot`에 전수 루프 금지
- `price_elasticity` 불변
- 점유 write는 기존 territorial/rebellion/플레이어 증서만

### 8-5. 4대 제국 흥망 — 리맵

투자서 「리더 사망 시 제국 멸망」은 **구현하지 않는다.**  
체감 대체:

- 접전 `news.territorialHold`
- 반란 전복·내전 공지
- 일 1회 PGP 브리핑
- 허브 플레이트 `hubBg.owned`

국호는 스텔리움 / 머큐리움 / 크림슨 / 아우렐리움만.

## 13. 테스트 계약

순수 함수 우선 (스토어/RN 없이):

1. LRU 65번째 함장 삽입 → 가장 오래된 `lastSeenAtMs` 축출  
2. 동일 통신 2회 → `commCount==2`, `events.length≤4`  
3. 거부 후 수락 → `refuseCount≥1`, 첫 accept 플래그  
4. digest: hold 변경 + roster + board → 상위 2만 (hold, roster)  
5. digest: prev 없음 → 빈 배열  
6. 씬 변이: commCount=0 → base; ≥1 + revisit 존재 → `__revisit`; 없으면 base  
7. 기함 행 → 기록 함수 no-op  
8. purge 후 hydrate → 빈 payload  
9. 방문 25번째 다른 행성 → 가장 오래된 `visitedAtMs` 축출. 축출된 행성 재착륙 digest 빈 배열  
10. 동일 통신에 W1 후 W2 → `commCount` +1만 (idempotent)  
11. 씬 변이: `lastPlanetId≠now` 이고 `__revisit_from` 없음 → `__revisit`(있으면) 또는 base. `__revisit_from`이 있을 때만 그 씬  

정책 테스트 기존 파일에 「기억 있어도 적대+talk off면 거부」 회귀 1개.
