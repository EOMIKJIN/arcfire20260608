## 0. 의도 한 줄

지금은 **무역 수수료 + convoy 마진이 금고에 쌓이고**, 지출은 **행성 800cr 유지비 + (일부) 방위위성 + 회계 소각**에 가깝다.  
목표 구조는 **국가 재정(중앙은행)** 이 수입을 받고, **군사·함선·함장·R&D** 를 일 1회 비용으로 빼며, 구현이 어려운 항목은 CSV 프록시로 처리하는 것이다.

```text
수입(수수료·convoy 몫·무역)
   → 금고(5축)
   → 일 1회 지출(실물 + 프록시)
   → 효과(시설·전력 스냅·학습 KPI)
   → 다음 날 수입에 약하게만 피드백 (고빈도 가격 금지)
```

## 1. 현행 전수 — 무엇이 돌아가고, 무엇이 빈 껍데기인가

### 1-1. 유지해야 할 계약 (건드리지 말 것)

| 계약 | 상태 |
|------|------|
| 일 1회 `runArcCoreDailyOpsBatch` · 12:00 KST | **유지** |
| `price_elasticity=0` | **유지** |
| 경제 `onSnapshot` 없음 · 금고 Firestore 금지 | **유지** |
| 계정 purge ≠ 월드 금고 1~4 | **유지** |
| 수수료 10% · 유지비 800 · 시드 기존값 | **기존값 — 무단 변경 금지** |

### 1-2. 자금 흐름 (2026-08-25 코드 정본)

```text
convoy 매입     → 수송선단 금고 출금
convoy 하역     → 수송선단 입금(마진+운송비 표시) → 운송비 출금 → 순마진 30% 아크코어 (CSV)
무역 수수료 5%  → BLUE / 중립 / 독립 / RED(아크코어=중앙은행)
행성 유지비     → 점유 금고 또는 player.credits (800 + 방위위성 dailyUpkeep)
중앙은행 패스   → 시드 초과분 34/33/33 배분
  · 함대·군사 34%  → vault trySpend (회계 소각) · 전함/함장/전투 없음
  · 행성개방 33%   → vault trySpend (회계 소각) · 성계 개방 없음
  · 행성개발 33%   → 예산 풀 적립(금고 선소각 없음) → 60s tick이 실제 건설 시 vault 차감
```

5축 라우팅은 **코드에 있다** (`resolveFactionVault.ts`). FABRIC §9·§11의 「중립→아크코어 폴백」은 **구문서**.

### 1-3. 중앙은행의 실제 역할

| 역할 | 구현 | 판정 |
|------|------|------|
| RED 금고 = 중앙은행 동일 인스턴스 | `useArcCoreVaultStore` | **의도대로** |
| 발행(mint) / 소각(burn) API | `arcCoreCentralBank.ts` | 운영툴용 · 일상 배치에서 mint 없음 |
| 시드 초과분 지출 패스 | `runArcCoreCentralBankExpenditurePass` | **켜짐** (`expenditure_pass_enabled=true`) |
| 함대·군사 지출 | `spendArcCoreCentralBankAccounting` — 주석: **게임 자원 차감 없음** | **빈 소각** |
| 행성개방 지출 | 동일 회계 소각 | **빈 소각** |
| 행성개발 | 예산 게이트 + 건설 시 vault `trySpend` | **유일하게 실물** |

즉 중앙은행은 지금 **「RED 금고에서 돈을 태우거나, 행성개발 예산을 열어 주는 장치」** 이지, 군사·함선·함장을 운용하는 재정부가 아니다.

### 1-4. 아크코어 자산·수송선단은 일방 적립인가

**예. 구조적으로 적립이 이기는 설계다.**

| 증거 | 내용 |
|------|------|
| 수송 순유지 | 순마진의 **70%** 가 선단 금고에 남음 (`convoy_net_margin_arc_core_share_pct=30`). 선단→RED **자동 이전 없음**(의도) |
| 손실 경로 | 플래너가 손실 루트 **제외** → 하역은 대체로 흑자 |
| 운송비 | 입금 후 같은 금액을 다시 출금 — **표시 분리**. 외부로 나가지 않음 |
| 선단 고정비 | 선박 감가·승무원·정비·보험 **0** |
| 실기(08-05) | 수송 **94,251,851** / 시드 500,000 · RED **8,997,612** / 시드 100,000 |
| 헤드리스 3h | 수송 ~52만 · RED ~25만 — **시뮬 ≠ 실기**. 장기 세이브가 적립을 보여 줌 |

RED도 수수료·convoy **30%** 로 들어오고, 나가는 실물은 유지비+방위위성+가끔 행성개발이다.  
시드 초과분의 67%는 **소각**이라 잔액 폭주를 일부 막지만, **군사력으로 바뀌지 않는다.**

| 축 | 하는 일 | 안 하는 일 |

## 3. 목표 구조 — 프록시 국가 재정 (1안)

전 함선·전 함장을 시뮬하지 않는다. **일 1회**, 이미 있는 관측값으로 비용을 찍는다.

### 3-1. 항등식

```text
일일_순재정 = 수수료유입 + convoy_arc몫 + (선택)선단배당
            − 점유유지비 − 시설유지비
            − 군사프록시 − 함선운용프록시 − 함장프록시 − RD프록시
            − 행성개발실투자
```

잔액이 시드를 크게 넘으면 중앙은행이 **잔여를 프록시 항목으로 배분** (지금처럼 통소각하지 않음).

### 3-2. 프록시 표 (신규 CSV · 기존 800/수수료율 **손대지 않음**)

| 항목 | 계산(초안) | 출금 금고 | 게임 효과 1차 |
|------|------------|-----------|---------------|
| **군사운용** | `k_mil × Σ(점유행성 D) × PGP_unit` 또는 영토전 작전 수 × 정액 | RED / BLUE / 중립 각자 | 지출 원장 + (선택) 미납 시 D −nudge |
| **전함운용** | `k_ship × 궤도트래픽척수(캡5)` + 조선소 레벨 정액 | 선단(물류) / RED(전투 프록시) | 선단 잔액 억제 |
| **함장양성** | `k_cap × (총사령관+talkEnabled 함장 수)` | 점유 금고 | 원장만 → 이후 바/스킬 슬롯 |
| **전함 R&D** | `k_rd × 연구소레벨합` | RED | 원장만 → 이후 함선 곡선 슬롯 |
| **행성개발** | **현행 실건설비 유지** | RED vault + 예산 게이트 | 시설 실물 |
| **미모델 잔여** | 위 합 후 시드 초과분 × cap | RED | 명시적 residual burn (빈 함대 소각 대체) |

정산이 어려운 수익(약탈·보험·감가)은 **넣지 않고** 위 계수로 흡수한다.

### 3-3. 선단 적립 닫기 (기존값 승인 후 1안만)

| 레버 | 1안 | 금지 |
|------|-----|------|
| 선단 일 운용비 | 순마진 유보의 **일부 %** 또는 척당 정액 | 수수료율·일 cap 무단 변경 |
| RED 배당 | 일 1회 선단→RED **소액 %** (대표님 승인 전 0) | 대규모 자동 이체 신설 |
| 손실 루트 | 플래너 제외 **유지** | 적자 수송 강요 |

### 3-4. 학습의 자리

학습·전력평가는 가격을 흔들지 않는다. **계수 힌트만** 일 1회.  
이미 있는 `runPlanetFiscalBalanceClosedLoopPass`는 **fee/upkeep 스트릭**으로만 `trade_route`를 미세 인하한다(탄력 0 계약의 일 1회 overlay). P1 vault 지출은 이 입력에 **직접 안 탐**. P2 시설 유지비를 올리면 deficit/warn이 늘 수 있으므로 **그때** 폐회로와 결합을 재확인한다.

- 선단/RED 잔액이 시드 대비 N배 → `k_ship`/`k_mil` 소폭 상향 (캡)
- 전력 평가 vs 영토전 성과 괴리 → 원장 플래그만 (전투 밸런스 즉시 변경 금지)
