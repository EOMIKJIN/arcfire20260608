## 1. 기획 의도 (정본 · v0.2 수정)

### 1-1. 핵심 결정 (대표님)

1. 제약·리스크가 크므로 **중요 스토리 관련 인물만** 사망 지정한다.  
2. **일반 트래픽에 참여하는 함장**의 사망 처리는 **보류**한다.  
3. **웨이브 전투**는 애매하므로 **당장 사망 처리하지 않는다**(불사 취급).  
4. **메인스토리 주요 함장**이  
   - 스토리상 지정 전투에서 격침되거나  
   - 스토리 연출상 사망이 확정되면  
   → **영구 사망** · **이후 다른 전투(허브 레이드·미션·트래픽 전투 시드 등)에 참여하지 못한다.**

### 1-2. 범위 밖 (명시적 보류)

| 축 | 상태 |
|----|------|
| `arcOrbitPresenceFill` 수송 풀 | 사망 보류 |
| 일반 `orbit_table_patrol` / 체류 | 사망 보류 |
| 총사령관·점유 플립 사망 | 사망 보류 |
| 웨이브 범용 침입자·공유 `npc_cpt_ai_robot_default` | **불사** |
| 스파이 expelled | 별축 유지(사망과 혼동 금지) |
| 샌드박스 수락 의뢰 적 함장 | 기본 보류(메인스토리 태깅 시에만 예외 가능) |

### 1-3. 왜 이 축소가 맞는지

- 일반 풀(~247)에 사망을 열면 fill·웨이브·총사령·캐시 전면 게이트가 필요 → 리스크 대비 이득 적음.  
- 메인스토리 주요 인물은 **소수·고유 id·서사 정본**이라 원장+한정 게이트로 완결 가능.  
- **함장 행이 아직 없어도** `deathClass=main_story` 계약·배정 파이프를 먼저 설계할 수 있다.

## 2. 메인스토리 함장 — 현황과 설계 전제

### 2-1. 현황 (2026-08-13)

| 항목 | 상태 |
|------|------|
| 튜토리얼 스토리 | `mission_*` 체인 존재 · `mission_combat_captains` 등 연동 |
| 메인스토리 씬 | 예: `story_dialog_story_001`(동기불명 살인사건) · 페이지에 기존 함장 id 참조 가능 |
| **메인스토리 전용 주요 함장 풀** | **미배정** — “메인스토리 사망 대상”으로 분류된 CSV 집합 없음 |
| 일반 함장 | 수송·궤도·전투·총사령 등에 **이미** 배정 |

### 2-2. 설계 전제 (배정 전에 고정할 계약)

메인스토리 주요 함장은 **일반 트래픽 풀과 분리된 정체**로 넣는다.

```text
[권장 배정 규칙 — 향후 Fable/콘텐츠]
1. 신규(또는 지정) captain id — 메인스토리 전용 태그
2. arcOrbitPresenceFill = FALSE  (수송 fill 금지)
3. 일반 epoch 순찰 풀에 넣지 않음 (또는 presence에서 main_story만 별도)
4. deathEligible = TRUE · deathClass = main_story
5. 전투 시드는 「메인스토리 전투 매핑」으로만 등장 (일반 combat seed 스캔에 안 잡히게)
6. 사망 후: 대화·전투·궤도·미션 적 슬롯 전부 비활성
```

> **기존 트래픽 함장을 나중에 메인스토리 주역으로 “겸임”시키는 방식은 비권장**  
> (사망 시 수송/궤도 구멍·의도치 않은 전투 시드). 겸임이 필요하면 **불사 스토리 NPC**로 두거나, 사망 가능 분신을 **별 id**로 둔다.

## 3. 목표 데이터 모델 (구현 전 설계만)

### 3-1. CSV (Table-First · 자격만)

| 컬럼(초안) | 값 | 의미 |
|------------|-----|------|
| `deathEligible` | bool | 영구 사망 **가능** 여부 |
| `deathClass` | `none` \| `main_story` | v0.2는 **`main_story`만 활성 클래스** · 나머지 `none` |

- 일반 트래픽·웨이브·총사령 함장: `deathEligible=false`, `deathClass=none`  
- 향후 메인스토리 주요 함장 행 추가 시: `true` + `main_story`  
- **플레이 중 사망 여부를 CSV에 쓰지 않음**

(선택) 정적 로어용 `presumedDead`는 콘텐츠 전용 · 런타임 원장과 OR.

### 3-2. 런타임 사망 원장 (플레이 결과)

선례: `arcCoreSpyExpelledStore` 형태 · **Set O(1)**

| 필드 | 용도 |
|------|------|
| `deadCaptainIds` | 재등장 금지 정본 |
| `deadAtMs` / `deathCause` | `story_combat` · `story_script` 등(감사·연출) |
| 스코프 | **계정 샌드박스 권장**(메인스토리 진행 = 계정 귀속). purge 시 리셋 |

### 3-3. 단일 게이트 (범위 축소판)

```text
isMainStoryCaptainDead(id)     — 원장에 있음
isCaptainAllowedInCombat(id)   — !dead ∧ (일반은 항상 허용)
isCaptainAllowedInStoryCast(id)— !dead
```

v0.2에서는 **전 함장 presence를 전면 개조하지 않는다.**  
게이트 의무 면:

| 면 | 의무 |
|----|------|
| 메인스토리 전투 시드 / 미션 전투 매핑 | **필수** — 사망자 제외 |
| 메인스토리 대화·씬 출연 | **필수** — 사망 시 대체 대사/미출연 |
| 일반 수송·궤도·웨이브·총사령 | **게이트 불필요**(대상이 그 풀에 안 들어오게 배정) |
| 허브 일반 combat seed 전량 스캔 | 메인스토리 함장이 여기 안 들어가게 **배정으로 차단** |

→ “전면 `isCaptainWorldActive`”는 **장기 옵션**. v0.2는 **스토리 캐스트·스토리 전투 경로만** 막으면 의도 충족.

## 4. 사망 트리거 (메인스토리만)

| 트리거 | 동작 |
|--------|------|
| **스토리 지정 전투**에서 `deathClass=main_story` 함장 격침 + 전투/씬 확정 | `markDead(id, story_combat)` |
| **스토리 스크립트** 사망(연출·분기, 전투 없음) | `markDead(id, story_script)` |
| 일반 트래픽 전투·웨이브·영토 | **사망 처리 없음** |
| 우연한 동일 id 격침(배정 실수) | 배정 규칙으로 방지 · 방어적으로 `deathEligible` 아니면 mark 무시 |

사망 후:

- 다른 메인스토리 전투 적/아군 슬롯 제외  
- 일반 전투 시드에 **애초에 포함되지 않음**(배정 계약)  
- UI: 사망 고지·도감/로그는 후속(선택)

## 7. 권장 기반 아키텍처 (축소판)

```text
[향후] npc_ai_captains 행 (메인스토리 주요)
  deathEligible=true, deathClass=main_story
  fill/일반순찰/웨이브 시드 제외
        │
        ▼
[Runtime] mainStoryCaptainDeadLedger  (계정)
        │
        ▼
스토리 전투 리졸버 · 스토리 씬 출연

일반 트래픽·웨이브·총사령
```

## 10. 총평

- 기획을 **「메인스토리 주요 함장 영구 사망」**으로 좁히면, 이전 P0 리스크(웨이브·fill·총사령·전면 스캔)를 **대부분 우회**할 수 있다.  
- 지금 함장이 없어도 **`deathClass=main_story` + 트래픽 비포함 배정 + 원장 + 스토리 경로 게이트**를 선설계하는 것이 맞다.  
- **코드·CSV는 수정하지 않았다.** S0 배정·T1 컬럼은 별도 승인 후.
