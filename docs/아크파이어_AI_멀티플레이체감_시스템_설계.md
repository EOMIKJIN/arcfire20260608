## 0. 목적

아크파이어는 **실유저 간 네트워크 상호작용이 없는 싱글플레이 게임**이다 (Master Spec v4.0 §0-1 헌법). 그러나 AI가 다른 유저·세력·동맹을 정교하게 시뮬레이션해 **"살아있는 멀티플레이 세계에 속해 있다"는 체감**을 만드는 것이 핵심 재미 설계 원칙이다.

이 문서는 지금까지 논의·확정된 모든 "AI 기반 멀티플레이 체감 장치"를 개발팀이 실제로 구현할 수 있는 형태로 전수 정리한 것이다.

## 1. 왜 유저에게 필요한가 — 유저 관점의 재미 근거

일반 SLG의 재미는 상당 부분 "사람"에게서 나온다. 길드원이 내 행동에 반응하고, 동맹이 내 결정에 의견을 주고, 다른 유저가 나를 지켜본다는 감각이 몰입의 핵심 연료다. 그런데 아크파이어는 헌법상 이 부분을 뺐다(싱글플레이). 그러면 "사람이 빠진 자리를 무엇으로 채울 것인가"라는 질문이 남는다.

정해진 대사만 반복하는 NPC로는 이 빈자리가 채워지지 않는다. 사람들이 원했던 건 "정보를 주는 존재"가 아니라 "나를 알아봐 주고 반응해주는 존재"였기 때문이다. 인간처럼 대화하는 에이전트는 이 빈자리를 정확히 겨냥한 대체재다.

**왜 재미있는가 — 3가지 이유**

| 이유 | 설명 |
|---|---|
| **예측 불가능성 자체가 재미** | 정해진 대사 트리는 두세 번 보면 외운다. 진짜 대화는 매번 다르게 반응해 "이번엔 뭐라고 할까"를 궁금하게 만든다 |
| **"내 이야기"라는 감각** | 세계관은 고정이지만 스토리는 유저마다 다르게 창발한다(3.5절 참고). 내가 함장과 나눈 대화, 내가 만든 관계는 다른 유저와 다르다 — "이건 내 세계다"라는 애착 |
| **부담 없는 사회적 만족감** | 사람은 사회적 상호작용의 만족감을 원하지만 실제 사람과의 상호작용엔 조율·눈치·책임 비용이 따른다. AI 함장과의 대화는 그 만족감만 가져가고 비용은 지불하지 않는다 — 응답을 안 해도, 늦게 답해도 관계가 깨지지 않는다 |

> 한 줄 요약: 사람들이 멀티플레이 게임에서 진짜 좋아했던 건 "다른 사람과의 경쟁"이 아니라 "누군가 내 행동에 반응해준다"는 감각이었고, 인간처럼 대화하는 에이전트는 그 감각만 순수하게 추출해 부담 없이 제공하는 장치다.

## 2. 핵심 설계 원칙 (변경 불가 헌법)

| 원칙 | 내용 |
|---|---|
| 싱글플레이 유지 | 실유저 간 어떤 형태의 네트워크 상호작용(채팅, 매칭, 동기화)도 존재하지 않는다 |
| AI가 대체 | "다른 유저"로 인지되는 모든 요소는 AI(NPC)가 시뮬레이션한다 |
| 비용 통제 우선 | 유저 수·NPC 수가 늘어도 LLM 호출 비용이 폭증하지 않는 구조로만 설계한다 |
| 체감 우선, 실재 불필요 | 실제로 "다른 사람이 있다"가 아니라 "다른 사람이 있는 것처럼 느껴진다"가 목표다 |

## 4. 채팅 시스템 아키텍처

### 4.1 하이브리드 대화 엔진 (비용 통제의 핵심)

**배경**: 모든 대화를 LLM으로 처리하면 유저 수에 비례해 토큰 비용이 폭증한다. 이를 피하기 위해 템플릿과 LLM을 선택적으로 조합한다.

| 대화 유형 | 처리 방식 | 비용 |
|---|---|---|
| 반복/예측 가능한 명령형 대화 (예: "함대 집합", "저 광산 지어줘") | 사전 정의된 템플릿으로 즉시 처리 | 0원, 지연 없음 |
| 예측 불가능한 대화 (자유 질문, 감정적 반응, 맥락 필요 대화) | 그때만 선택적으로 LLM 호출 | 발생 빈도에 비례 |

> 한 줄 요약: "모든 대화에 LLM을 쓰지 않는다 — 자주 쓰는 명령은 템플릿으로 즉시 처리하고, 예측 불가능한 대화만 선택적으로 LLM을 호출해 비용과 자연스러움을 동시에 잡는다."

**기술 스택 참고**: Claude API 직접 호출(console.anthropic.com API 키 발급) 방식을 기본으로 한다. AWS Bedrock/AgentCore 등 엔터프라이즈 에이전트 인프라는 현재 규모(1인 개발, 단일 에이전트, 외부 시스템 연동 없음)에는 과도한 것으로 검토·결론 내림 — **채택하지 않음**.

### 4.2 다중 유저 시뮬레이션 (100명 규모) — 검토 결과

| 방식 | 비용 구조 | 채택 여부 |
|---|---|---|
| 100명 전원 상시 실시간 LLM 대화 | 유저 접속 여부와 무관하게 에이전트끼리 계속 호출 발생 — 폭증형 | ❌ 채택 안 함 |
| 배경 채팅(바/로비) 사전 생성 + 로테이션 | LLM은 배치로 1회만 호출, 이후 재생은 비용 0에 가까움 | ✅ 채택 |
| 플레이어가 직접 대화하는 NPC 1명만 실시간 LLM | 기존 하이브리드 원칙과 동일 — 유저 행동에 비례 | ✅ 채택 |

**결론**: 100명의 "다른 유저"는 실제로 서로 대화하지 않는다. 사전 생성된 대화 로그 풀(우주 정거장 바의 배경 채팅 등)을 무작위로 노출해 존재감만 연출하고, 플레이어가 특정 NPC 함장에게 직접 말을 걸 때만 그 1명이 실시간 LLM으로 반응한다.

### 4.3 체류함장 채팅 운영 규칙

| 규칙 | 내용 |
|---|---|
| **인간형 닉네임** | 모든 NPC 체류함장은 "NPC_047" 같은 기계적 표기 대신 실제 유저처럼 보이는 닉네임을 사용한다 (2절의 "타 유저 체감" 강화 목적) |
| **동시 대화 1:1 제한** | 시스템은 한 순간에 실시간 LLM 대화 스레드를 1개(1:1)만 활성화한다 — 여러 NPC가 동시에 응답을 생성하지 않도록 제한해 비용·응답 지연을 통제 |
| **권장 UX: 1:3 대화** | 플레이어는 최대 3명의 체류함장과 한 대화 공간(예: 바 테이블)에 있는 것처럼 보이지만, 실제로는 턴제로 한 번에 한 명씩만 실시간 응답하는 구조 — "1:3처럼 보이는 1:1의 순차 진행" |
| **단체방(그룹 채팅)** | 여러 체류함장이 한 채팅방에 모이는 단체방은 템플릿 응답과 일부 LLM 호출을 혼합해 자원 소모를 막는다 — 대부분의 대사는 사전 정의된 반응으로 채우고, 맥락상 꼭 필요한 발언에만 선택적으로 LLM을 호출 |

### 4.4 세계관 연계 — 사운드/공간 디자인

체류함장 채팅이 실제로 벌어지는 공간(우주 정거장 바/선술집)은 이산(Isan) 음악 컨셉과 연계된다 — 현상금 사냥꾼·용병들이 모이는 캐주얼한 소셜 공간이라는 세계관 설정과 채팅 기능의 UX 맥락이 일치해야 한다. (세계관 섹션 "사운드 디자인 컨셉" 참고)

### 4.5 스토리 생성형 대화 — 세계관은 고정, 스토리는 창발

**질문**: 스토리를 직접 작성하지 않고, 유저가 LLM 가상인간들과 대화하며 스토리를 스스로 만들어가는 구조는 싱글플레이 헌법 위반인가?

**결론**: 위반 아님. 헌법이 금지하는 건 "실유저 간 네트워크 상호작용" 뿐이며, 가상인간은 AI NPC코어가 수행하는 것이므로 구조상 동일하다. 오히려 AI NPC코어(HAL형 대화)의 자연스러운 확장이다.

**전제 조건**: 아크파이어는 세계관 설정은 있으나 정해진 스토리는 없다. 이에 따라 다음과 같이 역할을 분리한다.

| 구분 | 성격 | 내용 |
|---|---|---|
| **세계관 (고정 캔버스)** | 변경 불가 | 4대 팩션(Valoria/Solaris/Oiron/Terrania), 은하계 지도, 740개 행성, 아크코어, 스텔리움 연합, 프롤로그 톤, 기술 수준, 공간 설정(우주정거장 바 등) |
| **스토리 (유저별 창발)** | 유저마다 다름 | 내 함장의 선택, 체류함장들과의 대화·관계, 결과적으로 "내 우주에서 있었던 일" |

**실무적으로 챙겨야 할 것**

1. **비용 구조 재검토 필요**: 기존 하이브리드 엔진(4.1절)은 "반복 명령 → 템플릿, 예측불가 대화 → LLM"이었다. 스토리를 함께 만드는 대화는 태생적으로 템플릿화가 어려워 LLM 호출 비율이 높아진다 — 기존 3개월 매출 시뮬레이션(투자자용 문서)에 이 비용이 아직 반영되어 있지 않으므로 재계산이 필요하다.
2. **가드레일은 "플롯 준수"가 아니라 "세계관 이탈 방지"**: 정해진 줄거리가 없으므로 AI에게 필요한 규칙은 "이 세계관 설정 안에서만 반응하라"는 것 하나로 단순하다. 예: 팩션 이름을 임의로 지어내지 않기, 기술 수준을 벗어난 설정(마법 등)을 만들지 않기, 프롤로그 톤과 다르게 가볍게 만들지 않기.

## 5. 구현 우선순위 (제안)

1. **P0 — 하이브리드 대화 엔진 코어**: 템플릿 매칭 로직 + LLM 폴백 호출 구조. 이게 없으면 나머지 전부가 비용 리스크를 안고 시작함.
2. **P0 — 인간형 닉네임 생성/할당 시스템**: NPC 체류함장 전원에 닉네임 풀 배정.
3. **P1 — 배경 채팅 로그 배치 생성 파이프라인**: LLM으로 대화 로그를 사전 생성해 CSV/테이블 형태로 저장, 클라이언트에서 무작위 재생.
4. **P1 — 1:1 동시성 제어 로직**: 한 번에 하나의 실시간 LLM 세션만 열리도록 하는 상태 관리(Zustand 등 기존 스택 활용).
5. **P2 — 1:3 UX 및 단체방 템플릿/LLM 혼합 로직**: 턴제 응답 순서 제어, 단체방 발언 트리거 조건 정의.
6. **P2 — AiNpcSubCore 궤도 트래픽, 함장 일지, 비콘, 4대 제국 흥망 시뮬레이션**: 기존 아크코어 온디바이스 연산 구조에 통합.
7. **P2 — 스토리 생성형 대화 가드레일 프롬프트**: "세계관 이탈 방지" 규칙을 시스템 프롬프트로 명문화 (4.5절 참고).
