## 0. 한 줄 결론

바의 **1순위 루프**는 「주인 맞이 → 종업원 선택 → 술 후원 → 15분 단위 공연(대사+숏컷)」이다.  
미션·공지 보드는 **부탭으로 유지**한다. 구현은 **Table-First CSV + `NarrativeDialogRow` + 경량 RN 숏컷**만 쓰고, Skia/고프레임 댄스·LLM 실시간 대사는 1차 범위 밖이다.

## 2. 플레이어 루프 (메인)

```text
바 입장
  → [A] 주인 인게임 대사 (맞이 + 「술 한 잔 사 주시겠어요?」)
  → [B] 선택지: [ 좋아 ] / [ 다음에 ]
       · 다음에 → 기존 보드/미션 탭만 (후원 세션 없음)
       · 좋아 → [C]
  → [C] 종업원 리스트 (행성별 5~20명 · 번영도 시드)
  → [D] 1명 선택 → 술 구매 확인 (크레딧 1차 · 향후 유료 아이템)
  → [E] 공연 세션 시작 (벽시계 기본 15분 / 잔)
       · 대사 페이지 진행 + 숏컷 애니(루프/클립)
       · 남은 시간 HUD
       · [ 술 추가 ] → 시간 연장 + 다음 콘텐츠 묶음 해금
       · [ 자리 비움 ] / 뒤로가기 / 시설 이탈 → `endSession` (활성 세션 null, 아래 §5)
  → [F] 세션 종료 → 호감/후원 로그 저장 → 보드 복귀
```

**재입장**: 시설 이탈 시 `endSession`(활성 세션 null · 인기/지출 persist는 유지). 다시 들어와도 **매 입장마다 [A] 주인 맞이를 먼저** 거친다. `[ 좋아 ]` 수락 후 라운지. 공연(Show) 탭은 이번 방문에서 술을 산 뒤에만 `gateAccepted && isLivePaidPatronageSession`으로 탭바 노출.

## 3. 기존 바과의 관계

| 현행 | 후원 도입 후 |
|------|----------------|
| 입장 시 주인 `presentIngameDialogScene` (맞이) | **후원 인트로 대사로 교체·확장** (OK 선택지 필수) |
| 탭: 보드 / 미션현황 / 신규의뢰 | **기본 탭 = 후원(라운지)** · 보드·미션은 부탭 유지 |
| `barHostCaptain` (함장 풀) | 주인 NPC **유지** (후원 게이트 화자) |
| `facility_bar` 레벨·P 스탯 | **행성 번영도(rosterBase)** 가 인원 기본 · 인구돔 레벨은 +0~3 가산 · qualityTier로 종업원 수준 |

| 바운티·미션 | **변경 최소** — 후원과 경제 축만 약하게 연결(선택) |

**메인 콘텐츠 정의**: 입장 직후 시선·첫 인터랙션은 후원.  
보드/미션은 “일하러 온 사람”용 2순위 UI.

## 5. 세션 · 시간 규칙

| 규칙 | 값 | 이유 |
|------|-----|------|
| 기본 단위 | **술 1잔 = 15분(벽시계)** | 대표님 지시 |

## 6. Table-First 콘텐츠 모델

편집 정본 = CSV → `npm run build:content-tables` (또는 balance). 코드 하드코딩 풀 금지.

### 6-1. `bar_attendants.csv` (종업원)

| 컬럼(안) | 설명 |
|----------|------|
| `attendantId` | 글로벌 유일 id (`ta_att_001`…`288`) |
| `planetId` | **해당 행성만** (`*` 유랑 풀 폐지) |
| `displayNameKo` / `En` | 단순 예명만 (`세이블` / `Sable`) · 행성 접미 금지 · 행성 간 중복 허용 |
| `portraitImageAssetKey` | `bar_att_portrait_001`…`288` |
| `taglineKo` | 한 줄 분위기 |
| `minBarLevel` | 시설 레벨 게이트 (1~5 분산) |
| `rosterWeight` | 동점 시 순위 · 균등 시드 |
| `dialogSetId` | 아키타입 (~8) |
| `animSetId` | 숏컷 세트 (`aset_soft`) |
| `songId` | `bar_songs.csv` many-to-one |
| `enabled` | 0/1 |

**리스트 크기**: 해당 행성 전용 후보에서 `clamp(12, 20, rosterMin + level - 1)`.  
후보가 target보다 많으면 상위 weight+dayKey 정렬로 target명, 적으면 그 행성 enabled 전원.  
당일 `dayKey`는 **정렬 순서용만**(가중 샘플/`*` 제거).  
동일 방문 재입장 시 planetId+dayKey로 순서 고정 → 깜빡임 방지.

[existing-value-change] `bar_patronage_policy.csv` `roster_min` 5→**12** · `roster_max` 15→**20** · 대표님 2026-09-05 승인.

## 8. 경제 · BM

| Phase | 결제 |

## 15. 은하계 종업원 용량·구조 (2026-09-06 · 행성 번영도 연동)

> A축 `planets.csv` **hasBar=true = 18곳**. synth 바은 **헤드룸 문서만**.
> **대표님 2026-09-06**: 수도·번영 = 인원·수준↑ · 외곽 = 자본력·발전도 → **5~20**.

### 15-1. 총원 산정표

| 항목 | 값 | 비고 |
|------|----|------|
| 바 행성 (A축) | **18** | `hasBar=true` |
| 행성별 노출 | **5~20** | `bar_planet_roster_policy.csv` rosterBase + 발전 가산 |
| 행성별 시드 풀 | **8~20** | 정책 `poolSize` · 수도 20 · 변방 8 |
| 은하 총원 (시드) | **정책 pool 합** | 균일 288 고정 해제 · 재시드 시 로그 확인 |
| 유랑 풀 | **폐지** | `planetId='*'` 금지 |

### 15-2. 테이블 축

| 축 | 정본 | 계약 |
|----|------|------|
| roster policy | `bar_planet_roster_policy.csv` | planetId · rosterBase · poolSize · qualityTier(1–5) |
| attendants | `bar_attendants.csv` | `attendantId` 글로벌 유일 · **1 planetId 고정** · poolSize만큼 시드 |
| songs | `bar_songs.csv` | **5곡** 공유 |
| dialog archetype | `bar_dialog_turns.csv` | **~8 아키타입** + host/shared · 수도는 premium set 비중↑ |

아키타입 id: `dset_cheerful` · `dset_calm` · `dset_jazz` · `dset_star` · `dset_ballroom` · `dset_whisper` · `dset_ember` · `dset_echo`.

### 15-3. 유일성 계약

- `attendantId` 은하 유일 (`ta_att_001`…). 글로벌 유일은 **id만**.
- 각 행은 **행성 1곳만** 근무. 재배치·유랑 없음.
- `displayNameKo` / `displayNameEn`은 **단순 예명**만. **행성 내** 이름 중복 금지 · **행성 간** 동일 이름 허용.
- `portraitImageAssetKey` 슬롯 유일. 샘플 PNG 순환은 **맵 구현**.

### 15-4. 노래

- `bar_songs.csv`: `songId,titleKo,titleEn,assetKey,durationSec,enabled,note`
- 시드 5행 `song_01`…`song_05` · 종업원 `songId` 순환 배정.

### 15-5. 대화

- 개별 장문 금지. 아키타입 dialogSet + 주인(`dset_host`)만.
- qualityTier≥5(수도)는 premium set(`star`/`ballroom`/`cheerful`/`jazz`) 우선.

### 15-6. 이미지

- 키 슬롯 헤드룸 360 (`barAttendantPortraitAssets.ts`).
- **critical-session prefetch 금지**.
