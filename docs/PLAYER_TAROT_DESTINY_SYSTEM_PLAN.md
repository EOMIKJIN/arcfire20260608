# 플레이어 타로(운명) 시스템 — 기획 정본 (v0.1)

> **상태**: 기획만 · **코드 미착수** (대표님 지시 2026-07-24)  
> **성격**: 최초 선택으로 플레이어의 **가장 중요한 특성·미래 축**을 미리 결정하고, 이후 스토리·전투·죽음·NPC 상호작용까지 확장하는 **대맥락 시스템**  
> **데이터**: 메이저 아르카나 계열 **22장** — 해석·스탯·연동 수치는 **개발자(대표님)가 직접 작성·제공**

---

## 0. 한 줄 정의

**「플레이어의 미래를 결정짓는 최초의 선택」** — 신규 온보딩에서 22장 중 1장을 고르면, 그 카드의 해석·특성이 계정에 귀속되어 게임 전반의 영향을 주는 운명 축이 된다.

---

## 1. 기획 의도

| 축 | 내용 |
|----|------|
| **경험** | 캐릭터(직업) 선택보다 앞선 **운명 의식** — “나는 어떤 미래를 미리 받아들이는가” |
| **정체성** | 카드 1장이 플레이어의 **핵심 특성**(성향·업보·길)을 대표 |
| **확장** | 단순 문구가 아니라, 이후 **스토리 분기 · 전투 결과 · 죽음의 운명 · 엔딩 · 전 NPC 상호작용**에 스탯·플래그로 연동 |
| **저작** | 22장 본문·수치·키는 Table-First로 두되, **1차 원문은 대표님이 직접 입력·생성** |

예시 해석 톤(샘플, 정식 데이터 아님):

> 「내면의 깊은 혼란과 빛나는 앞길을 향한 의지의 전진」

이런 해석 문장이 카드 행의 `interpretationKo`(가칭)에 들어가고, 같은 행의 스탯·태그·가중치가 런타임에서 행동·전투·서사에 읽힌다.

---

## 2. 현재 온보딩과의 위치 — 삽입 가능 여부 (**검토 결론: 가능**)

### 2-1. 현행 신규 흐름 (코드 기준 · 참고)

```text
타이틀 → intro(프롤로그) → character-select(캐릭터 3명) → nickname → … → 행성 허브
```

- `intro.tsx` 종료 시 `/(game)/character-select` 로 이동  
- 직업/초상은 `character-select` · `onboardingDraftStorage` · `onboardingPilotRegistration`  
- **계정 생성·영속 확정은 nickname 전후**에 가깝게 묶여 있음

### 2-2. 제안 삽입점 (권장)

```text
타이틀 → intro → 【타로 운명】 → character-select → nickname → …
```

| 판단 | 내용 |
|------|------|
| **가능 여부** | **가능** — intro와 character-select **사이**에 온보딩 STAGE 화면 1장 추가하는 형태가 기존 패턴과 맞음 |
| **이유** | 캐릭터 3선택보다 **운명(미래 축)이 먼저**라는 기획과 일치 · draft 저장(`onboardingDraft*`)에 `destinyCardId`만 실어 nickname/계정 생성 시 프로필에 병합하면 됨 |
| **대안** | 타이틀 직후 / nickname 직후 — 비권장(서사 호흡·“최초 선택” 무게가 약해짐) |
| **이어하기** | 기존 계정은 **스킵** (이미 카드 보유 또는 레거시 폴백) |

### 2-3. 구현 시 주의 (기획 메모 · 코딩 시점)

- STAGE 0 온보딩 · `Navigation.replace` · 세션 dispose 계약 준수  
- 카드 데이터는 CSV/테이블 정본 · 하드코딩 해석 금지  
- 영속: 플레이어 계정 귀속 + `purgeLocalAccountData` 연동 (신규 스토어 시)  
- 본 문서는 **코드 작업 없음** — 위는 향후 DoD용

## 3. MVP UX 흐름 (시스템 1~4) — **추가 가능 · 권장 범위**

대표님 요청 4단계를 **1차 구현 범위(연출·선택·공개·설명)** 로 고정한다.  
스탯 연동·스토리/전투 분기는 **Phase 2+**.

| # | 단계 | 플레이어 행동 / 연출 | 산출 |
|---|------|----------------------|------|
| **1** | 간단한 설명 + 카드 등장 | 짧은 안내 문구 · 22장(또는 뒷면 더미)이 깔리거나 흩어지는 **등장 연출** | 분위기·규칙 고지 |
| **2** | 1~22 숫자 입력 | 플레이어가 **1~22** 중 하나를 입력(키패드/입력창). 카드 “뽑기”의 명시적 선택 | `selectedIndex` (1-based) |
| **3** | 카드 공개 오픈 연출 | 해당 번호 카드가 뒤집히며 **공개 연출** (앞면 아트·타이틀) | `cardId` 확정 연출 |
| **4** | 최종 설명 | 카드명 + **해석 문장** + (선택) 핵심 특성 한 줄 요약 → 확인 후 character-select | draft에 `destinyCardId` 저장 |

### 3-1. MVP에서 의도적으로 빼는 것

- 전투/스토리/NPC 수치 실시간 반영 (데이터 스키마·훅만 예약)  
- 카드 재선택·상점 판매 (최초 1회 확정)  
- 22장 풀 일러스트 필수 — **없으면 번호·테마 색·플레이스홀더**로도 MVP 성립  
- AI 생성 해석 — **대표님 제공 22행만** 사용

### 3-2. 숫자 입력 UX 메모

- 유효: 정수 1…22 · 그 외는 거부 + 짧은 안내  
- “랜덤” 버튼은 **선택 사항**(기획상 ‘스스로 고른 운명’이면 없어도 됨)  
- 접근성: 큰 입력 · 한국어 안내

## 4. 22장 데이터 (개발자 제공 · Table-First 예약)

### 4-1. 원칙

- **정본 22행**은 대표님이 작성·검수  
- 파일 가칭: `tables/content/player_destiny_tarot_cards.csv` (구현 시 확정)  
- 코드에 해석 문자열 하드코딩 금지

### 4-2. 행 필드 (기획 스키마 · 가칭)

| 필드 | 필수 | 설명 |
|------|------|------|
| `id` | ✅ | 예: `tarot_00` … `tarot_21` 또는 `tarot_01`…`tarot_22` |
| `ordinal` | ✅ | 1…22 (입력 번호와 1:1) |
| `nameKo` / `nameEn` | ✅ | 카드 표시명 |
| `interpretationKo` / `interpretationEn` | ✅ | 긴 해석 (최종 설명·로그) |
| `traitSummaryKo` | ✅ | 한 줄 핵심 특성 |
| `imageAssetKey` | △ | 향후 일러스트 · 없으면 UI 폴백 |
| `tagsPipe` | △ | 예: `chaos\|resolve\|frontier` — NPC/스토리 매칭용 |
| `stat_*` 또는 JSON attrs | △ | Phase 2 스탯 (전투·사망·호감 등) — **대표님 수치 확정 후** |

> MVP는 `ordinal` + 이름 + 해석 + 요약만으로도 화면 4단계를 닫을 수 있다.  
> 스탯 컬럼은 **빈 칸 허용** 후 Phase 2에서 채운다.

### 4-3. 플레이어 대입

1. 입력 `n` → `ordinal === n` 행 조회  
2. `destinyCardId = row.id` 를 온보딩 draft → 계정 프로필/스토어에 저장  
3. 이후 모든 연동은 **`destinyCardId` → 테이블 O(1) 조회**만 사용 (복제 문자열 금지)

---

## 5. 확장 비전 (대맥락 · Phase 2+)

카드를 “문구”가 아니라 **세계 반응의 가중치**로 쓴다.

| 영역 | 영향 예 (기획) |
|------|----------------|
| **스토리** | 미션·씬 분기 태그, 선택지 해금/봉인 |
| **전투** | 명중·회피·위기 시 보정, 패배 연출 톤 |
| **죽음의 운명** | 사망 시 메시지·패널티·부활 조건 톤 (규칙 수치는 별도 밸런스) |
| **최후/엔딩** | 엔딩 플래그·에필로그 문단 |
| **NPC 상호작용** | 대사 톤, 호감·적대 초기 오프셋, 퀘스트 제시 확률 |

공통 규칙(향후):

- 고빈도 틱에서 카드 테이블 전수 스캔 금지 · **부트/이벤트 시 1회 해석 캐시**  
- AABS·일일 배치와 충돌하지 않게 **플레이어 귀속 보정**으로만 누적  
- 멀티플레이 동기화 없음 (싱글 샌드박스)

## 9. 미결정 (대표님 확인 대기)

1. 캐릭터 **초기화 시** 타로 재선택 여부  
2. 카드 번호 체계: 0–21(전통 메이저) vs 1–22(입력 UX) — **MVP는 1–22 입력**에 맞춤

4. 일러스트 일정 (플레이스홀더로 Phase 1 가능 여부 — **가능**으로 기획 확정)
