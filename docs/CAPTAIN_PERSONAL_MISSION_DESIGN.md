# 함장 개인미션 — INFO 통신 의뢰 설계

> **작성**: 2026-09-18 · 김팀장  
> **상태**: **설계 정본 · 코드 미착수**  
> **지시**: 인포창 대화목록에서 통신이 연결되면, 그 함장이 **개인 사연 의뢰**를 준다. 바 인스턴스와 **같은 수락·수행·보상 가문**, 다른 채널.  
> **충돌 시 우선**: 본 문서 > 허브 [대화] 자동수락 관행 > 바 보드를 INFO에 복제하는 안  
> **유지**: 2게이트(NPC=1차만) · Table-First · STAGE `replace()` · 13번째 서브코어 금지 · ZERO_BILL · PSS §0-A · 본편 `story_*` 잠금 · `questOnly` 함장 행 추가 금지

```text
[pss-pre-dev] hot_path=INFO 통신 수락 1회 · 대화 종료 수락/거절 1회 · 목표 완료 기존 missionStore
[pss-pre-dev] alloc=함장당 listed 0~1 · 전역 동시 활성 상한 3 · 일일 전 함장 보드 금지
[pss-pre-dev] stage=INFO overlay dismiss 후 1차 통신 · 메신저 없음
[pss-pre-dev] verdict=PASS — 아래 잠금을 지키면 착수 가능. 바 보드 복제·침묵 수락은 REDESIGN
```

## 0. 한 줄

통신이 연결된 함장만, **1차 대사로 짧은 사연을 말한 뒤 [수락]/[다음에]** 로 개인미션을 건넨다.  
바 [신규 의뢰]는 행성 일자리 게시판이고, 이건 **그 함장의 개인 부탁**이다.

## 1. 현재 상태 (검토 근거)

| 경로 | 지금 하는 일 | 개인미션 |

없는 것은 「통신 연결 → 사연 → 선택 수락 → 함장 귀속 인스턴스」 계약이다.

## 3. 잠금 (구현이 따른다)

### 3-1. 채널

- **유일한 오퍼 입구**: INFO 통신이 `accept`로 연결된 뒤의 **1차 통신** (`presentIngameDialogScene`).
- 허브 [대화] 명단·바 [신규 의뢰]에는 **v1에서 넣지 않는다.** (침묵 수락·일자리와 섞이지 않음)
- 거부(적대·미식별·대화 비활성)·기함·궤도 필(`arcOrbitPresenceFill`)은 오퍼 없음.
- 연결 팝업은 유지. 퀘스트는 팝업이 아니라 **대사 마지막 페이지**.

### 3-2. 트랙

| 트랙 | 접두사 | 역할 |
|------|--------|------|
| 본편 | `story_*` | 기존. 최우선. 이 함장에 수락 가능 본편이 있으면 개인미션 **대기** |
| 튜토리얼 | `mission_*` | 기존 |
| 수락 의뢰 | `sandbox_*` | 기존 고정·허브/바 |
| 바 인스턴스 | `tq_*` → `arc_inst_*` | 행성 일자리 |
| **함장 개인** | **`cp_*` 템플릿 → `arc_cpt_{captainId}_{seq}`** | 이번 설계 |

HUD는 기존 `quest` 가문(📋)에 실어 주선과 싸우지 않는다.  
`acceptQuestMission`과 같은 수락·만료·클리어 파이프라인을 쓰되, id·오퍼 게이트만 분리한다.

### 3-3. 오퍼 조건 (모두 만족)

1. 이번 통신 `outcome=accept`
2. `mainStageTalkEnabled`
3. 적대 거부 경로가 아님
4. 이 함장에 **수락 가능 본편** 없음
5. 이 함장에 **활성 talk_npc 접촉 목표** 없음 (기존 퀘스트 만남이 우선)
6. 이 함장 **개인미션 활성 0건**
7. 계정 전체 개인미션 활성 **≤ 3**
8. 거절 쿨다운 아님 (기본 1 아크코어 일)
9. 템플릿 풀에서 이 함장·행성 컨텍스트로 1건 뽑힘

재통신: 활성 개인미션이 있으면 **진행/독촉 한 페이지**만. 새 오퍼 없음.  
클리어 후: 감사 한 페이지. 다음 오퍼는 쿨다운 후.

### 3-4. 대화 형식 (사연 → 요청)

1차 통신만. 메신저 없음. 레이아웃 상수 불변.

```text
페이지 1~2  사연 (함장 이름·직전 행성 토큰 가능)
페이지 3    부탁 + 보상 한 줄
마지막      [ 수락 ] / [ 다음에 ]
```

- `[ 수락 ]` → 인스턴스 수락 · 보상은 클리어 시.
- `[ 다음에 ]` → 수락 없음 · 쿨다운만. 적대 아님.
- 침묵 `accept_quest_mission`을 대화 종료에 붙이지 않는다.

### 3-5. 콘텐츠 (Table-First · 간단한 스토리)

전원 고유 소설이 아니다. **사연 가문 템플릿** + 함장/행성 토큰.

| 가문 id (초안) | 사연 한 줄 | 목표 유형 (기존만) |
|----------------|------------|---------------------|
| `cp_favor_cargo` | 맡긴 화물이 다른 허브에 묶였다 | `buy_goods` 또는 `reach_planet` |
| `cp_old_debt` | 옛 전우에게 빚을 갚고 싶다 | `reach_planet` + 소액 |
| `cp_escort_kin` | 가족이 탄 항로가 불안하다 | `reach_system` / 호위형 배달 |
| `cp_hunt_mark` | 얼굴을 아는 약탈자를 찾는다 | `defeat_enemy` (기존 템플릿만) |
| `cp_talk_witness` | 목격자 함장에게 말을 전해 달라 | `talk_npc` |
| `cp_rumor_check` | 소문을 확인하고 돌아와 달라 | `reach_planet` |

- 템플릿 CSV 6~8행으로 v1 충분. 함장 해시+일차로 결정적 선택.
- **이름 있는 함장 전용 원고**는 나중에 bind CSV로 덮어쓴다. 엔진은 동일.
- 새 함장·새 행성·새 목표 타입 없음.
- `defeat_enemy`는 기존 `mission_quest_combat_ops` 규칙 준수.

### 3-6. 메모리·영속

- **생성 시점**: 통신 수락 직후 1건만 materialize. 일일 배치에서 전 함장 생성 금지.
- persist: 기존 `missionStore` + (선택) `orbitPresenceMemory`에 `lastPersonalOfferDayKey` · `declineUntilDayKey` 필드. **신규 AsyncStorage 스토어 금지**가 기본. 필드 추가 시 purge 연동.
- 인스턴스 캐시: 바 `materializedByInstanceId`와 **다른 Map**. 함장당 1, 클리어 시 제거.
- Views: INFO 행 수 불변. 버튼 추가 없음.

### 3-7. 보상

- 바 돔 평판과 **무관**. 개인미션은 관계·사연이 본전.
- v1: 템플릿 CR/EXP 고정(난이도 소폭). 아이템은 기존 `item_defs`만.
- 5대 스탯·무역 탄력 없음.

## 4. 프로세스

```text
INFO 목록 → [통신요청]
  ├─ 거부/기함/필  → 기존과 동일 (퀘스트 없음)
  └─ 연결 팝업 [확인]
        → 1차 통신
              ├─ 본편/접촉 우선 씬 (기존 씬 id) — 개인미션 페이지 없음
              ├─ 개인미션 오퍼 가능
              │     → 사연 페이지 → [수락] 인스턴스 수락
              │                   → [다음에] 쿨다운
              └─ 오퍼 불가 (상한·쿨다운·활성)
                    → 기존 함장 씬만 (지금과 동일)
```

클리어: 기존 목표 훅 → 클리어 1차 통신(가능하면 같은 함장) → 보상.

## 6. 구현 순서 (코드는 승인 후)

1. 트랙·id · 템플릿 CSV 스키마 · 오퍼 게이트 순수 함수  
2. INFO 통신 수락 씬에 오퍼 페이지 연결 (`showAcceptCancelChoice`)  
3. 수락 → `arc_cpt_*` materialize + `missionStore`  
4. 목표/클리어/감사 씬 — 기존 훅만  
5. 이름 있는 함장 bind는 콘텐츠 승인 후

커밋·테이블 빌드·함장 행 추가는 대표님 지시 전 금지.
