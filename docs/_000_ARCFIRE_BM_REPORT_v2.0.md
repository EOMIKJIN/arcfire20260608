## 1. BM 철학 및 설계 원칙

### 1-1. 핵심 철학

| 원칙 | 내용 |
|------|------|
| **경쟁 배제** | 싱글플레이 샌드박스 — 유저 간 PvP 과금 압박 구조 없음 |
| **편의 중심** | 성장 가속·이동 편의·전투 보조 중심 |
| **통화 역할 분리** | 크레딧(인플레 허용 게임머니) ↔ 보석(수량 통제 프리미엄 통화) 완전 분리 |
| **핵심 자산 보호** | 함선·헐 등 핵심 자산은 보석 전용 루트로만 접근 가능 |

### 1-2. 통화 역할 요약

```
크레딧 (Cr)  — 게임 내 플레이로 자연 획득. 인플레 허용. 소모성 지출 중심.
보석 (Gem)   — 현금 구매 또는 제한적 이벤트 획득. 수량 통제. 핵심 자산 구매 전용.
```

## 2. 이중통화 구조

### 2-1. 크레딧 (Credits, Cr)

| 항목 | 내용 |
|------|------|
| **성격** | 게임머니 — 인플레이션 허용 |
| **획득** | 전투 보상, 무역 수익, 채굴 판매, 무역 수수료 환급, 미션 보상, 이벤트 무료 지급 |
| **현금 구매** | ❌ 직접 현금 구매 불가 — **보석 → 크레딧 교환만 가능** |
| **주요 지출** | 무기·장비 구매, 행성 유지비, 수리비, 소모성 아이템 |
| **인플레 통제** | 일 1회 배치(12:00 KST) AABS 보정. 시장 탄력 없음(`price_elasticity=0`) |

### 2-2. 보석 (Gems)

| 항목 | 내용 |
|------|------|
| **성격** | 프리미엄 통화 — 수량 통제 |
| **획득** | ① 현금 구매 (보석팩, 스타터팩, 시즌패스 포함) ② 이벤트/미션 소량 무료 지급 |
| **현금 구매** | ✅ 보석팩 직접 현금 구매 |
| **주요 지출** | 핵심 자산(함선/헐 직접 구매), 크레딧 교환, VIP 구독, 편의 아이템 |
| **수량 통제** | 무료 지급 경로 엄격 제한. Whale/F2P 전투력 비율 ≥ 8 금지 |

### 2-3. 교환 정책

| 방향 | 가능 여부 | 비고 |
|------|-----------|------|
| 보석 → 크레딧 | ✅ 가능 | 교환 비율은 CSV 정본(`gem_exchange_rate`) 기준 |
| 크레딧 → 보석 | ❌ 불가 | 완전 단방향 — 크레딧으로 보석 획득 루트 없음 |

> ⚠️ 크레딧 → 보석 교환을 허용하면 F2P 고플레이어가 보석을 무제한 획득 가능 → **Whale/F2P 비율 붕괴 위험**. 단방향 고정.

## 3. 과금 상품 유형 분류

구매 수단 기준으로 5가지 유형으로 분류한다.

### Type A — 현금 직접 구매 상품

> 앱스토어 IAP(In-App Purchase)로 직접 결제

| 상품 | 내용 | 지급 통화 |
|------|------|-----------|
| **보석팩** | 소/중/대/특대 패키지 | 보석 |
| **스타터팩** | 신규 유저 한정 할인 번들 (보석 + 크레딧 + 장비) | 보석 + 크레딧 + 아이템 |
| **시즌패스** | 기간 한정 프리미엄 패스 (`isPremium: true`) | 패스 레벨 보상 (보석/크레딧/아이템 혼합) |
| **VIP 구독** | `basic / plus / max` 월정액 | 매일 보석 지급 + 혜택 |

### Type B — 보석으로 구매하는 상품

> 게임 내 상점에서 보석 소비

| 상품 | 내용 | 소비 통화 |
|------|------|-----------|
| **함선/헐 직접 구매** | 조선소 크레딧 구매 대신 즉시 획득 | 보석 |
| **희귀 무기/장비** | 보석 전용 진열 아이템 | 보석 |
| **크레딧 교환** | 보석 → 크레딧 환전 | 보석 → 크레딧 |
| **빠른 이동권** | 이동 시간 즉시 단축 | 보석 |
| **탐사 티켓** | 잠긴 구역 탐사 진입권 | 보석 |
| **부활권** | Stage 3 전투 중 즉시 부활 | 보석 |
| **전투 버프** | 일시적 전투 강화 | 보석 |

### Type C — 크레딧으로 구매하는 상품

> 무역소·조선소에서 크레딧 소비 (F2P 메인 루트)

| 상품 | 내용 | 소비 통화 |
|------|------|-----------|
| 무기·장비 | 무역소 진열 아이템 | 크레딧 |
| 함선 체급 업그레이드 | 조선소 헐 티어 구매 | 크레딧 |
| 행성 시설 설치 | 방위위성·개발 시설 | 크레딧 |
| 광물 업그레이드 | 조선소 강화 단계 | 크레딧 |
| 소모성 수리 | 전투 후 수리비 | 크레딧 |

### Type D — 무료 지급 (이벤트·미션 보상)

> 현금 없이 획득 가능한 경로

| 상품 | 지급 조건 | 지급 통화 |
|------|-----------|-----------|
| 이벤트 크레딧 | 기간 한정 이벤트 참여 | 크레딧 |
| 미션 보상 크레딧 | 미션 완료 | 크레딧 |
| 시즌패스 무료 보상 | 패스 레벨 달성 (`isPremium: false` 무료 트랙) | 크레딧 + 소량 아이템 |
| 보석 소량 지급 | 특별 이벤트·업적 한정 | 보석 (소량 엄격 통제) |

### Type E — 스타터팩 (신규 유저 전용)

> 첫 구매 특가. 1계정 1회 한정

| 항목 | 내용 |
|------|------|
| 구매 수단 | 현금 (IAP) |
| 지급 내용 | 보석 + 크레딧 + 초반 장비 번들 |
| 조건 | 계정당 1회, 초반 레벨 구간에서만 노출 |
| 목적 | 신규 유저 첫 결제 유입 (Dolphin 전환 퍼널) |

## 4. 스테이지별 BM 매핑

> ⚠️ 각 스테이지 메모리 제약 준수 필수 — 상점 Modal 호출 시점 엄격히 지킬 것

### Stage 1 — Hub (행성 허브)

| 항목 | 내용 |
|------|------|
| **노출 상품** | 시즌패스, VIP 구독, 스타터팩, 보석팩 |
| **결제 수단** | 현금(IAP) |
| **메모리 주의** | rAF 루프 유지 중 → Modal 내부 메모리 최적화 필수 |
| **통화 UI** | 상단 HUD에 크레딧(Cr) + 보석(💎) 잔액 동시 표시 |

### Stage 2 — Map (은하 지도)

| 항목 | 내용 |
|------|------|
| **노출 상품** | 빠른 이동권, 탐사 티켓 |
| **결제 수단** | 보석 |
| **가격 조회** | CSV O(1) 조회 (`gem_item_price_index`) |

### Stage 3 — Combat (전투)

| 항목 | 내용 |
|------|------|
| **노출 상품** | 부활권, 전투 버프 |
| **결제 수단** | 보석 |
| **🚨 절대 규칙** | Skia Canvas `.dispose()` 완전 완료 후에만 상점 Modal 오픈 |

## 5. Firestore BM 스키마

### 5-1. `arcfire_player_v1` 확장 스키마

```typescript
interface PlayerBMData {

  // ── 보석 잔액 ──────────────────────────────────
  gems: {
    balance: number;                  // 현재 보석 잔액
    lifetimePurchased: number;        // 누적 현금 구매 보석 (Whale 판별용)
    lifetimeEarned: number;           // 누적 무료 획득 보석
    lastUpdatedAt: Timestamp;
  };

  // ── 시즌패스 ───────────────────────────────────
  seasonPass: {
    seasonId: string;
    isPremium: boolean;               // true = 유료 트랙 활성
    currentLevel: number;
    claimedRewards: string[];
    expiresAt: Timestamp;
  };

  // ── VIP 구독 ───────────────────────────────────
  vip: {
    tier: 'none' | 'basic' | 'plus' | 'max';
    subscribedAt: Timestamp | null;
    expiresAt: Timestamp | null;
    dailyGemGrant: number;            // 매일 지급 보석 수량 (tier별 상이)
    lastDailyGrantAt: Timestamp | null;
  };

  // ── 스타터팩 ───────────────────────────────────
  starterPack: {
    purchased: boolean;               // 구매 여부 (1회 한정)
    purchasedAt: Timestamp | null;
  };

  // ── 구매 이력 (퍼널 분석용) ────────────────────
  purchaseHistory: {
    productId: string;
    purchaseType: 'gem_pack' | 'starter_pack' | 'season_pass' | 'vip' | 'gem_item';
    gemAmount?: number;
    creditAmount?: number;
    purchasedAt: Timestamp;
  }[];
}
```

### 5-2. 보석 트랜잭션 처리 원칙

```typescript
// 보석 지출 시 반드시 잔액 검증 후 차감
const spendGems = (amount: number): boolean => {
  if (player.gems.balance < amount) return false; // 잔액 부족 시 결제 유도 UI
  player.gems.balance -= amount;
  // Firestore 단발성 업데이트
  return true;
};

// 보석 → 크레딧 교환 (단방향)
const exchangeGemsToCredits = (gems: number): number => {
  const rate = gemExchangeRateIndex.get('gem_to_credit_rate'); // CSV O(1)
  return gems * rate;
};

// 크레딧 → 보석 교환: 절대 금지
// ❌ const exchangeCreditsToGems = () => {} // 구현 금지
```

## 6. 통화 흐름 다이어그램

```
[ 현금 (IAP) ]
      │
      ├──→ 보석팩        ─────────────────────→ [ 보석 잔액 ]
      ├──→ 스타터팩      ─→ 보석 + 크레딧 + 아이템  │
      ├──→ 시즌패스      ─→ 패스 레벨 보상(혼합)    │
      └──→ VIP 구독      ─→ 매일 보석 지급 ─────────┤
                                                    │
[ 이벤트·미션 무료 지급 ] ─→ 크레딧 ───────→ [ 크레딧 잔액 ]
[ 이벤트 소량 지급 ]     ─→ 보석 ─────────→ [ 보석 잔액 ]
                                                    │
[ 전투·무역·채굴 ]  ─────────────────────────→ [ 크레딧 잔액 ]
                                                    │
                              [ 보석 잔액 ] ─→ 크레딧 교환 ─→ [ 크레딧 잔액 ]
                              (단방향, 역방향 금지)
                                    │
                    ┌───────────────┼───────────────────┐
                    ↓               ↓                   ↓
              함선/헐 구매    빠른이동·탐사티켓      부활권·전투버프
              희귀 무기/장비  VIP·시즌패스 구매

[ 크레딧 잔액 ]
      │
      ├──→ 무기·장비 (무역소)
      ├──→ 함선 체급 업그레이드 (조선소, 크레딧 루트)
      ├──→ 행성 유지비 800Cr/일
      ├──→ 수리비
      └──→ 광물 업그레이드
```

## 7. 인플레이션 통제 정책

### 7-1. 크레딧 인플레 허용 범위

크레딧은 인플레이션을 **의도적으로 허용**하되, 게임 진행이 불가능한 수준의 붕괴를 막기 위해 아래 정책을 적용한다.

| 통제 수단 | 내용 |
|-----------|------|
| `price_elasticity = 0` | 플레이어 대량 매매에도 가격 즉각 변동 없음 |
| 일 1회 AABS 보정 | 12:00 KST 배치에서만 가격 조정 (±5% 캡) |
| 크레딧 → 보석 교환 차단 | 크레딧 과잉 공급이 보석 가치에 영향 불가 |
| 유지비 sink | 행성 1개당 800 Cr/일 강제 소각 |
| 수리비 sink | TDI 높을수록 수리비 증가 → 크레딧 자연 소비 |

### 7-2. 보석 수량 통제

보석은 **공급량을 엄격히 통제**한다.

| 통제 수단 | 내용 |
|-----------|------|
| 무료 보석 지급 | 이벤트·업적 한정, 소량만 허용. 경로별 상한 정의 필요 |
| VIP 일일 지급 | tier별 지급량 고정 — 런타임 변경 금지 |
| 보석 → 크레딧 비율 | CSV 정본 고정. 런타임 임의 변경 금지 |
| Whale/F2P 비율 모니터링 | 전투력 비율 ≥ 8 시 AABS 경고 |

## 8. 플레이어 등급 밸런스

| 등급 | 정의 | 주요 구매 패턴 |
|------|------|---------------|
| **F2P** | 무과금 | 크레딧만 사용. 이벤트 보석 소량 획득 |
| **Dolphin** | 소액 과금 | 스타터팩 1회 + 시즌패스 위주 |
| **Whale** | 고액 과금 | VIP MAX + 보석팩 반복 구매 + 함선 직구 |

### 밸런스 KPI

| 상태 | Whale/F2P 전투력 비율 | 판정 |
|------|----------------------|------|
| 정상 | < 5 | ✅ OK |
| 경고 | 5 ~ 8 | ⚠️ WARN — 보석 공급 재검토 |
| 위험 | ≥ 8 | 🚨 CRITICAL — AABS 강제 보정 |

## 9. 개발 제약 및 금지사항

### BM 통화 관련

| 규칙 | 위반 결과 |
|------|-----------|
| 크레딧 → 보석 교환 로직 구현 금지 | 보석 수량 통제 붕괴 |
| 보석 잔액을 런타임에서 직접 증가 금지 (IAP 콜백 외) | 부정 보석 획득 |
| 보석 지급 이벤트를 CSV 정본 없이 하드코딩 금지 | 감사 불가 |
| VIP 일일 보석 지급량 런타임 변경 금지 | 무제한 보석 취약점 |

### 상점 Modal 관련 (마스터 스펙 §14 Rule 11)

| 규칙 | 위반 결과 |
|------|-----------|
| Stage 3 전투 중 상점 Modal 호출 금지 | SIGSEGV 크래시 |
| Skia `.dispose()` 전 Modal 오픈 금지 | GL mtrack 누수 |
| 가격 조회 시 O(N) 순회 금지 → Map O(1) 강제 | 렌더링 성능 저하 |

### Firestore 관련

| 규칙 | 내용 |
|------|------|
| 보석 잔액은 Firestore 단발성 `.set()` 으로만 동기화 | `onSnapshot` 실시간 감시 금지 |
| IAP 영수증 검증 없이 보석 지급 금지 | 결제 우회 취약점 |
| `purchaseHistory` 클라이언트 단독 기록 — 서버 검증 추후 | 현재 구조 한계 명시 |
