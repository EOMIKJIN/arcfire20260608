
## 1. 확장의 정의 (이 문서가 다루는 것)

**확장시스템** = 이미 돌아가는 은하·아크코어 운영(일일배치·교역시장·궤도·금고·점유)을 **깨지 않고** 새 월드 축을 얹는 일.

이 문서의 첫 사례는 **남부(F2 머큐리움 연합) · 북부(F4 아우렐리움 길드) 국가 수송선단**이다.  
이후 같은 종류의 확장(제3 선단, 국가 전용 정산, 시각 트래픽 분배)도 **§4 게이트**를 통과해야 한다.

**확장이 아닌 것** (여기 등록하지 않음):

- 점유 hold에 F2/F4를 넣는 일 — 대표님 잠금. 전쟁축은 BLUE/RED만.
- 대화 채널이 선단·배치를 조종하는 일 — 입≠몸.
- 신규 서브코어를 팬테온 13석으로 추가하는 일.

## 2. 현재 운영 골격 — 무엇이 이미 “플러그”인가

### 2-1. 네 축은 이미 분리되어 있다 (기반 PASS)

| 축 | 정본 | 남·북과의 관계 |
|----|------|----------------|
| **교역 국가 F** | `planet_trade_route_profile.csv` · `quadNationRouteCanon` · `GALAXY_ROUTE_POLICIES` | F2=남 · F4=북. 행성 17곳이 F를 가짐. |
| **tg_* SKU** | `item_defs` attrs `srcFactionCode`/`dstFactionCode` | F2↔F4 구간 SKU **이미 존재**. 진열 역할은 배정표 1순위. |
| **점유 hold** | `planet_occupation_seeds` BLUE/RED/NEUTRAL | 남·북 행성이어도 hold는 전쟁 오버레이. 교역 F와 **의도적 불일치**. |
| **flavor** | `planets.csv` · NPC `factionId` | `trade_coalition`/`miners_guild`는 국가가 아님. |

이 분리가 있어, “남부 행성에서 머큐리움 교역품이 돈다”는 **이미 데이터로 가능**하다.  
아크코어 일일 선단이 F2/F4 행성도 **같은 패스**로 왕복한다 (`listConvoySupplyPlanetIds`는 국가를 가리지 않음).

### 2-2. 선단·정산은 단일 운영자다 (기반 미완)

```text
일 1회 runArcCoreDailyOpsBatch
  └─ runArcCoreConvoyDailySettlementPass
        shipId = arc_daily_convoy_{kstDay}_{supplyPlanetId}
        은행   = useArcCoreTransportFleetBankStore   ← 1개
        하역   = applyConvoyUnloadVaultSettlement
                  순마진 일부 → useArcCoreVaultStore (RED≡중앙은행)
        궤도   = getConvoyShipCargoDestination → AiNpcSubCore
                  허브 렌더 예산 8척 (주둔 테이블 최소 3 예약 → 아크 수송 잔여 ≈5)
```

코드 실체:

- 계획: `arcConvoyTradePlanner.ts` — 함수명·주석이 **아크 선단 전용**
- 실행: `runArcTransportTradePass.ts` — RAM 화물 Map은 `shipId` 키라 **id만 안 겹치면** 공용 가능. 은행·하역 금고 호출은 아크 고정
- 정산 금고: `applyConvoyUnloadVaultSettlement` — `bank`+`arcVault` 인자는 있으나 **호출부가 아크 금고로 고정**
- 궤도: `AiNpcSubCore` + `listArcNpcTrafficRowsFromTables` — `arcOrbitPresenceFill`만

즉 **교역 그래프는 4국가, 선단 주체는 1국가(아크코어)** 이다.

### 2-3. 금고는 점유 5축이지, 교역 4국가가 아니다

`resolveFactionVault.ts` 라우팅:

| hold | 금고 |
|------|------|
| BLUE | 블루팀 공유 |
| RED | 아크코어(중앙은행) |
| NEUTRAL | 중립국 |
| 플레이어 독립 | 독립국 |
| *(F2/F4 국가)* | **슬롯 없음** |

마지노선 `externalFactionCodes=F2|F4`는 **전투 가중 라벨**이지 선단·금고가 아니다. **물량 숫자와 묶지 않음** (§7-3).

**금고 (대표님 잠금 2026-08-15)**: 남·북 수익은 **기존 월드 금고가 총괄**한다.  
선단 은행 = `useArcCoreTransportFleetBankStore`, 아크 몫 = `useArcCoreVaultStore`.  
원장에 `operatorId`만 남겨 나중에 배분할 수 있게 한다.  
**F2/F4 국가 금고는 남·북 국가시스템 안정화 후에만** 생성·배분. 지금 `createFactionVaultStore`로 신규 스토어를 열지 않는다.

### 2-4. 메모리·배치 계약 (확장이 깨면 안 되는 것)

- 고빈도 시세·AABS 금지. 선단 정산은 **일 1회 배치**만.
- 시작 화면 버튼에 선단 워밍 금지. 합류는 차원항로 `runContinueSessionPrewarm`.
- 신규 persist는 월드 축 vs 계정 축을 밝히고, 월드면 `purgeLocalAccountData` **제외**.
- STAGE 1 허브 렌더 예산 **`PLANET_HUB_ORBIT_CAPITAL_RENDER_MAX = 8`**. 주둔 테이블 **최소 3슬롯 예약** 후 아크 수송이 잔여를 쓴다. 남·북 함선을 더하면 이 예산과 싸운다. (헌법 문구의 「동시 5척」은 구 계약 · 실코드는 8+예약 3)
- 팬테온 **12 서브코어 고정**. 선단 확장은 `AiEconomySubCore`·기존 일일배치·`AiNpcSubCore` 테이블 행으로만.

## 3. 사례 — 남부·북부 국가 수송선단 병렬 운용

### 3-1. 판정표

| 층 | 지금 바로 병렬? | 이유 |
|----|-----------------|------|
| 교역 SKU·F2/F4 행성 | **예** | 프로필·attrs·배정표가 이미 남/북 행성을 가리킴 |
| 일일 왕복 정산 | **조건부** | 패스를 국가 필터로 나누면 됨. 지금 전 행성 1회 순회는 **아크 단독** |
| 선단 금고 | **월드 총괄** | 신규 F2/F4 금고 없음. 기존 선단은행+아크금고 + `operatorId` 태그. 안정화 후 배분 |
| 무역 수수료 | **점유 따름** | 남부 행성이 BLUE hold면 수수료는 블루 금고. 선단 국적과 무관 |
| 궤도 연출 | **1단계 동일 파이프** | 아크와 같은 `AiNpcSubCore`·화물 목적지. 허브 8슬롯 공유. 색·태그는 후속 |
| 마지노선 | **숫자 비연동** | F2\|F4는 전투 가중 라벨만. HARD와 선단 물량을 한 숫자에 묶지 않음 |
| 대화/아크코어 입 | **연동 금지** | 선단은 몸. 채팅이 출항을 지시하면 안 됨 |

### 3-2. 병렬이 되려면 필요한 계약 (구현 전 설계)

운영자를 **데이터**로 둔다. 코드에 `if (south) …` 복제를 두지 않는다.

```text
convoy_operator.csv (가칭)
  operatorId        arc_core | mercurium | aurelium
  nationId          mega_crimson_legion | mega_mercurium_coalition | mega_aurelium_guild
  tradeFactionCodes F3 | F2 | F4          ← 출발 행성 필터
  fleetBankKey      월드 persist 키 (1단계=아크 선단은행 공용)
  dailyShipIdPrefix 일일 배치 shipId (운영자별 prefix, 충돌 금지)
  hubVisual         same_as_arc  (1단계 필수 · 정산만 금지)
  hubVisualSlots    기존 8슬롯 예산 안에서 분배 (신규 풀 금지)
  shareOfDailyGross 0..1  같은 행성 재고·매출 cap을 나눌 쿼터
  macroColorTag     later (월드맵 색·태그 후속)
```

일일배치 한 슬롯 안에서:

```text
for operator in convoy_operator (enabled)
  supplyPlanets = listConvoySupplyPlanetIds
                  .filter(p => profile(p).F ∈ operator.tradeFactionCodes)
  executeRoundTrip(operator, shipId, planet)   // 은행·쿼터만 다름
```

**같은 시장 재고**를 두 선단이 쓰면 아크코어가 먼저 비운다.  
쿼터 없으면 “병렬”이 아니라 **약탈**이다.

### 3-3. 페이즈 (대표님 잠금 반영 · 구현은 별도 지시)

| Phase | 내용 | 아크코어 영향 |
|-------|------|----------------|
| **P0 관측** | 운영자 레지스트리 CSV만. 정산·연출은 계속 아크 1선단. F2/F4 출발 행성 **리포트** | 없음 |
| **P1 동일 운용** | 일일배치 운영자 루프 + **아크와 같은 궤도 파이프**. 월드 금고 총괄 + `operatorId`. 재고·슬롯 쿼터 필수. 색·태그 없음 | 시장 cap·허브 8슬롯 공유. PSS/GL 실측 |
| **P2 매크로 식별** | 월드맵 다른 색·태그. 허브 연출 파이프는 유지 | UI만. 레이아웃 상수 금지 |
| **P3 국가 금고 배분** | 남·북 국가시스템 **안정화 후** F2/F4 금고 생성. 원장 `operatorId`로 이관 | persist 신규 · purge 월드 축 |
| **P4 마지노선** | **하지 않음.** HARD와 선단 물량을 숫자로 묶지 않음 | — |

1단계는 **정산만이 아니다.** 아크코어 수송선단과 **같은 몸(일일 왕복) + 같은 궤도 비주얼**이다.  
함선 풀을 두 배로 늘리지 않는다. 기존 `getConvoyShipCargoDestination` → `AiNpcSubCore` → 허브 8슬롯에 **운영자 shipId가 합류**한다. 구분은 나중에 매크로 색·태그로만 한다.

### 3-4. 하면 안 되는 확장

- `runArcCoreConvoyDailySettlementPass`를 복사해 `runMercuriumConvoy…` / `runAureliumConvoy…` 두 파일 추가 — 시장·캡·hydrate 레이스 재발
- 남·북 선단용 **13번째 서브코어**
- 매 틱 선단 AI (`onWallTick`에서 매입)
- 점유를 F2/F4로 바꿔 수수료를 국가 금고로 보내는 우회
- 대화 에이전트가 “출항하라”고 배치를 트리거

## 4. 모든 확장시스템에 적용하는 공통 게이트

신규 확장은 코딩 전 아래를 설계안에 기입한다. 하나라도 **불가**면 구현 보류.

| # | 게이트 | 합격 |
|---|--------|------|
| G1 | **축 선언** | 교역 F / 점유 hold / flavor / 운영자 / 대화 중 **어느 축인지** 한 줄 |
| G2 | **기존 정본 재사용** | 새 스토어·새 루프 전에 일일배치·`createFactionVaultStore`·CSV 레지스트리부터 |
| G3 | **서브코어** | 12석 유지. 명령은 버스, 실행은 기존 서브코어 또는 배치 패스 |
| G4 | **주기** | 틱 금지. 벽시계 일 1회 또는 이벤트 1회 |
| G5 | **메모리** | `[pss-pre-dev]` 3줄. persist coalesce. 허브 시각은 렌더 예산 8(주둔 3예약) |
| G6 | **부트** | 시작 화면 비활성. 차원항로 합류만 |
| G7 | **purge** | 월드 축 vs 계정 축 명시 |
| G8 | **공유 자원** | 시장 재고·궤도 슬롯·일일 `convoyGrossCredits` cap을 **쿼터로 나눔**. 복수 선단 무한 경쟁 금지 |
| G9 | **입≠몸** | 확장 운용이 채팅/허브 대화에 의존하지 않음 |
| G10 | **기존값** | 확정 CSV·곡선 변경은 대표님 재확인 |

남·북 선단에 적용한 예:

| 게이트 | 판정 |
|--------|------|
| G1 | 운영자 축 (교역 F는 필터만) |
| G2 | 일일배치·배정표·금고 팩토리 재사용 |
| G3 | 새 서브코어 불필요 |
| G4 | 일 1회 |
| G5 | P1부터 허브 8슬롯 공유 + GL/PSS. 신규 persist 스토어 없음(월드 금고 공용) |
| G6 | 배치에만 |
| G7 | 선단 금고 = 월드 축 |
| G8 | **미구축 — P1 필수 선행** |
| G9 | 준수 |
| G10 | 배정·F 코드 재배치 없음 (필터만) |

## 6. 잔여 리스크 (현재 정리분과의 관계)

2026-08-15 4대 국가 정렬 이후:

- F↔지역·국호는 안정. **확장의 지리 키로 써도 된다.**
- 배정표와 attrs F는 여전히 다른 축이다. 선단 필터는 **배정 행성 프로필 F**를 쓴다 (attrs F만 믿으면 출발지가 빗나감).
- 역할 해석은 배정 1순위. 운영자 패스도 `resolveTradeRouteRole`을 그대로 쓴다.

이 리스크는 “남·북 선단을 못 만든다”가 아니라, **운영자 필터를 배정 행성 기준으로 짜야 한다**는 뜻이다.
