## 1. 증상

개척선이 신규 사령부를 세워 **요새 베이스**가 블루 진영에 편입됐다. 이 성계는 **서쪽에 인접 성계가 없다.** 결과적으로 국경 영역이 지도 왼쪽 외곽까지 거대하게 뻗어 나간다(첨부 실기 화면).

수정 시도 과정에서 기존 Voronoi 국경선까지 망가지고 코드가 엉켰다. **가상 성계 추가·영역 잘라내기 모두 실패**했다.

---

## 2. 원인 — 3가지, 그중 2개는 요새 베이스와 무관한 별개 결함

### 원인 A (근본) — Voronoi에는 「영향 반경」 개념이 없다

`buildGalaxyTerritoryVoronoi.ts:323-334`

```ts
const clipBounds = computeClipBounds(sites, mapBounds);          // 사이트 bbox + 48
const voronoi = delaunay.voronoi([x0, y0, x1, y1]);
const poly = voronoi.cellPolygon(i);                              // ← 크기 제한 없음
```

Voronoi 셀은 **이웃 사이트가 나타날 때까지 무한히 뻗는다.** 요새 베이스 서쪽에 가까운 사이트가 없으므로, 셀의 서쪽 경계는 **훨씬 멀리 있는 사이트(서쪽 팔 관문 등)와의 이등분선**까지 밀려난다. 클립 사각형에 닿으면 거기서 잘린다.

즉 **기하학적으로는 «정상»이고 의미상으로만 틀렸다.** 「이 성계의 세력권이 어디까지인가」를 Voronoi 하나로 결정하려 한 것이 설계 오류다. Voronoi가 답할 수 있는 것은 **「두 성계 사이 경계가 어디인가」**뿐이다.

> 대표님이 관찰하신 «중간기점을 그리는 로직이 왼쪽에 없는 성계 때문에 뻥 뚫려»가 정확히 이 현상이다.

### 원인 B (치명 · 별개 버그) — 채움과 국경선이 **서로 다른 Voronoi**로 그려진다

두 빌더가 **다른 클립 사각형**으로 각자 Voronoi를 만든다.

| 빌더 | 클립 사각형 | 근거 |
|---|---|---|
| 영역 채움 `buildGalaxyTerritoryVoronoi` | **사이트 bbox + 48** | `:323` `computeClipBounds(sites, mapBounds)` |
| 국경선 `buildGalaxyBlueRedVoronoiBorders` | **mapBounds 원본** | `:77` `delaunay.voronoi([bounds.x0, …])` |

호출부(`computeGalaxyMapTerritoryVoronoiModel.ts:100-107`)는 둘 다에 `input.mapBounds`를 넘기는데, 한쪽만 내부에서 축소한다.

**내부 성계는 두 결과가 같다**(클립은 외곽 셀만 바꾸므로). 그러나 **변경 성계에서는 셀 모양이 서로 다르다.** 그 결과:

- 채움은 잘렸는데 국경선은 남거나, 그 반대가 된다
- `isClipHullEdge()`가 **서로 다른 사각형**을 기준으로 판정해 한쪽에서만 외곽 변이 제거된다
- 한쪽을 고치면 다른 쪽이 어긋난다 → **«고치느라 기존 국경선이 망가진» 직접 원인**

**이 결함은 요새 베이스와 무관하게 이미 존재했다.** 변경 성계가 생기면서 드러난 것뿐이다.

### 원인 C (불안정) — 클립 사각형이 성계 점령 상태에 따라 변한다

`computeClipBounds`는 **사이트 bbox**로 사각형을 만든다. 사이트 집합이 바뀌면(신규 해금·개척) **사각형 전체가 움직이고, 모든 변경 셀 모양이 동시에 바뀐다.**

가상 성계를 추가했을 때 효과가 없었던 이유가 이것이다 — 가상 사이트가 bbox를 넓혀 **클립 사각형까지 같이 밀려났다.**

## 3. 해결안 — 「영향 반경 클램프」

### 3-1. 핵심 원칙

> **Voronoi는 «경계의 위치»만 결정하고, «세력권의 크기»는 별도 규칙이 정한다.**

각 성계의 영역을 다음으로 정의한다.

```text
영역_i  =  Voronoi 셀_i  ∩  원(중심=성계_i, 반지름=R)
```

### 3-2. 왜 이 방법이 맞는가

| 요구 | 충족 방식 |
|---|---|
| **다른 성계에 영향 없음** | 셀을 «깎는» 연산이라 **이등분선이 전혀 움직이지 않는다.** 내부 성계는 셀이 R보다 작아 `셀 ∩ 원 = 셀` — **결과가 1픽셀도 안 바뀐다.** 「전체 다른 성계까지 엉키게」가 구조적으로 불가능해진다 |
| **이웃 유무와 무관** | 왼쪽에 성계가 있든 없든 반지름 R에서 멈춘다. 변경·고립 성계에 특수 처리가 필요 없다 |
| **기존 파이프라인 재사용** | 원을 24~32각형으로 근사하면 **볼록 다각형끼리의 교집합 = 볼록 다각형**. `polygonAreaCentroid`·`polyToPointsAttr`·라벨 앵커가 **수정 없이 그대로 동작**한다 |
| **연출이 설정과 맞음** | 변경 세력권 바깥쪽이 둥글게 마무리된다 — 「영향력이 미개척 공간으로 흐려진다」는 세계관과 일치 |

### 3-3. 반지름 R 설계

- **반드시 월드 좌표로 정의하고 `toScreen`으로 환산할 것.** 화면 픽셀로 잡으면 **줌할 때 영토 모양이 변한다.** 현재 `buildVoronoiSites`가 `toScreen`을 먼저 적용하므로, 배율 인자를 함께 넘기거나 사이트에 월드 좌표를 같이 실어야 한다 — **설계 시 반드시 결정할 항목.**
- **v1 권장**: 전 성계 공통 상수. 값은 **성계 간 평균 간격 × 1.2~1.5**. 내부 셀은 건드리지 않으면서 변경만 깎이는 값이다.
- **v2 확장(선택)**: 개척 단계·시설 수준에 비례해 R을 키운다 → 「개척할수록 세력권이 넓어진다」는 게임적 보상이 지도에 드러난다. **v1에서는 하지 말 것.**

### 3-4. 국경선 분류를 나눈다

지금은 국경선이 `owners.length === 2`(두 셀이 공유하는 변)일 때만 그려진다(`buildGalaxyTerritoryVoronoi.ts:387`, `buildGalaxyBlueRedVoronoiBorders.ts:107`). 클램프 도입 후에는 변을 **두 종류로 구분**해야 한다.

| 종류 | 정의 | 처리 |
|---|---|---|
| **내부 경계** | 두 셀이 공유하는 이등분선 | **현행 유지** — 진영 색(블루/레드/접경/독립) 그대로 |
| **외곽 경계** | 이웃이 없어 원호로 잘린 변 | **실선 국경 금지** — 페이드/점선/무선 처리 |

> **국경선은 «반대편에 누군가 있다»는 뜻이다.** 미개척 공간 쪽에는 반대편이 없으므로 선을 그으면 안 된다. 현재 화면에서 빈 우주를 향해 굵은 파란 선이 그어진 것이 어색한 이유가 이것이다.

## 4. 기존 시도가 실패한 이유 (재시도 금지 근거)

### 가상 성계 추가 — 실패 원인 4가지

가상 사이트는 Delaunay뿐 아니라 **모든 소비자에 동시에 들어간다.**

1. `computeClipBounds` → **bbox가 넓어져 클립 사각형이 밀린다**(원인 C)
2. `edgeOwners` → **유령 국경선**이 생긴다
3. `cellMetrics` + `UnionFind` → **국가 라벨 묶음이 잘못 갈리거나 합쳐진다**(`buildOccupationLabels`)
4. `fills` → 진영이 neutral이 아니면 **유령 영역이 칠해진다**

네 곳 전부에서 제외해야 하는데, 제외 조건이 하나 늘 때마다 분기가 늘어난다. **코드가 엉킨 경로가 정확히 이것이다.**

### 클립 사각형 축소 — 실패 원인

사각형은 **전역**이다. 요새 베이스 하나를 잡으려고 줄이면 **반대편 성계들도 같이 잘린다.** 국소 문제에 전역 도구를 쓴 것이다.

**추가 권장 케이스**

1. **고립 성계 단독** — 한쪽에 이웃이 없는 사이트의 셀 면적이 `π·R²` 이하인가
2. **클램프 전후 내부 셀 동일성** — 내부 성계들의 `points` 문자열이 **완전히 같은가**(1픽셀도 안 변해야 함)

4. **줌 불변성** — 배율을 바꿔도 영토의 **월드 좌표 모양이 동일**한가 (§3-3)

# 8. 국경선 판정 규칙 — 확정 (대표님 지시 · 2026-09-24)

```text
status=APPROVED
지시=대표님 「잘린 쪽은 안 그리는 게 맞는데, 성계가 확실히 있는 쪽은 그려야 일관성 있지 않은가」
판정=대표님 말씀이 맞다. 현재 이웃 쪽까지 안 그려지는 것은 의도가 아니라 버그.
```

## 8-1. 현상 — 채움은 정상, 국경선만 고장

| 항목 | 현재 | 판정 |
|---|---|---|
| 요새 베이스 채움 | 반경으로 잘려 정상 표시 | ✅ 정상 |
| 서쪽(빈 우주) 외곽선 | 안 그려짐 | ✅ 정상 |
| **이웃 성계가 있는 쪽 국경선** | **안 그려짐** | ❌ **버그** |

## 8-2. 원칙 — 「잘렸는가」가 아니라 「반대편에 주인이 있는가」

**규칙은 두 줄이고 예외는 없다.**

```text
1. 변이 이등분선이고 «양쪽 원 안»에 있다  →  실선 (진영 색)
2. 그 외 모든 변                          →  페이드
```

> 「이웃인데 멀어서 사이에 빈 공간이 끼는」 경우는 **별도 규칙이 아니다.** 1번을 만족하지 못하므로 2번으로 자동 처리된다 — 양쪽 다 페이드로 끝난다.

**이 규칙이 맞는 이유는 기존 색 체계에 이미 들어 있다.** `buildGalaxyBlueRedVoronoiBorders.ts`의 국경선 색(노랑=blue↔red 접경 · 파랑=blue↔neutral · 빨강=red↔neutral · 녹색=independent)은 전부 **「양쪽에 누가 있는가」**를 인코딩한다. 반대편이 빈 우주면 **인코딩할 관계가 없어 색을 정의할 수 없다.** 선을 긋지 않는 것이 기존 설계와 일관된 유일한 선택이다.

## 8-3. 버그 원인 — 좌표로 변을 짝짓는데 클램프가 한쪽만 자른다

| 위치 | 코드 | 문제 |
|---|---|---|
| `buildGalaxyBlueRedVoronoiBorders.ts:105` | `const key = edgeKey(a, b)` | 변을 **좌표 문자열**(`toFixed(2)`)로 짝짓는다 |
| 〃 `:122` | `if (owners.length !== 2) continue;` | 짝을 못 찾으면 **버린다** |
| `clampGalaxyVoronoiInfluenceCell.ts:140` | `if (allVerticesInsideDisk(...)) return poly;` | **원 안이면 원본 그대로 반환** |

```text
요새 베이스 셀 → 원 밖으로 나가 잘림   → 변 끝점이 «이동»
이웃 셀        → 원 안이라 원본 반환   → 변 끝점 «그대로»
```

**같은 이등분선인데 두 셀이 서로 다른 좌표를 갖는다.** 키가 달라져 각각 `owners.length === 1`이 되고 **둘 다 버려진다.** `buildGalaxyTerritoryVoronoi.ts:353`도 동일 패턴이다.

## 8-4. 수정 방향 — 좌표 대신 «성계 쌍»으로 짝짓는다

좌표 일치에 기대는 구조를 버린다. d3-delaunay가 이미 이웃 관계를 안다.

```text
Delaunay 이웃인 두 성계 (i, j)에 대해:
  공유 이등분선 구간을 «클램프 이전» 셀에서 구한다   ← 양쪽이 반드시 같은 구간
  그 구간을 «원(i) ∩ 원(j)» 로 자른다                ← 대칭
  남은 구간이 있으면 → 국경선 (owners = {i, j})
  비면                → 국경선 없음 (2번 규칙으로 페이드)
```

**대칭 연산이라 비대칭 절단이 원천적으로 불가능**하고, 좌표 비교가 아예 사라진다.

- **채움(fill)은 현행 유지** — 클램프된 폴리곤 그대로. 이미 정상 동작한다.
- **R은 건드리지 않는다** — `VORONOI_INFLUENCE_RADIUS_NN_MUL = 1.35`는 두 성계가 **평균 최근접 간격의 2.7배 미만이면 맞닿게** 하는 값이다. 「떨어짐」은 요새 베이스 서쪽처럼 **진짜로 이웃이 없는 곳에서만** 생긴다. **국경선을 그리려고 R을 키우지 말 것** — 그것은 §2 원인 A의 분할 모델로 되돌아가는 것이고, 요새 베이스 문제가 형태만 바꿔 재발한다.

## 8-5. 검증 추가

1. **이웃 쪽 국경선 생성** — 클램프된 셀과 클램프 안 된 이웃 사이에 **국경선 segment가 존재**하는가 (이번 버그의 직접 회귀 케이스)
2. **빈 우주 쪽 미생성** — 이웃이 없는 방향에는 segment가 **없는가**
3. **대칭성** — i→j로 구한 구간과 j→i로 구한 구간이 **동일 좌표**인가
4. **떨어진 쌍** — 거리가 2R을 넘는 두 성계 사이에 segment가 **없는가**
5. 기존 `blue/red 대륙 라벨 회귀 없음`은 계속 통과해야 한다
