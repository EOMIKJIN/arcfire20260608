## 2. 핵심 결정 3가지

### 결정 A — 기본/향상 관계
**오퍼레이터 대화가 기본. 담당자 대화는 컨택 대상 퀘스트만.**  
컨택 대상: `type=delivery` · `(buy_goods|deliver_cargo)+reach_*` · `requiresClearContact=1` · 명시 `clearNpcCaptainId`.  
탐험·전투·단순 이동·구매만은 목적지가 있어도 **오퍼레이터**. 담당자를 못 찾으면 오퍼레이터.

### 결정 B — 배정 시점 = 수락 시(스냅샷)
행성 담당자는 점령전으로 **런타임에 바뀔 수 있다**(`mergeRuntimeGovernorAssignment`). 완료 시점에 매번 새로 조회하면, 수락할 땐 우호 관문순찰대장이었는데 퀘스트 진행 중 그 행성이 점령당해 적대 지휘관으로 바뀐 채 "물건 잘 받았다"고 대사하는 모순이 생긴다. 그래서 **수락 순간 담당자 id를 `MissionProgress`에 스냅샷**해두고, 완료 시엔 그 스냅샷만 쓴다(대표님 지시 "수락 시부터 배정"과 정확히 일치).

### 결정 C — 목적지 행성 해석 규칙
| 미션 objective 마지막 타입 | 목적지 행성 해석 |
|---|---|
| `reach_planet` | `objective.targetId`가 이미 행성 id — 그대로 사용 |
| `reach_system`(배달·이동) | 해당 시스템의 첫 번째 행성(`GALAXY_SYSTEMS_PRECOMPUTED[systemId].planets[0].id`) — 지금 데이터 기준 시스템당 행성 0~1개라 모호성 없음. 행성이 없으면 담당자 없음(오퍼레이터 폴백) |
| `defeat_enemy`/`buy_goods` 단독(목적지 없는 미션) | 담당자 없음 — 오퍼레이터 폴백(그대로) |

## 3. 데이터 모델 변경

### 3-1. `MissionProgress`에 필드 1개 추가(optional)
```ts
export interface MissionProgress {
  missionId: string;
  status: MissionStatus;
  objectives: Record<string, boolean>;
  startedAt?: number;
  completedAt?: number;
  /** 수락 시점 스냅샷 — 완료 대화에 응답할 목적지 담당 NPC. 없으면 오퍼레이터 폴백. */
  assignedClearNpcCaptainId?: string;
}
```
optional이라 기존 세이브(`arcfire_missions_v1`)는 `undefined`로 읽혀 자동으로 폴백 — **마이그레이션 스크립트 불필요**.

### 3-2. `IngameDialogTextContext`에 담당자 이름 토큰 추가
```ts
export type IngameDialogTextContext = {
  missionTitle?: string;
  missionTitleEn?: string;
  /** 신규 — [담당자] 토큰 + 동적 초상 오버라이드용 */
  npcCaptainId?: string;
  npcName?: string;
  npcNameEn?: string;
};
```
`applyTextContext`에 `text.replace(/\[담당자\]/g, npcName)` 한 줄 추가. `resolveIngameDialogPortraitSource`도 `context.npcCaptainId`가 있으면 씬 CSV의 고정 `speakerNpcCaptainId`보다 우선하도록 한 줄 분기 추가(제네릭 템플릿 씬 1개로 모든 담당자를 표현하기 위한 핵심 포인트).

## 4. 씬(대화) 콘텐츠 — 제네릭 템플릿 2종으로 시작

미션마다 담당자별 대사를 손으로 다 쓰면 CSV 수십~수백 줄이 필요해 확장성이 없다. **먼저 제네릭 템플릿 2종**(배달 수령 / 도착 보고)만 만들고 `[담당자]`·`[미션제목]`·`[닉네임]` 토큰으로 어떤 담당자·미션에도 재사용한다. 특정 미션에 맞춤 대사가 필요해지면 그때 `mission_clear_${missionId}` 특정 씬으로 개별 오버라이드(기존 우선순위 규칙 그대로 유지).

```
mission_clear_npc_delivery   — "[담당자]: 화물 확인했다. 「[미션제목]」 수고했다, [닉네임]."
mission_clear_npc_arrival    — "[담당자]: 여기까지 오느라 고생했군. 「[미션제목]」 확인됐다."
```

씬 선택 우선순위(신규):
```
1. mission_clear_${missionId}          (기존 — 미션별 맞춤 씬. 최우선 그대로 유지)
2. progress.assignedClearNpcCaptainId 있고
   해당 미션이 delivery류 → mission_clear_npc_delivery
   그 외 도착류           → mission_clear_npc_arrival
3. mission_clear_default               (기존 폴백 — 오퍼레이터)
```
1번(미션별 맞춤 씬)이 여전히 최우선이라 **기존 mission_001~003처럼 이미 손으로 쓴 완료 대사는 전혀 안 바뀐다** — 이번 기능은 "맞춤 씬이 없는 나머지 다수 미션"에 자동으로 담당자를 붙여주는 레이어다.

## 5. 이번 턴에 준비한 것 (신규 파일만, 기존 파일 무수정)

- `src/missions/resolveMissionClearNpcContext.ts` — 목적지 행성 해석(§2 결정 C) + governor 조회(`talkEnabled` 확인) + 스냅샷용 캡틴id/씬id 산출을 순수 함수로 구현. `Mission`/`PlanetGovernorCommanderRow`만 입력받고 스토어·CSV I/O 없음 — 테스트 용이.
- `src/missions/resolveMissionClearNpcContext.test.ts` — reach_planet 직접 지정 / reach_system→행성 해석 / governor 없음(폴백) / talkEnabled=false(폴백) / defeat_enemy 단독(폴백) 5케이스.

- [ ] `MissionProgress.assignedClearNpcCaptainId` optional 추가 — 구세이브 로드 회귀 없음(신규 테스트)
- [ ] 수락 3함수 모두 스냅샷 기록 확인
- [ ] `resolveMissionClearDialogSceneId` 3단 우선순위 — 미션별 맞춤 씬 있는 기존 3개 미션(001~003) 결과 불변 확인(회귀 테스트)
- [ ] governor `talkEnabled=false`/미배정 행성 → 오퍼레이터 폴백 확인
- [ ] `[담당자]` 토큰 미주입 시(구 세이브·오퍼레이터 경로) 빈 문자열로 깨지지 않는지 확인
- [ ] `tsc` · 기존 미션 테스트 전체 재실행(회귀 0건)

## 7. 리스크·롤백

- 전부 optional 필드 + 폴백 체인이라 **신규 기능이 아무것도 없어도 기존 동작과 100% 동일** — 킬스위치 없이도 안전하지만, 원하면 §4 2번 분기 자체를 주석 처리하는 것만으로 즉시 오퍼레이터 전용으로 복귀 가능.
- 유일한 실사용 리스크는 **콘텐츠 톤 불일치**(governor 캐릭터 성격과 "화물 확인했다" 같은 제네릭 대사가 안 맞는 경우) — 코드 리스크가 아니라 라이팅 검수 필요.

## 8. 김팀장 구현 (2026-08-24)

- `shouldAssignClearContact` — 위 게이트. 테스트에 탐험/전투/구매만 = 오퍼레이터 고정.
- `missions.csv` `clearNpcCaptainId` · `requiresClearContact`. `mission_001`·`tq_oth_05`만 접선 플래그. 기존 제목·설명 유지.
- ArcCore 인스턴스 materialize 시 배달·접선만 `clearNpcCaptainId` + 설명에 `발송지 담당`/`목적지 담당` 한 줄.
- 허브 `[대화]`는 활성 컨택 퀘스트의 **목적지 행성 담당만** `quest_contact`로 올림.

- 맞춤 클리어씬(`mission_001`~`003`) 우선순위 유지.
