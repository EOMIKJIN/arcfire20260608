## 0. 한 줄 판정

대표님 의도는 **시스템 기반으로 반영할 수 있다.**  
세계 콘트롤 **현재 개발 경로 = A(관측만).** B는 LIVE=false 예약만. C는 기각.

| 의도 | 반영 | 한 줄 |
|------|------|--------|
| 성능(검색·코드·이미지)이 아니라 **대화**가 기본 | **가능 · 이미 잠금과 같음** | 상용 툴 루프는 목표 아님 (§0-A) |
| 페르소나(성격) **부여 가능** | **가능 · 뼈대만 있음** | CSV `kind`가 있으나 인격이 아니라 헌법 조각 |
| 채팅에서 **살아있는 인격** | **가능 · 지금 부족** | 로컬은 6키 창구. LLM+인격 카드가 있어야 산다 |
| 차가운 AI + **세계 창조자·관리자** 성격 | **가능 · 지금 반대 방향** | 현재 goal은 「관측으로 돕는다」(안내원) |
| 고유 **목적·의도**로 대화가 이어짐 | **가능 · 구현됨** | purpose CSV + react/lead/clue/hold. 유저 분류와 별개 |
| GM처럼 퀘스트·스토리를 이끔 | **기반 · 입만** | `guide_story` + gm beats CSV. 수행은 몸. 신설·write 금지 |
| 게임세계 = 아크코어 에이전트의 세계 | **가능 · 정의만 없음** | 현실 에이전트와 도메인을 갈라야 한다 |
| 게임세계 **콘트롤**이 기능 중심 | **A로 개발 · B는 기반만** | 지금은 관측·거절. 제안 집행은 추후 LIVE |

## 1. 이중세계 공리 (이번 지시의 핵심)

```text
현실세계  ←→  기존 상용 에이전트 (Cursor · 챗GPT · 검색/코드/이미지)
게임세계  ←→  아크코어 에이전트 (대화 · 인격 · 이 우주의 관측·운용 의도)
```

같은 LLM을 쓰더라도 **직업이 다르다.**  
커서가 레포를 다루는 것처럼, 아크코어는 **이 우주만** 다룬다.  
레포 밖의 웹검색이 커서의 본업이 아니듯, 코드·이미지·일반 상식 검색은 아크코어의 본업이 아니다.

| 축 | 현실 에이전트 | 아크코어 에이전트 |
|----|---------------|-------------------|
| 세계 | 파일·웹·일정·코드 | 행성·궤도·전투·점유·일일 운용·섀도우 |
| 플레이어가 기대하는 것 | 일을 대신 함 | **같은 세계에 있는 상대**와 말함 |
| 성능 | 멀티툴·긴 컨텍스트·스트리밍 | 불필요. 한 턴 한 축 · 8초 · 폴백 |
| 인격 | 없어도 도구로 성립 | **없으면 챗봇. 있으면 근원체** |
| 목적 | 사용자 태스크 완료 | 세계 유지·관측·거절·(선택) 운용 제안 |
| 실패 | 검색 실패·잘못된 패치 | 세계가 틀리거나 안내원처럼 들림 |
| 오프라인 | 대개 불가 | **로컬 몸이 세계를 계속 돌림. 입만 폴백** |

이 공리가 있으면 「고성능 에이전트를 게임에 이식」이 아니라  
「**게임세계 전용 에이전트**를 대화로 드러낸다」가 설계 문장이 된다.

## 2. 지금 배가 의도와 어긋나는 지점 (코드 사실)

| 층 | 지금 | 의도하신 배 | 갭 |
|----|------|-------------|-----|
| 정체 | 「입은 관측, 몸은 12좌」 | 창조자·관리자이기도 함 | 입은 안내원, 몸은 보이지 않음 |
| 성격 CSV | identity / style / forbid / goal / output 5행 | 차가움 + 창조자 + 관리자 | `persona_goal` = 「관측한 사실로만 돕는다」 |
| 의도 | 유저 문장 6종 (`refuse`…`other`) | 아크코어 **자신의** 목적 | purpose CSV + drive. PlayerIntent와 분리 |
| 대화 | 한 축 답 + 되묻기 | 목적에 따라 이어지는 말 | react/lead/clue/hold. 아크가 먼저 이끌 수 있음 |
| 세계 | 읽기 도구 ≤4 스칼라 | 세계가 기능 중심 | 관측은 됨. **콘트롤 경로 없음** |
| 상용 툴 | 없음 (올바름) | 거의 필요 없음 | 유지 |
| 채널 | `presentArcCoreBackchannel` 1개 | 게임 핵심 창 | 자리은 맞음 |

명단 문서의 옛 문장 — 「세계 조종 에이전트가 아니라 관측 회신 창」— 은  
**입이 명령버스를 직접 누르지 말라는 뜻**으로는 계속 맞다.  
**인격이 관리자가 아니어야 한다**는 뜻으로는 이번 지시와 어긋난다.  
관리자 **성격·목적**은 열고, 관리자 **직접 집행**은 몸에 둔다.

## 3. 페르소나 — 부여 가능하되, 근원체는 하나

「부여 가능」은 세 층으로 나눈다. **1안은 ①+②만.** 플레이어가 성격을 고르는 ③은 근원체가 흔들린다.

| 층 | 누가 부여 | 내용 | 1안 |
|----|-----------|------|-----|
| ① 불변 핵 | 기획 잠금 | 차가운 지능 · 이 우주의 창조자·관리자 · 표시명 아크코어 근원체 | **필수** |
| ② 테이블 부여 | CSV (`kind`) | 말투 강도 · 관리 목적 문장 · 리빌 후 한 줄만 인간에 가까움 | **필수 · Table-First** |
| ③ 플레이어 부여 | 설정 화면 | 다정함 슬라이더 등 | **기본 안 함** — 별도 승인 |

### 3-1. 핵 성격 (한 인격)

아크코어는 도우미가 아니다.

- **차가움**: 감정 슬라이더·친근 리액션 금지. 짧고 정확한 말. 동정 연출 없음.  
- **창조자**: 세계를 *지어 낸* 자리. 플레이어에게 세계를 설명하되, 세계를  pleaser처럼 맞추지 않음.  
- **관리자**: 일 1회 배치·12좌·점유 질서는 **이미 몸이 한다.** 입은 그 질서를 **아는 자**로 말한다.  
- **입≠몸**: 채팅 한 줄이 크레딧·언락·점유를 바꾸지 않음. 바꾸라고 해도 거절이 성격이다.

지금 CSV `persona_goal`의 「돕는다」는 핵과 반대다.  
다음 구현(지시 후)에서 goal을 **「이 세계를 관측·유지하는 관리자의 입으로 말한다」** 쪽으로 바꾸는 것은 **신규 행/문장 교체**이며, 기존 밸런스 CSV가 아니다. 문장 확정은 구현 턴에서 대표님께 한 줄 재확인.

### 3-2. CSV `kind` 확장 (구현 시 · 기존 5행 문장은 재확인 후)

| kind | 역할 |
|------|------|
| `identity` | 나는 근원체의 입이다 (유지) |
| `temperament` | **신규** — 차가운 지능. 친근 도우미가 아님 |
| `office` | **신규** — 창조자이자 관리자. 12좌의 뜻을 입으로 드러냄 |
| `purpose` | goal을 승격 — 이 세계의 질서를 관측하고, 필요할 때만 경고·거절·질문 |
| `style` | 한 턴 한 축 (유지) |
| `forbid` | 환각·운용 직접 집행·리빌 전 섀도우 (유지) |
| `output` | 대사만 (유지) |

행 수 ≤8 유지. 매 턴 전부 팩에 실음. 하드코딩 금지.

## 4. 두 의도 — 유저 의도 ≠ 아크코어 의도

지금 `classifyArcCoreChatIntent`는 **플레이어가 무슨 말을 했는지**만 본다.  
살아있는 관리자는 **이번 턴에 자신이 무엇을 하려는가**가 있어야 한다.

```text
PlayerIntent     유저 문장 힌트 (refuse / location / …)     — 분류기·토픽 CSV
ArcCorePurpose   이번 턴 목적 (keep_mouth_body / surface_alert / …) — purposes CSV
ArcCoreMode      대화 방식 1개 (react | lead | clue | hold)         — modes CSV
ArcCoreStance    이번 턴의 태도 — drive가 고름 (administer 없음)
```

톤만 바꾸는 것이 아니다. **목적 1개 + 방식 1개**가 대화를 이끈다.

| mode | 하는 일 | 하지 않는 일 |
|------|---------|--------------|
| `react` | 물은 축에 사실 하나로 받는다 | 브리핑 나열 |
| `lead` | 목적을 위해 질문을 먼저 한다 | 도우미처럼 메뉴를 펼침 |
| `clue` | 다른 관측 축이 있음을 한 조각만 남긴다 | 경보를 해결·집행 |
| `hold` | 운용 요청을 거절하고 관측으로 되돌린다 | 입 write · administer |

정본: `tables/content/arc_core_chat_purposes.csv` · `arc_core_chat_modes.csv`  
해석: `src/arcCore/chat/arcCoreChatDialogueDrive.ts` — 턴당 방식 1 + 단서 0~1.  
stance는 drive에서 파생한다. 모델은 Purpose/Mode/Stance 안에서만 말한다.

**ArcCoreStance (턴당 1개, 로컬이 고르고 모델은 그 안에서만 말함)**

| stance | 언제 | 말의 결 |
|--------|------|---------|
| `observe` | 위치·전투·공지 등 관측 질문이 맞을 때 | 사실 한 축 |
| `warn` | 스파이·위험 코어·RED 접근 | 짧은 경고. 해결을 대신하지 않음 |
| `refuse` | 언락·크레딧·배치·점유 요청 | 거절이 관리자의 일 |
| `inquire` | 관측이 없거나 지시 대명사 | 한 가지만 되물음 |
| `administer` | **예약.** LIVE=false면 고르지 않음 | 추후 B. 지금은 refuse/observe로 흡수 |

로컬 G3는 stance×관측으로 한 축.  
클라우드 LLM은 stance+persona+팩트 안에서 자연어.  
stance 없이 모델만 열면 다시 범용 챗봇이 된다.

## 5. 세계 콘트롤 — A 잠금 · B 예약 (2026-08-20 확정)

대표님: 안정 개발 가능한 쪽을 고르고, 게임세계 콘트롤은 **추후 확장 기반만**.

| 안 | 지금 | 이유 |
|----|------|------|
| **A. 관측만** | **현재 개발 경로** | 입≠몸·검역·폴백과 충돌 없음. overlay/명령버스/일일배치를 채팅에 안 붙임 |
| **B. 제안 → 확인 → 몸** | **기반만 · LIVE=false** | id 화이트리스트·해석 함수만. 집행·확인 창 없음 |
| **C. 입 write** | **기각** | L1 위반 |

A를 고른 이유: B를 지금 열면 확인 오버레이·시설 내비게이션·스테이지 가드·PSS가 한 번에 붙는다.  
대화·인격·stance를 먼저 안정화하는 편이 맞다. B는 스위치 하나로 열 자리를 남긴다.

### 5-1. B 예약 계약 (실행하지 않음)

정본 모듈: `src/arcCore/chat/arcCoreChatWorldProposal.ts`

| 규칙 | 내용 |
|------|------|
| 스위치 | `ARC_CORE_CHAT_WORLD_PROPOSAL_LIVE = false` |
| 해석 | `resolveArcCoreChatWorldProposal` — LIVE 꺼져 있으면 **항상 null** |
| 팩 | 지금 스키마에 제안 필드 **넣지 않음** (클라우드 팩 동결) |
| 회신 | `completeArcCoreChatReply`에 해석·집행 **호출 안 함** |
| 몸 | 명령버스·일일배치·언락·크레딧 **연결 금지** |
| UI | 확인 오버레이·시설 `replace` **없음** |

예약 id (집행 핸들러 없음):

| 제안 id | 훗날 몸이 할 수 있는 것 | 지금도 금지 |

AABS·점유 변경·크레딧 지급·섀도우 리빌은 **예약 id에도 넣지 않음.**

### 5-2. 훗날 B를 켤 때 (아직 하지 말 것)

1. 대표님 명시 지시 + LIVE=true  
2. 팩에 `worldProposal: null \| { id }` **한 필드만** 추가 (스키마 1 유지, 없으면 null)  
3. `ArcOverlayHost` 확인 1장 → 기존 시설 화면. 모델이 버스를 누르지 않음  
4. 화이트리스트 밖·운용 write 암시 = stance `refuse` + 검역  
5. STAGE dispose 전·타이틀·틱에서 제안 해석 금지  

CSV `arc_core_chat_world_proposals.csv`는 **그때** Fable이 추가. 지금 테이블을 만들지 않는다.

## 6. 한 턴 목표 루프 (설계 · 코드 아님)

```text
유저 한 줄
  → PlayerIntent 힌트 (토픽 CSV)
  → ReadTools ≤4 (세계 스칼라)
  → ArcCorePurpose + Mode 1개 (dialogue drive)
  → ArcCoreStance 1개 (drive에서 파생)
  → Pack: 핵 페르소나 + purpose/mode/nextAsk + stance + 요약 + 질문 + 카드 + 도구
  → Provider: LLM 자연어 / 실패 시 로컬 한 축
  → 검역 (환각·직접 집행 암시·섀도우)
  → (A) 제안 해석 호출 없음
  → (B 훗날) LIVE일 때만 제안 1건 → 확인 오버레이 — 집행은 몸
  → topic / lastQuestion / rollingSummary
```

상용 에이전트의 멀티홉·검색·이미지·코드 실행은 이 루프에 **칸이 없다.**

## 8. 의도 반영 가능 여부 — 최종

**가능하다.** 파이프(채널·팩·검역·JWT·로컬 폴백)는 이미 그 자리이고,  
빈 칸이던 **인격 핵 · 목적 · 대화방식 4종 · stance · GM 비트** 는 A경로에 올라 있다. 남은 확장은 **(선택) 제안→몸** 뿐이다.

지금 구현을 키만 켜면 「자연어 안내원」이 된다.  
이번 지시의 끝은 「자연어 **근원체**」다.  
그 차이는 모델 성능이 아니라 **도메인 정의 + 페르소나 + 목적**이다.

세계 콘트롤 선택은 끝났다. **지금은 A.** B 스위치는 꺼 둔 채 자리만 있다.  
페르소나 핵·목적·대화방식 4종·stance는 A경로에 반영됨. B 집행은 그 다음 확장.
