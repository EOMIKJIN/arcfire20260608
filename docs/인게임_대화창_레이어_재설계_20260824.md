## 0. 한 줄 결론

**허브 크롬(탑바·퀘스트)은 보이게 두고, 대사 HUD만 반투명으로 올린다.**  
그 아래 그림은 구현 효율에 따라 둘 중 하나다.

| 안 | 이미지 | 구조 변화 | 쓸 때 |
|---|---|---|---|
| **A 분리** | L1 배경 + L2 누끼 캐릭터 + L3 HUD | Image 2 | 행성별 배경 재사용 · 캐릭터만 교체 |
| **B 합성** | **한 장**(배경+캐릭터 합본) + L3 HUD | 현행과 거의 동일 | 지금 더미·원본을 합본으로 통일할 때 |

B는 누끼 PNG가 없다. 카드에 합본만 `cover`하면 되므로 **큰 구조 변경 없이** 가능하다.  
공통으로 바꾸는 것은 **불투명 흰 카드/하단 가림 → 허브 비침 + HUD 반투명**이다.

탑바·퀘스트는 가리지 않는다. 캐릭터(또는 합본 상단)가 크롬 위로 걸치는 것은 **필수 아님** — 기본 0.

## 3. 목표 구조 (To-Be) — 크롬 공통, 이미지 안 분기

Host는 지금처럼 **딤 없음·passthrough**. 허브 UI가 뒤에 남는 것이 공통 핵심이다.

```text
[이미 있는 허브 — 건드리지 않음]
  PlanetStageBackground (성운·backdrop·궤도)
  포그라운드 탑바 · QuestHUD · 하단 도크

[대화 오버레이 · pointerEvents=box-none]
  그림:  A = L1 배경 + L2 누끼    또는    B = 합본 1장
  L3 대사 HUD   반투명 View + 텍스트 + 버튼     ← 공통
```

### 3-0. 안 B — 배경+캐릭터 합본 1장 (효율·현행 근접)

대표님 보완(2026-08-24): 배경과 캐릭터를 **분리하지 않고 한 장으로 적용**하는 안을 반드시 검토한다.

```text
현행 카드:  합본 Image cover + 불투명 HUD + 흰 bleed
안 B:       합본 Image cover + 반투명 HUD + 허브 크롬 비침
            (누끼 레이어 없음)
```

| 항목 | 내용 |
|---|---|
| 출력 | `portraitImageAssetKey` **한 PNG만**. 그 안에 장면+인물이 이미 있음 |
| 구조 | `NarrativeDialogRow`의 Image 1 + HUD. L1/L2 분해 **불필요** |
| 효율 | RN Image **1장** · decode 1회 · 행성 backdrop 추가 조회 없음 |
| 적합성 | **지금 더미가 이미 이 형식**. 원본도 합본으로 통일하면 교체만 하면 됨 |
| 한계 | 행성별 허브 배경과 장면이 **어긋날 수 있음**(함교 더미 vs 행성 성운). 캐릭터만 재사용·배경만 교체는 불가 |

구현 착수 전 **A vs B를 효율로 한 번 고른다.** 기본 추천은 아래 §3-5.

### 3-1. 안 A · L1 배경 — 「허브 배경영역 + 이미지만」

**의미**

- 슬롯 위치 = 허브가 배경을 그리는 **같은 시각 밴드** (탑 크롬 아래 ~ 하단 도크·예약 위).
- 내용 = `resolvePlanetBackdropSource(backdropImageAssetKey)` **한 장**.
- 넣지 않음: 궤도 함선, 행성 구체, 월드오브젝트, 메뉴, Skia dodge/성운 **Canvas**.

**키 없을 때 (다수 행성)**

- L1을 **그리지 않음** → 이미 떠 있는 허브 성운/실배경이 그대로 비친다.
- 대화 전용으로 성운 Canvas를 하나 더 올리는 것은 PSS/Skia 헌법 위반.

**왜 복제 Image인가**

- 「배경이미지만 따로」= 궤도·구체와 **분리된 레이어**를 대화 트리에 둔다.
- 같은 `require`라 디코드 캐시를 공유할 수 있음. **세션(대화 열림) 한정 1장**, 닫으면 언마운트.
- 부트 critical prefetch에 함장 초상·전 행성 배경을 **추가하지 않음** (기존 초상 계약과 동일).

### 3-2. 안 A · L2 캐릭터 (누끼가 있을 때만)

B안에서는 이 레이어를 **만들지 않는다.**

| 단계 | 에셋 | 그리는 방법 |
|---|---|---|
| **A · 원본 도착 후** | 외곽 제거 알파 PNG | `contain` · 키만 교체 |
| **A · 더미 기간** | 기존 합본을 L2에 올리면 L1과 **장면이 겹침** | 비효율 → 더미 기간은 **B가 맞음** |

- 가로는 화면 전폭을 넘기지 않음.
- 세로는 핀(540) 안에 발을 두고, 머리만 위로 살짝 나가게 할 수 있음 (`overlapUpPx`, 기본 **0**).
- 이름 각인(「STELLA ARIS」등)이 더미에 박혀 있으면 HUD 라벨과 **이중 표기**될 수 있음 — 알파 원본에서는 각인 없이 제작.

### 3-3. L3 대사·버튼

현행 HUD 수학 **유지** (기존값 변경 재확인 대상이 아님).

- 높이 176 · 최대 3줄 · 좌측 정렬 · `[ 다음 ]` / 수락·취소 듀얼
- **바꿀 것**: `backgroundColor` 불투명 → **반투명 흰/전술 틴트** (캐릭터 하체가 비침)
- 가독성: 반투명 + 가벼운 딤(HUD 영역만). 화면 전체 딤은 넣지 않음
- 버튼 Y는 계속 540 핀. 초상 확장으로 버튼을 내리지 않음

### 3-4. 「허브 UI 위 캐릭터 걸침」 (선택)

```text
탑바 · QuestHUD          ← 항상 보임 (헤더를 카드로 덮지 않음)
        ┌ 캐릭터 머리 ─ overlapUpPx (기본 0, 승인 시 16~32)
배경밴드 ┤ 캐릭터 상체
        └ HUD 반투명
하단 도크·예약            ← 초상/대사 침범 금지 (현행 reserved 계약)
```

2026-08-20 「빗살 헤더를 1px도 가리면 실패」는 **바 헤더** 계약이다.  
허브는 **탑바·퀘스트를 가리지 않는 것**을 기본으로 하고, 걸침은 별도 승인 스위치로만 켠다. B안이면 걸침은 합본 상단 crop/정렬로만 한다.

### 3-5. A vs B 효율 — 구현 시 선택 기준

| 축 | A 분리 | B 합성 1장 |
|---|---|---|
| RN Image | 최대 2 (backdrop + 캐릭터) | **1** |
| 조회 | 행성 `backdropImageAssetKey` + 함장 초상 | 함장 초상만 (현행 resolve) |
| PSS | 디코드 2 · 세션 언마운트 | 디코드 1 · 현행과 동일 |
| 코드량 | L1/L2 슬롯·정렬·키 없음 폴백 | HUD 반투명 + 흰 bleed 제거 수준 |
| 에셋 | 누끼 N + 행성별 배경 | **합본 N장만** (지금 더미와 동일) |
| 허브 실배경과 일치 | L1을 허브 키로 맞출 수 있음 | 합본 장면이 허브와 다를 수 있음 |
| 캐릭터 재사용 | 한 누끼를 여러 행성 배경에 | 행성마다 합본이 필요하거나 장면 고정 |

**구현 기본값 (효율 1안):** 원본이 합본(또는 지금 더미)인 동안은 **B**.  
누끼 원본이 **전원 통일**되어 들어오고, 행성별 배경 재사용이 필요할 때만 A로 연다.  
런타임에 A/B를 페이지마다 섞지 않는다 — **빌드·에셋 정본은 한 모드**.

## 6. 원본 에셋 — **한 방식으로 통일**

대표님: 어떤 안이든 **원본 규격은 하나로** 가는 것이 관리 효율이다.  
폴더에 누끼와 합본을 섞어 두지 않는다. CSV 플래그로 장마다 바꾸지 않는다.

| 통일안 | 원본 1장 | 런타임 | 비고 |
|---|---|---|---|
| **합본 통일 (B, 현 더미와 동일)** | 장면+인물 PNG (알파 불필요, 불투명 배경 OK) | Image 1 | **지금 제작 파이프와 일치. 1차 권장** |
| **누끼 통일 (A)** | 인물만 PNG-24+알파 | L1=행성 backdrop + L2=누끼 | 행성별 배경 재사용이 필요할 때. 전 함장 재작업 |

공통 제작 규칙(모드와 무관):

| 항목 | 규칙 |
|---|---|
| 구도 | 허리~머리, 정면~3/4 |
| 각인 | 이름/로고 **넣지 않음** (HUD 라벨이 정본) |
| 해상도 | 짧은 변 ≤ 1080. 4K 금지 |
| 키 | `assets/images/npc/<id>.png` → 맵 + `portraitImageAssetKey` (현행 3단계) |

합본 통일이면 행성 `backdropImageAssetKey`는 **대화 L1이 아니라 허브 배경 전용**으로 남긴다.  
누끼 통일로 전환할 때는 전 키를 한 번에 교체하고 문서를 A로 잠근다.

## 7. 구현 준비 (승인 후 착수 순서)

코드는 쓰지 않는다. 승인되면 아래만 한다.

### Phase A — 허브 크롬 (B 우선, 구조 최소)

1. **모드 확정**: 원본 통일 = 합본이면 **B만** 구현. A 슬롯은 만들지 않음
2. HUD 배경만 alpha. 핀·3줄·분할·자동닫힘·`imageSource` 1장 **그대로**
3. 허브 `stageFill`에서 불투명 흰 `topWhiteMargin` / `bottomBleed` 제거 (허브 비침). `reservedBottom`은 초상 비침범만
4. intro(`stageFill=null`)·바은 현행
5. 규칙 mdc · 초상 계약을 **합본 통일**로 개정

### Phase A′ — A 분리는 원본이 누끼로 통일된 뒤에만

- L1 backdrop + L2 alpha. 더미 합본을 L2에 올리는 임시 분리는 **하지 않음**(겹침·Image 2 낭비)

### Phase B — 겹침·가독성 미세 (실기 후)

- `overlapUpPx` 0 → 대표님 실기 보고 후만
- HUD alpha % (제안 시작점 0.78~0.86, **기존값 아님 · 신규**)

### Phase C — 바/intro

- 별도 승인. 바은 2026-08-20 흰색 계약과 충돌하므로 자동 적용 금지

### 손댈 파일 (예정)

- B: `NarrativeDialogRow.tsx` · `narrativeDialogLayout.ts` (+ test) · HUD alpha · 허브 흰 bleed 제거
