# 행성 체류전함 — 경제 가중 분포 · 도시·문화 소비 축 설계

> **상태**: 설계 정본 + **능동 판단 런타임 반영** (2026-09-11)  
> **요청**: 체류 비중이 성계 경제활동에 따라 분포하고, 체류 중에는 5대 지표의 **소비·인구·정보·환경(도시·문화)** 을 담당한다. 수송선단은 수요·공급 축을 유지한다.  
> **전제**: Table-First · 일 1회 배치 · 틱에서 코어 persist 금지 · 허브 Skia 렌더 캡 유지 · 체류 척수는 확정이 아니라 시스템이 필요하면 확대 가능  
> **대표님 추가 의도**: 일원화된 반복 체류(3h `hash%N`)가 아니라, 성계 경제·운용·자체 판단이 겹친 **능동 활동**.

---

## 0. 의도 (대표님)

1. 지금 돌아가는 **행성 체류전함**이 발전도·경제 수치에 따라 성계/행성마다 **다른 비중**으로 머무는지 확인한다.
2. 그렇지 않다면 **성계 경제활동 가중치**로 체류 비중을 분포하도록 고도화한다.
3. **이제 막 개척된 성계**는 체류 숫자가 적고, **개척 관련 전함 소수**만 있는 흐름이 맞다.
4. 체류는 빈 연출이 아니다. 행성 5대 스탯 중 **순수 행성 경제의 소비 축**을 담당할 수 있다.
5. **수송선단** = 핵심 수요·공급. **체류전함** = 소비 · 인구 · 정보 · 환경(체류가 많을수록 환경↓) 등 **도시·문화 영향**.
6. 체류 척수는 지금 숫자를 잠그지 않는다. 시스템이 필요하면 확대한다.
7. 단순 반복 체류가 아니라 경제·운용·판단이 결합된 활동으로 구현한다.

## 1. 현행 검수 — 이미 되나 / 안 되나

결론부터: **체류전함은 작동한다. 다만 경제·발전도 가중 분포는 없다.** 체류의 경제 효과는 **아크 수송선의 위상 누적만** 있고, 테이블 체류전함은 지표를 건드리지 않는다.

### 1-1. 두 축이 이미 갈라져 있다 (유지)

| 축 | 정본 | 지금 하는 일 |
|---|---|---|
| **아크 수송** | `AiNpcSubCore` · `arcOrbitPresenceFill` · `balanceArcTrafficPlanetPick` | 전 행성 **최소 부하 균등** 배치. 체류 60~600초. `planetDevelopmentAccStore`에 5지표 **가산** |
| **테이블 체류/순찰** | `resolveCaptainTableOrbitPlanetId` · `orbit_table_patrol` | CSV 홈/활동 행성 ∩ 팩션 후보에서 **3시간 버킷 균등 해시**. 전투 함장·수송 fill 제외 |
| **허브 표시** | `applyPlanetHubOrbitRenderBudget` | 테이블 최소 3 + 수송 잔여, **화면 최대 8척** |

수송선단의 수요·공급(컨보이 정산·fabric·무역 수수료)은 일일 배치에 이미 있다. 이 축을 체류전함에 합치지 않는다.

### 1-2. 분포 — 경제 가중 없음

- 테이블 체류: `hash % candidates.length`. 후보가 많으면 홈이 희석될 뿐, **P/R/무역량/개척 페이즈를 보지 않는다.**
- 아크 수송: 행성별 척수를 같게 맞춘다. **번화한 항구와 개척 전초가 같은 목표 밀도**다.
- 스타터 허브(`arcadia_prime`)만 부트 시 1척 soft-pin.

따라서 “발전이 높은 성계에 체류가 몰리고, 갓 개척한 성계에는 소수”는 **현재 성립하지 않는다.**

### 1-3. 체류 중 5지표 — 수송만, 그리고 환경은 +

`planetDevelopmentAccStore` `PHASE_WEIGHT.dwelling`:

| 지표 | 수송 체류 가중 | 대표님 체류전함 의도 |
|---|---|---|
| R 자원 | +0.21 | **소비(−)** — 행성 내수 |
| P 인구 | +0.35 | **인구·도시 압력(+)** — 방향은 유사, 의미는 방문/상주 |
| D 방위 | +0.07 | 체류 본축 아님 |
| T 기술 | +0.11 | **정보·문화 교류(+)** 로 재해석 가능 |
| E 환경 | **+0.26** | **체류↑ → 환경↓** — **현행과 반대** |

일일 `runPlanetEnvironmentDiversityPass`가 이 누적을 정수로 소비한다. 다만

- 적용 범위가 **플레이어 현재 성계 주변 최대 20행성**이다 (전 은하 체류 효과 아님).
- `environmentDiversity=false`인 플레이어 소유/본거지 행성은 **이 패스 전체를 스킵**한다.
- **테이블 체류전함은 누적에 참여하지 않는다.**

### 1-4. 개척 성계

프론티어(synth)는 개방·phase≥1 후 궤도 시드가 붙는다. 테이블 체류 배정은 로컬 CSV 후보가 없으면 개방 행성 풀로 폴백할 수 있어, **갓 열린 성계에 민간 체류가 과하게 들어갈 여지가 있다.**  
함장 `aiRole`은 `patrol` / `garrison` / `hunter` / `escort` / `fleet_leader` 등 **전투·호위 중심**이다. 개척·민간·문화 역할 컬럼은 없다.

### 1-5. 척수

- 허브 **표시** 상한 8은 메모리·INFO 계약이다. 세계 논리 척수와 같다 보지 않는다.
- 아크 fill 수송은 소수(테이블 정본 + 성계 시드).
- 테이블 `general`/`neutral` 함장은 훨씬 많다. 전원 한 행성에 그리면 STAGE 1 예산을 깬다.

## 2. 가능 여부

**가능하다.** 조건은 아래를 어기지 않는 것이다.

| 계약 | 설계 대응 |
|---|---|
| 경제/AABS는 일 1회 배치 | 체류 **효과**는 관측 누적 → 정오 배치만 코어에 반영 |
| 틱 persist·전 행성 동기 루프 금지 | 가중 테이블은 epoch/배치 1회 빌드. 누적은 기존처럼 모듈 버퍼 in-place |
| 허브 Skia 5~8 · Zero-Allocation | **논리 척수**와 **표시 척수** 분리. 표시는 지금 캡 유지 |
| Table-First | 역할·가중·지표 델타는 CSV. 코드에 행성 id 하드코딩 금지 |
| 5지표 권한 CSV | 신규 패스는 `planet_core_stat_authority`에 **별도 플래그**로 넣는다. 다양성 패스를 무단 재사용하지 않음 |
| 수송 수요·공급 유지 | 컨보이·fabric·수수료 패스 **불변**. 체류는 소비/도시 축만 |
| 기존값 재확인 | 수송 `PHASE_WEIGHT`(환경 +)는 **뒤집지 않는다.** 체류 시민 축은 신규 가중 |

플레이어 소유 행성에 시민 체류 효과를 줄지는 **구현 전 한 줄 승인**이 필요하다. 지금은 월드 기본 행성에만 켜는 것을 1안으로 한다.

## 4. 분포 — 경제 가중

### 4-1. 행성 활력 점수 `dwellGravity` (배치 또는 3h epoch 1회)

입력은 **이미 있는 값만** 쓴다. 틱 재집계 금지.

| 입력 | 출처 | 방향 |
|---|---|---|
| 런타임 P · R | `planetCoreRuntimeStore` | 도시·내수 클수록 체류↑ |
| 구역 `targetCreditsEarned` | 존 밸런스 테이블 | 경제 규모 |
| 무역소·조선소·바 | `planets.csv` / colonization CSV | 시설 있으면 가산 |
| 수수료 원장(있으면) | `planetTradeFeeLedger` | 실거래 활력 |
| 성계 zone | safe / neutral / pvp / endgame | 안전 허브 > 전초 |
| **개척 페이즈** | synth colonization phase | 0~1은 중력 바닥 |

정규화 후 행성마다 `gravity ∈ [floor, 1]`.  
**갓 개척**: `phase < 1` → gravity ≈ 0.04~0.08, **논리 체류 상한 0~1**. `phase = 1` → 상한 1~2, 역할은 개척/측량만.

코어 21은 항상 개방이므로 “개척 직후”는 **주로 synth**다. 코어라도 P+R이 낮고 무역소가 없으면 gravity를 낮춘다 (베가·유적·어비스·스론 등 미진열과 맞춤).

### 4-2. 배정 — 능동 판단 (구현 정본)

`hash % N` 과 단일 가중 추첨만으로 끝내지 않는다. `judgeTableDwellPlanet` 이 아래를 **한 번에** 본다.

1. 함장 후보(CSV 홈/활동/팩션) ∩ **개방 행성만**. 잠금·phase0 은 논리 척수 0.
2. 역할 적합성: colonizer↔프론티어, survey↔저T/접전, consumer↔무역·인구, cultural↔바, information↔기술.
3. 운용 배율: 반란·WDI·저환경·접전·pvp 는 민간을 밀어낸다. 측량은 오히려 끌린다.
4. 혼잡: 인덱스 빌드가 함장 id 순으로 순차 배정. `occupancy ≥ logicalCap` 이면 다음 후보(군중 피드백).
5. 이력: 직전 epoch 판단이 아직 고려 집합(`best * hysteresis`)이면 **stay**. 아니면 relocate. 합법 후보가 없으면 depart.
6. 고려 집합 안에서만 결정론 가중 선택(함장+KST day+epoch+역할). 매일·3h 마다 경제 신호가 바뀌면 목적지가 바뀐다.
7. `capMax` 초안 12, phase1 상한 2 — 허브 표시 8과 분리.

정본: `src/arcCore/dwell/planetDwellJudgment.ts` · 배정 `assignCaptainTableDwellPlanetId`.

### 4-3. 개척 성계 구성

| 개척 단계 | 논리 척수 | 허용 역할 |
|---|---|---|
| 미개방 / phase 0 | 0 | 없음 |
| 막 개방 (phase 1) | 1~2 | `colonizer` · `survey` |
| 정착 (phase≥2, gravity 중) | 2~5 | 위 + `garrison` 소수 |
| 번화 코어 | gravity 비례, 상한 `capMax` | `civilian_consumer` · `cultural` · `information` 위주 |

역할은 **신규 CSV**로 둔다. 기존 `aiRole`(hunter 등)을 시민 역할로 재해석하지 않는다. 배정 컬럼이 비면 `civilian_consumer`(코어) / `survey`(프론티어) 폴백만.

## 5. 체류 효과 — 소비·인구·정보·환경

### 5-1. 관측 (벽시계, persist 없음)

행성별로 **역할-시간**만 모듈 버퍼에 더한다. 함선 객체 배열을 직렬화하지 않는다.

```text
dwellCivicAcc[planetId][role] += wallDeltaSec * (그 행성 논리 체류 수 중 해당 역할 비율)
```

허브에 안 그려져도 논리에 있으면 누적한다. (표시 8 ≠ 세계 12)

테이블 배정이 3h로 고정이므로, 틱마다 함장 전수 스캔은 하지 않는다. **epoch 변경·배치 시 행성별 역할 카운트 스냅샷**을 들고, 틱은 그 카운트×dt만 더한다 (수송 acc와 같은 PSS 패턴).

### 5-2. 일일 반영 `runPlanetDwellCivicDailyPass`

정오 배치에 **새 스텝**으로 넣는다. 다양성 패스·컨보이 정산과 분리.

역할별 일일 기여(초안, **구현 전 CSV 수치 재확인**):

| 역할 | R 소비 | P | D | T 정보 | E 환경 |
|---|---|---|---|---|---|
| colonizer | 0 ~ 약− | 소+ | 소+ | 소+ | 소− (공사) |
| survey | 0 | 0 | 0 | + | 0 |
| civilian_consumer | **− (내수)** | **+** | 0 | 소+ | **− (혼잡)** |
| cultural | 0 | 소+ | 0 | + | 소− |
| information | 0 | 소+ | 0 | **+** | 소− |

부호 규칙:

- **R**: 체류는 화물을 생산하지 않고 **먹는다**. 공급은 수송선단.
- **P**: 체류·방문은 인구·도시 활력으로 본다 (+). 과밀은 E로만 벌한다.
- **T**: 정보·문화 교류 (+). 무기 연구 폭주 아님. 일일 캡 작게.
- **E**: 체류 밀도↑ → 환경↓. 수송 체류의 기존 E+ 와 **더하지 않고 축을 분리**한다.
- **D**: 기본 0. 개척 `colonizer`만 소폭 +. 주둔 전투 함장은 이 패스 밖.

캡: 지표당 일일 |Δ| ≤ 기존 equilibrium/`maxDailyStatGain` 계열과 맞춘다 (초안 ±2). AABS 5%·0.7~1.3을 우회하지 않는다.

적용 범위: **개방 코어 + 개방 synth 전 행성** (주변 20 제한을 쓰지 않음). 전 행성 루프는 **배치 전용**, 청크·yield. 부트 `onBoot` 금지.

### 5-3. 권한

기존 `planet_core_stat_authority.csv` **셀은 변경하지 않는다.**  
시민 패스 게이트는 `resolvePlanetCoreStatAuthorityContext === world_default` (1안: 플레이어 소유/홈 OFF).

| context | 적용 |
|---|---|
| world_default | ON |
| player_owned / player_home | **OFF** |

ON으로 바꿀 때는 기존값 재확인.

## 6. 표시 vs 논리 (척수 확대)

```text
논리 체류 N (경제 가중, 상한 capMax)  ── 시민 누적·일일 패스
                │
                ▼
허브 렌더 min(N, 8)  ── 테이블 예약 3 유지
  우선 노출: 개척 성계는 colonizer/survey
             번화 성계는 consumer/cultural 혼합
```

N을 키워도 Skia Path `.map()`·함선당 Canvas를 늘리지 않는다. INFO는 표시 중인 함만.

확대가 필요할 때: CSV에 시민 함장·역할 행을 **추가**한다. 런타임으로 유령 함장을 만들지 않는다 (`aiVirtualPlayerStore` 금지와 동일).

## 8. 배치 삽입점

`runArcCoreDailyOpsBatch` 제안 순서:

1. 기존 에너지·환경·fabric·시장 (공급 정렬)
2. **컨보이 정산** (수요·공급) — 위치 유지
3. **`runPlanetDwellCivicDailyPass`** (소비·도시) — 컨보이 직후
4. 업킵·재정 감쇠

관측 버퍼는 배치가 소비한다. 타이틀 버튼·`onBoot`에 합류 금지.
